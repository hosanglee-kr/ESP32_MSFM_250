## 2. 모듈별 세부 설계 및 개선 구현 사양

### 2.1 [1] GDMA 및 CPU L1 캐시 일관성 (Cache Coherency) 제어
* **목표:** ESP32-S3의 L1 캐시와 외부 PSRAM DMA 버퍼 간의 불일치를 방지하여 데이터 오염을 예방합니다.
* **구현 설계:**
  * `esp_cache.h` 헤더를 포함합니다.
  * 센서 엔진 및 I2S DMA 버퍼 조작 영역에 아래 매크로 함수 기반 동기화 루틴을 선언합니다.
```cpp
#include "esp_cache.h"

inline void sync_cache_before_dma_read(void* addr, size_t size) {
    // DMA 전송 시작 전 메모리 영역 캐시 무효화 (기존 더티 데이터 제거)
    esp_cache_msync(addr, size, ESP_CACHE_MSYNC_FLAG_INVALIDATE);
}

inline void sync_cache_after_dma_write(void* addr, size_t size) {
    // DMA 전송 완료 후 L1 캐시 무효화하여 물리 RAM에서 강제 로드
    esp_cache_msync(addr, size, ESP_CACHE_MSYNC_FLAG_INVALIDATE);
}
```

### 2.6 [12] 복소수 FFT 버퍼 메모리 무결성 확보 (2 * N 크기 강제)
* **목표:** 복소수 FFT 연산 수행 시 발생하는 인덱스 오버플로우 메모리 붕괴(Memory Corruption) 차단.
* **구현 설계:**
  * 실수 데이터를 복소수 구조에 복사할 때 짝수=실수, 홀수=0.0f로 교차 배치합니다.
```cpp
// T240_DspEng_250.hpp
// static float _sramFftPing[2048] alignas(16); // 1024 FFT를 위한 복소수 배열 (Real, Imag 교차 배치)

void prepare_complex_fft_buffer(const float* raw_real_data, float* complex_buffer, size_t n) {
    for (size_t i = 0; i < n; i++) {
        complex_buffer[2 * i]     = raw_real_data[i]; // Real Part
        complex_buffer[2 * i + 1] = 0.0f;             // Imaginary Part
    }
}
```

### 2.8 [16] 스토리지 I/O 뮤텍스 디커플링 (Lock Decoupling)
* **목표:** SD 카드 쓰기 시 발생하는 수백 ms 대기 시간 동안 실시간 데이터 수집이 지연되는 파이프라인 붕괴를 해결합니다.
* **구현 설계:**
  * 물리 파일 쓰기 및 `flush()` 수행 시에는 `_lock`을 획득하지 않고 별도의 독립된 태스크에서 수행합니다.
```cpp
// T260_Storage_250.cpp
// _lock 뮤텍스는 오직 링 버퍼의 포인터 갱신에만 취득
bool CL_T2_StorageManager::pushAudioFrame(const T2_Type::ST_FeatureSlot_Aud_t* p_audFeat, const T2_Type::ST_Raw_Audio_t* p_rawAud) {
    xSemaphoreTakeRecursive(_lock, portMAX_DELAY);
    // 링버퍼 포인터 갱신 및 큐 데이터 push (수 마이크로초 소요)
    uint16_t v_writtenIdx = _asyncAudHead;
    _asyncAudRing[v_writtenIdx] = *p_audFeat;
    _asyncAudHead = ( _asyncAudHead + 1 ) % ASYNC_RING_CAPACITY;
    xSemaphoreGiveRecursive(_lock);

    // 파일 I/O 태스크 노티 (실제 기록된 인덱스 전송)
    xQueueSend(_qAudStorage, &v_writtenIdx, 0);
    return true;
}
```

### 2.9 [22] 소프트웨어 Drop & Shift 기반 시간축 정렬 (Software PLL)
* **목표:** 오디오 APLL과 가속도 SPI 폴링 간 클럭 편차 누적 시 발생하는 데드락 예방.
* **구현 설계:**
  - 오디오 타임스탬프를 마스터 기준으로 두고 가속도 시간축이 임계 오차(`_max_allowed_skew_us`)를 벗어나 지연될 경우, 가속도 버퍼를 리셋하거나 Drop & Shift하여 강제 매칭을 수행합니다.
  - esp_timer 단조 시계로 백업 스위칭 시 위상 급변을 차단하는 안정화 필터(Muting)를 추가합니다.
```cpp
// T248_SeqBuild_250.cpp
void MultiRateTimeAligner::notifyClockSourceSwitch() {
    _prev_vib.timestamp_us = 0;
    _curr_vib.timestamp_us = 0;
    _mutingRemainingTicks = 25; // 약 500ms(20ms 슬롯 기준) 동안 드롭 제어 일시 동결
}

bool MultiRateTimeAligner::getAlignedVibration(uint64_t audio_ts, float* out_feats) {
    if (!_curr_vib.is_valid) return false;

    // 단조 시계 백업 스위칭 발생 시 과도기 위상 Muting 제어 (급격한 드롭 방어)
    if (_mutingRemainingTicks > 0) {
        _mutingRemainingTicks--;
        _prev_vib = _curr_vib;
        _prev_vib.timestamp_us = audio_ts - 20000;
        _curr_vib.timestamp_us = audio_ts;
    }

    int64_t skew = static_cast<int64_t>(audio_ts) - static_cast<int64_t>(_curr_vib.timestamp_us);

    // 임계값 초과 시 강제 Drop & Shift (회복 모듈, 단 Muting 구간 외에서만 트리거)
    if (_mutingRemainingTicks == 0 && std::abs(skew) > static_cast<int64_t>(_max_allowed_skew_us)) {
        ESP_LOGW("T248_TIME", "Clock drift skew detected: %lld us. Soft drop and align.", skew);
        _prev_vib = _curr_vib;
        _prev_vib.timestamp_us = audio_ts - 20000; // 가상 오차 보정 시간 임의 주입
        _curr_vib.timestamp_us = audio_ts;
        skew = 0;
    }

    constexpr size_t VIB_FEAT_CNT = T2_Def::Vib::FEAT_CNT;

    // 보간 연산 및 uint64_t 언더플로우 방어 가드
    if (_curr_vib.timestamp_us <= _prev_vib.timestamp_us || audio_ts <= _prev_vib.timestamp_us) {
        // 시간축 역전 또는 비정상 흐름 시 보간을 생략하고 최신 특징량 복제 전달
        std::copy(_curr_vib.features, _curr_vib.features + VIB_FEAT_CNT, out_feats);
        return true;
    }

    uint64_t total_delta = _curr_vib.timestamp_us - _prev_vib.timestamp_us;
    float alpha = static_cast<float>(audio_ts - _prev_vib.timestamp_us) / static_cast<float>(total_delta);

    // 외삽(Extrapolation) 방지를 위한 계수 클램핑
    if (alpha < 0.0f) alpha = 0.0f;
    if (alpha > 1.0f) alpha = 1.0f;

    for (size_t i = 0; i < VIB_FEAT_CNT; i++) {
        out_feats[i] = _prev_vib.features[i] + alpha * (_curr_vib.features[i] - _prev_vib.features[i]);
    }
    return true;
}
```

### 2.10 [28] OTA 진입 시 하드웨어 인터럽트 및 DMA 일시 차단
* **목표:** OTA 플래시 메모리 캐시 비활성화 상태 시 발생하는 캐시 미스 예외 및 크래시 방지.
* **구현 설계:**
  - 강제 `vTaskSuspend`를 배제하고, FSM 상태 기계의 `SYS_STATE_OTA` 전이 상태를 감지하여 개별 태스크 루프 내부에서 락을 완전히 반환한 안전 지점(Safe Point)에서 자발적으로 대기하도록 **Graceful Pause** 방식을 채택합니다.
```cpp
// T290_FsmMgr_250.cpp
void CL_T2_FsmManager::prepareForOta() {
    ESP_LOGW(TAG, "Initiating Graceful Pause for OTA flash write...");
    // 1. 상태 전이를 통해 태스크들이 루프 내 Safe Point에서 자발적으로 락을 반환하고 대기 유도
    setSystemState(SYS_STATE_OTA);
    
    // 2. 센서 인터럽트 차단 및 I2S DMA 일시 중단
    detachInterrupt(digitalPinToInterrupt(T2_Def::Imu::Hardware::PIN_INT1_WATERMARK_CONST));
    _sensor.stopI2SDma();
    
    // 3. SPI 버스 뮤텍스 소유자가 릴리즈할 때까지 최대 100ms 동적 대기 (데드락 방어)
    int waitLimit = 10;
    while (xSemaphoreGetMutexHolder(_spiBusMutex) != nullptr && --waitLimit > 0) {
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
```

### 2.12 [9] FSM 매니저 내부의 제로 카피(Zero-Copy) 원칙 준수 (memcpy 회피)
* **목표:** `memcpy`를 남발하여 대용량 가속도/오디오 버퍼 복사 시 CPU 오버헤드가 발생하는 것을 방지하고, 락 프리 링버퍼(`CL_T2_RingBuffer`)의 포인터 교환을 통해 Zero-Copy를 구현합니다.
* **구현 설계:**
  * DSP 결과 버퍼에서 가속도/오디오 특징 추출기로 전달 시, 원시 데이터 복사를 피하고 링버퍼 구조체의 쓰기(Write)/읽기(Read) 인덱스 주소를 직접 참조하도록 합니다.
```cpp
// T290_FsmMgr_250.cpp (VibProcTask 내 Zero-Copy 예시)
// 기존: memcpy(v_tmpAcc, _dsp.getAccBuf(), size); (X)
// 개선: RingBuffer에 pointer/index를 직접 획득하여 전달하거나 swap
const float* v_dspAccBuf = _dsp.getSharedAccBufferPointer();
if (v_dspAccBuf != nullptr) {
    // 링버퍼에 포인터를 직접 enqueue하여 소비 태스크가 직접 접근하도록 함
    _sharedCtx->accelRingBuffer.enqueuePointer(v_dspAccBuf);
}
```
* **타모듈 영향도:** `CL_T2_DspEngine`, `SharedContext`, `VibProcTask` 간의 데이터 참조 라이프타임 관리가 필요하며, 메모리가 덮어쓰기 전에 소비자가 사용 완료(Release)해야 함.

### 2.14 [15] 락 프리 링버퍼 오버라이트 시 메모리 오더링(Memory Ordering) 보장
* **목표:** 듀얼 코어 동시 접근 환경에서 `_tail` 포인터 갱신 전에 버퍼 쓰기가 완벽하게 끝나도록 하드웨어 펜스를 보정합니다.
* **구현 설계:**
```cpp
// T216_RingBuf_250.hpp
template <typename T>
bool CL_T2_RingBuffer<T>::enqueue(const T& item) {
    uint16_t head = _head.load(std::memory_order_relaxed);
    uint16_t next_head = (head + 1) % _capacity;
    uint16_t tail = _tail.load(std::memory_order_acquire); // acquire를 통해 tail 변화 동기화

    if (next_head == tail) {
        // [중요] tail 전진 전 메모리 배리어를 쳐 데이터 복사 완료 보장
        _buffer[head] = item;
        std::atomic_thread_fence(std::memory_order_release);
        _tail.store((tail + 1) % _capacity, std::memory_order_relaxed);
    } else {
        _buffer[head] = item;
        std::atomic_thread_fence(std::memory_order_release);
    }
    _head.store(next_head, std::memory_order_release); // release를 통한 가시성 전파
    return true;
}
```

### 2.33 [보완] 구현 설계상 모순/누락 대응 및 안정성 보완 설계

1. **동적 핫스왑 노치 필터와 SMEA_FLASH_RODATA 격리 설계 (2.13 & 2.27 모순 해결)**
   * `SMEA_FLASH_RODATA` 매크로는 오직 컴파일 타임에 고정되어 변하지 않는 `s_iir_hpf_coeffs` 및 `s_iir_lpf_coeffs`에만 한정 적용합니다.
   * 실시간으로 중심 주파수가 변경되는 노치 필터 계수 `_notch_coeffs`는 RAM(`CL_T2_DspEngine` 객체 멤버 변수 영역)에 상주하도록 유지하여 런타임 쓰기 시 Exception이 발생하지 않도록 격리 설계합니다.

2. **OTA 중단/실패 시 안전 재기동 (Resume) 파이프라인 누락 대응 (2.10 누락 해결)**
   * OTA 전송 오류나 타임아웃 발생 시, 중단된 센서 스트림과 CPU 태스크를 Graceful하게 복구하는 `resumeFromOtaFailure()` 인터페이스를 FSM에 신설합니다.
```cpp
void CL_T2_FsmManager::resumeFromOtaFailure() {
    ESP_LOGW(TAG, "OTA failed. Resuming sensor processing pipeline...");
    // 1. 센서 인터럽트 복구 및 재연결
    attachInterrupt(digitalPinToInterrupt(T2_Def::Imu::Hardware::PIN_INT1_WATERMARK_CONST), T200_handleTriggerISR, RISING);
    // 2. I2S DMA 재가동
    _sensor.startI2SDma();
    // 3. RTOS 가공 태스크 Resume
    if (_hAudioTask) vTaskResume(_hAudioTask);
    if (_hVibTask) vTaskResume(_hVibTask);
}
```

3. **closeSession 비동기 지연으로 인한 FSM 블로킹 회피 설계 (2.24 & 2.31 연계 보완)**
   * `closeSession()` 내부의 링버퍼 대기 루틴은 FSM의 메인 제어 태스크를 잡고 있지 않도록, 비동기 스토리지 전용 태스크(`StorageTask`) 내에서 플러시를 완전히 끝낸 뒤 FSM에 완료 시그널을 비동기로 던져주는 세마포어/이벤트 그룹 방식으로 전환합니다. FSM은 상태 전환 중에도 다른 제어 커맨드 수신 능력을 잃지 않아야 합니다.

4. **dumpPreTriggerToSession의 스냅샷 바운스 버퍼 도입 (2.21 & 2.8 모순 해결)**
   * SD 카드 파일 I/O 블로킹 시간 동안 `pushAudioFrame`과의 Lock 경합을 차단하기 위해 프리트리거 데이터를 덤프할 때 **스냅샷 바운스 버퍼** 기법을 적용합니다.
   * `_lock`을 획득하고 링 버퍼에 있는 데이터를 임시 로컬 메모리 버퍼로 빠르게 일괄 복사한 후 `_lock`을 즉시 해제(Release)합니다. 이로써 실시간 스트림 수집 지연을 수 마이크로초 수준으로 최소화하고, 해제 상태에서 임시 버퍼 데이터를 파일에 기록하도록 개선합니다.

5. **딥슬립 Wake-up 이후 BMI270 인터럽트 레지스터 원상복구 누락 대응 (2.30 누락 해결)**
   * 딥슬립에서 깨어난 장비가 다시 정상 `MONITORING` 상태로 진입할 때 Any-Motion 인터럽트 매핑을 해제하고 FIFO 워터마크 인터럽트(`INT1`) 구조로 복구하는 `restoreFromDeepSleepWakeup()` 인터페이스를 `CL_T2_SensorEngine`에 신설합니다.
```cpp
void CL_T2_SensorEngine::restoreFromDeepSleepWakeup() {
    ESP_LOGI(TAG, "Restoring BMI270 registers from sleep wakeup mode...");
    // 1. Any-motion 기능 비활성화 및 설정 초기화
    _writeRegSingle(0x5F, 0x00);
    _writeRegSingle(0x60, 0x00);
    // 2. 인터럽트 매핑을 원래의 FIFO Watermark (INT1 RISING) 구조로 원복
    _writeRegSingle(0x53, 0x08); // Map FIFO watermark to INT1
    _writeRegSingle(0x54, 0x00); // Unmap from INT2
}
```

7. **g_CrashDiag 듀얼코어 레이스 컨디션 방지 및 콜드 스타트 쓰레기값 방지 설계 (2.26 모순 해결)**
   * RTC 영역 데이터 `g_CrashDiag`에 값을 쓸 때와 읽을 때의 원자성(Atomicity)을 보장하기 위해, 쓰기/읽기 구문 전후에 CPU 메모리 배리어(`asm volatile("memw")` 및 `std::atomic_thread_fence(std::memory_order_seq_cst)`)를 결합하거나 크래시 이벤트를 제외하고는 복사 데이터 팩킹을 통해 다중 접근을 배제하도록 설계를 강화합니다.
   * `RTC_DATA_ATTR` 메모리 영역은 전원 차단 후 최초 기동 시(Cold Boot) 임의의 쓰레기 값을 가질 수 있으므로, 초기화 단계에서 `esp_reset_reason()`을 체크하여 `ESP_RST_POWERON` 등 콜드 부트일 경우에는 `g_CrashDiag`를 `0`으로 강제 초기화하며, `ESP_RST_PANIC`, `ESP_RST_WDT` 등 소프트웨어 예외 리셋으로 재기동된 경우에만 보존된 이전 사이클의 데이터를 MQTT로 정상 송출하도록 설계합니다.

8. **processNetworkRestart 시 MQTT 핸들 완전 해제 후 재배치 설계 (2.20 누락 해결)**
   * 설정 변경에 따른 네트워크 재기동 시 커넥션 정보 누수를 방지하기 위해, 기존 MQTT 클라이언트를 완전히 소멸시키고 재기동하는 파이프라인을 추가합니다.
   * 이때 `_mqttConnected = false;`를 명시적으로 리셋해 주어, 네트워크 감시 루프(`runNetwork()`)가 새로 할당된 MQTT 클라이언트 인스턴스에 대해 `esp_mqtt_client_start()`를 정상적으로 재호출하도록 통신 컨텍스트 데드락을 원천 예방합니다.
```cpp
void CL_T2_CommuManager::recreateMqttClient(const esp_mqtt_client_config_t& new_cfg) {
    if (_mqttClient) {
        esp_mqtt_client_stop(_mqttClient);
        esp_mqtt_client_destroy(_mqttClient); // 기존 인스턴스 파괴
        _mqttClient = nullptr;
    }
    _mqttConnected = false; // 신규 클라이언트 시작 유도를 위해 연결 플래그 리셋
    _mqttClient = esp_mqtt_client_init(&new_cfg); // 변경된 설정으로 재할당
}
```

14. **설비 고장 진단 도메인별 물리적 측정 대상 매칭 및 덤프 무결성 설계 (이슈 21 & 이슈 5 연계 보완)**
    * 가속도(직선 기계식 진동 충격 측정)와 자이로(회전축 비틀림 및 모멘트 각도 측정)는 기계 고장 진단의 관점에서 완전히 상이한 물리 변수입니다. 원시 파형 백업 시 가속도(`ST_Raw_Accel_t`)뿐만 아니라, 자이로 원시 파형 데이터(`ST_Raw_Gyro_t`)도 유실 없이 파일에 기록되도록 전용 `_preGyrBuf` 링버퍼 및 `_gyrBinFile` 덤프 핸들러를 스토리지 엔진에 구성하여 덤프 데이터의 도메인별 영속성 무결성을 완성합니다.

15. **센서 센싱 물리 특성에 따른 노이즈 차감(Spectral Subtraction)의 도메인 국소화 설계 (이슈 29 연계 보완)**
    * 비접촉식 마이크로폰(오디오)은 주변 환경 소음에 상시 오염되므로 켑스트럼 특징 추출 전 백인 노이즈 프로필 학습 및 스펙트럼 차감(Spectral Subtraction)이 물리적으로 필수적입니다. 반면 고체 접촉 전파식 가속도 센서는 기계 표면에 접착되어 주변 음향 소음에 영향을 받지 않고 오직 구조물의 물리적 진동만 수집하므로 노이즈 프로필 차감 연산을 전면 차단합니다. 대신, 진동 도메인은 장기 평균(LTA)을 통한 동적 임계치 갱신(Threshold Adaptation)만을 독자 가동하도록 신호처리 파이프라인을 분리 설계합니다.

16. **신호 해상도 물리 특성을 반영한 이종 샘플링 레이트 보간 방향성 교정 (이슈 22 연계 보완)**
    * 고속 오디오 신호(16kHz/42kHz)를 저속 진동 신호(1.6kHz)의 시간축 격자에 강제 매칭시키면 주파수 특징량(MFCC)의 고속 연속성이 왜곡 및 파열됩니다. 따라서 시간축 정렬기(`MultiRateTimeAligner`)는 오디오 누적 샘플을 Master Clock 기준으로 삼되, 저속 진동 데이터의 타임스탬프 스팬(Span)을 선형 보간(Linear Interpolation)하여 고속 오디오 타임 그리드에 주입(Up-sampling 방향의 결합)함으로써 데이터 정렬 시 물리적 신호 해상도 손실을 방어합니다.

17. **진동(가속도)과 회전 각속도(자이로) 센서 고유 물리 대역에 따른 필터링(HPF/LPF) 비대칭 구조 설계 (이슈 5 & 이슈 32 연계 보완)**
    * 기계적 베어링 결함이나 충격파 등 수백~수 kHz 영역의 과도 응답을 잡아야 하는 가속도는 직류 바이어스를 걷어내는 High Pass Filter(HPF)가 주연산인 반면, 모터 세차 운동 및 비틀림 회전 주기를 계측하는 자이로는 저주파 유효 거동 측정을 위해 고주파 충격 진동 노이즈를 깎아내는 Low Pass Filter(LPF)가 주연산입니다. 따라서 동적 설정 재계산(`recalculateFilters`) 모듈 구성 시, 가속도와 자이로에 필터 주파수 컷오프 파라미터를 동일하게 매핑하지 않고 **가속도는 HPF 및 Notch 위주, 자이로는 LPF 및 바이어스 소거 중심의 비대칭형 튜닝 파이프라인**을 독립 적용하도록 수정 설계하여 진단의 물리 정합성을 확보합니다.

18. **오디오 물리 신호 연속성 보존을 위한 프레임 드롭 시 크로스페이드 및 히스토리 평활화 가드 설계 (이슈 11 & 이슈 36 연계 보완)**
    * 링버퍼 오버런 시 데이터 파열을 막기 위해 가속도는 단순히 프레임 드롭 후 DSP 히스토리를 0.0f로 클리어하여 재수렴시킬 수 있으나, 매우 예민한 오디오 신호(MFCC 연산 입력)는 50% Overlap 홉의 위상이 일시적으로 단절되면 스펙트럼 누설로 인한 허위 알람이 발생합니다. 이를 위해 오디오는 꽉 참 시의 프레임 드롭 발생 구간 전후의 신호 접점에 **크로스페이딩(Cross-fading) 가드** 및 **MFCC 델타-델타 평활화 버퍼 이력의 보존 전이 로직**을 추가 적용하여, 프레임이 손실된 구간에서도 기계 진단 특징량의 인위적인 수치 급발진을 억제합니다.

19. **이종 물리 단위(g, dps, 무차원 스케일) 간의 다중 센서 융합용 SNR/배수 기반 무차원 표준화(Normalization) 설계 (이슈 24 & 이슈 43 연계 보완)**
    * 접촉 진동 가속도($g$), 각속도 자이로($dps$), 비접촉 음압 오디오(dB)는 물리적 차원(Dimension)이 완전히 상이하여 가중합이나 임계치 비교를 공통 수식으로 결합할 수 없습니다. 따라서 판정 엔진(`CL_T2_TriggerEngine`)은 원시 물리값의 다이렉트 비교를 전면 차단하고, 각 모달리티마다 개별 캘리브레이션된 정상 상태 진폭(Baseline) 대비 현재 측정치의 비율인 **Fold-Change(배수 스케일)** 또는 **신호 대 잡음비(SNR)** 개념으로 데이터를 무차원화(Dimensionless Normalization)한 뒤, 최종 다중 센서 융합 판정 로직에 주입하도록 설계하여 수식적/물리적 모순을 차단합니다.

20. **설비 결함주파수 대역과 센서별 주파수 분해능(Resolution) 종속성 격리 및 데모듈레이션(Envelope) 설계 (이슈 11 & 이슈 12 연계 보완)**
    * 저속 회전체 기계 결함(BPFO 등, 수십 Hz) 진단 시, 1.6kHz 가속도 1024-point FFT의 분해능($1.56\text{ Hz}$)은 고조파 분리에 적합하나, 16kHz 오디오 1024-point FFT의 분해능($15.6\text{ Hz}$)은 기계 고장 성분을 구별하기가 물리적으로 불가능합니다. 이를 극복하기 위해 두 도메인을 단순 FFT 대역 비교로 묶는 설계를 파기합니다. 가속도 엔진은 저주파 베어링 결함 성분을 고주파 반송파에서 추출하기 위해 **복소 포락선 복조(Envelope Demodulation)** 전처리 DSP 계층을 독립 가동하고, 오디오 엔진은 고주파 마찰음 및 누설 진단 목적의 켑스트럼 패턴 분석에만 종속되도록 주파수 연산 목적을 물리 대역에 따라 격리 설계합니다.

21. **물리적 신호 전달 경로(Transmission Path) 매질 속도 차이에 따른 시간 동적 정렬 오프셋 보정 설계 (이슈 22 & 이슈 31 연계 보완)**
    * 타격 파형 발생 시 고체(금속) 전파 진동은 약 $5,900\text{ m/s}$로 마이크로초 단위 도달을 보이나, 공기 전파 소음은 약 $340\text{ m/s}$로 느리게 도달하므로, 두 센서 간 $50\text{ cm}$ 이격 배치 시 약 $1.47\text{ ms}$ (오디오 $23.5$ 샘플 수준)의 물리 전달 지연(Time-of-Flight Shift)이 필연적으로 수집부에 유입됩니다. 시간축 정렬기(`MultiRateTimeAligner`)는 단순 취득 시각 동기화를 넘어, 기하학적 배치 거리에 따른 **매질 전파 지연 오프셋(`_propagation_delay_offset_us`)** 변수를 보정 항으로 반영하여 오디오와 진동의 이벤트 발생 임팩트 시점을 물리적으로 정렬시켜 AI 텐서 결합 유효성을 보장합니다.

22. **ISO-10816 설비 진단 표준 사양을 만족하기 위한 가속도-진동 속도(Velocity) 변환 적분기(Integrator) 설계 (이슈 2 & 이슈 26 연계 보완)**
    * 설비의 저주파 기계식 고장(1X/2X 불평형, 느슨함 등)은 절대 가속도($g$) 단위 판정 시 저주파 감도가 극히 떨어져 판정이 누락되고 고주파 노이즈에 의존하는 물리학적 모순이 있습니다. 이를 막기 위해 가속도 진단 파이프라인(`T240_DspEng`) 내에 가속도 원시 파형을 주파수 영역에서 $1/\omega$ 필터링하거나 시간 영역에서 면적 적분을 적용하여 **진동 속도(Velocity, $mm/s$ RMS) 스트림으로 물리 변환하는 적분기(Integrator) 모듈**을 포함하고, 저주파 대역 룰 평가기에는 가속도가 아닌 속도 진폭 데이터를 매핑하여 판정 신뢰성을 확보합니다.

23. **MEMS 센서 온도 드리프트 동적 보정 설계 (이슈 5 & 이슈 26 연계 보완)**
    * **물리적 모순:** 기계 구동 시 마찰열 등으로 인해 가속도/자이로 센서 본체의 온도가 비선형적으로 상승합니다. 이때 MEMS 소자의 열 팽창 및 정전 용량 변동으로 인해 ZRO(Zero-g Offset)가 드리프트됩니다. 고정된 캘리브레이션 오프셋만 적용하면 고온 조건에서 특징량이 왜곡되어 오경보를 유발합니다.
    * **해결 설계:** 센서 내장 온도 센서(`BMI270_TEMP`)의 실시간 측정값 $T_t$를 바탕으로, 다항식 온도-오프셋 커브 $Offset(T) = a_2 T^2 + a_1 T + a_0$를 적용하여 실시간으로 가속도 및 자이로 원시 데이터에서 오프셋을 동적으로 차감합니다.
```cpp
// T230_Sensor_250.hpp
struct ST_TempCalibCoeffs_t {
    float acc_coeff[3][3];  // 3축 x [a2, a1, a0] 계수
    float gyro_coeff[3][3]; // 3축 x [a2, a1, a0] 계수
};

class CL_T2_SensorEngine {
private:
    ST_TempCalibCoeffs_t _tempCalib;
public:
    void compensateThermalDrift(float raw_acc[3], float raw_gyro[3], float temp_c) {
        for (int i = 0; i < 3; i++) {
            float acc_offset = _tempCalib.acc_coeff[i][0] * temp_c * temp_c +
                               _tempCalib.acc_coeff[i][1] * temp_c +
                               _tempCalib.acc_coeff[i][2];
            raw_acc[i] -= acc_offset;

            float gyro_offset = _tempCalib.gyro_coeff[i][0] * temp_c * temp_c +
                                _tempCalib.gyro_coeff[i][1] * temp_c +
                                _tempCalib.gyro_coeff[i][2];
            raw_gyro[i] -= gyro_offset;
        }
    }
};
```

24. **오디오 다중 경로 반사 지연(RT60) 및 공간 잔향 평활화 마스커 설계 (이슈 29 연계 보완)**
    * **물리적 모순:** 밀폐된 공장 환경은 소음이 다중 경로로 반사(Multipath Reflection)되어 잔향 시간(RT60)이 깁니다. 기계 이상에 의한 고음파 누설이 발생 후 소멸되어도 반사파(잔향음)가 잔류하여 오경보가 연장되는 물리학적 모순이 발생합니다.
    * **해결 설계:** 오디오 특징 추출기에서 잔향의 지수 감쇄 특성을 감안한 **다차원 마스킹 필터 및 동적 EMA 평활화기**를 구성하여, 이전 시점의 잔향 에너지를 감안한 마스커(Reverberation Masker)를 차감 적용합니다.
```cpp
// T245_FeatExtra_250.hpp
class CL_T2_FeatureExtractor {
private:
    float _reverb_mask[16];   // 16개 오디오 밴드별 잔향 마스커 상태
    float _decay_coeffs[16];  // 16개 오디오 밴드별 물리 반사 감쇄 계수 (beta = e^(-dt/tau))
public:
    void applyReverbMasking(float* current_band_energies, size_t band_cnt) {
        for (size_t b = 0; b < band_cnt; b++) {
            // 1. 현재 입력 에너지와 이전 마스킹 잔류치 중 최대값 획득
            float v_effective = std::max(current_band_energies[b], _reverb_mask[b]);

            // 2. 현재 입력에서 잔향 노이즈를 감산하여 물리 순수 성분 분리
            current_band_energies[b] = std::max(0.0f, current_band_energies[b] - _reverb_mask[b]);

            // 3. 지수 감쇄(Decay) 모델을 적용하여 다음 주기 마스커 갱신
            _reverb_mask[b] = v_effective * _decay_coeffs[b];
        }
    }
    }
};
```

25. **가속도-자이로 간의 간섭(원심력 및 중력 가속도 투영) 보상 설계 (이슈 5 & 이슈 26 연계 보완)**
    * **물리적 모순:** 회전 기계 기동 시 발생하는 원심가속도($a_c = r\omega^2$) 및 동적 기울기 변동에 따른 중력 가속도($g$) 투영 성분이 가속도 센서에 합성 유입됩니다. 이를 보상하지 않으면 회전 속도 변화 시 가짜 진동 결함으로 판정하게 됩니다.
    * **해결 설계:** 자이로 3축 각속도 적분 기반 실시간 동적 자세각(Tilt Angle)을 추정하여 $g$-벡터 성분을 가속도 데이터에서 실시간 감산하고, 장착 반경 $r$과 각속도 $\omega$를 매핑하여 원심력 오프셋을 제거합니다.
```cpp
// T230_Sensor_250.hpp / .cpp
class CL_T2_SensorCompensator {
private:
    float _mounting_radius_m = 0.05f; // 센서 회전 중심축으로부터의 기하학적 거리
    float _pitch_rad = 0.0f;
    float _roll_rad = 0.0f;
public:
    void compensateDynamicForces(float acc[3], const float gyro[3], float dt) {
        // 1. 자이로 각속도 기반의 피치/롤 자세각 적분 (상보필터 적용)
        _pitch_rad += gyro[0] * dt;
        _roll_rad  += gyro[1] * dt;

        // 2. 자세 변화에 따른 3축 중력 가속도 투영 성분 계산
        float g_x = -sin(_pitch_rad);
        float g_y =  sin(_roll_rad) * cos(_pitch_rad);
        float g_z =  cos(_roll_rad) * cos(_pitch_rad);

        // 3. 가속도 센서에서 중력 성분 소거
        acc[0] -= g_x;
        acc[1] -= g_y;
        acc[2] -= g_z;

        // 4. z축 회전에 따른 원심력(r * w^2) 성분 계산 및 z축 진동 보정
        float w_z = gyro[2];
        float centrifugal_force = _mounting_radius_m * w_z * w_z;
        acc[2] -= centrifugal_force;
    }
};
```

26. **오디오 공간 위상 상쇄 방지 스펙트럼 플럭스(Spectral Flux) 분석 설계 (이슈 29 연계 보완)**
    * **물리적 모순:** 고주파(수 kHz 이상) 음파는 매질 반사 시 정류파(Standing Wave)나 위상 상쇄가 필연적으로 발생합니다. 단일 지점 마이크의 고정 주파수 음압 절대 크기에 의존하면 기하학적 위치에 따라 결함 감지가 누락되는 불감대(Blind Spot)가 발생합니다.
    * **해결 설계:** 특정 밴드 파워의 단순 비교를 전면 차단하고, 주파수 분포의 시계열 변화율을 나타내는 **스펙트럼 플럭스(Spectral Flux)** 지표를 도출하여 마이크 위치에 기인한 위상 간섭에 견고한 진단 로직을 수립합니다.
```cpp
// T245_FeatExtra_250.cpp
float calculate_spectral_flux(const float* current_fft, const float* prev_fft, size_t bins) {
    float flux_sum = 0.0f;
    for (size_t i = 0; i < bins; i++) {
        // 에너지 증가량만을 타겟으로 추출 (Half-wave Rectification)
        float diff = current_fft[i] - prev_fft[i];
        if (diff > 0.0f) {
            flux_sum += diff * diff;
        }
    }
    return sqrt(flux_sum); // 스펙트럼 변동 에너지 반환
}
```

27. **센서 장착 강성(Mounting Stiffness) 고유 주파수 특성 이퀄라이징 설계 (이슈 5 & 이슈 32 연계 보완)**
    * **물리적 모순:** Stud(스크류), Adhesive(에폭시), Magnet(자석) 등 센서 기계 장착 방식의 접촉 강성에 의해 차단 주파수(Cut-off) 및 물리 주파수 전달 특성이 왜곡(고주파 댐핑 등)됩니다.
    * **해결 설계:** 부착 모드 정보(`EM_MountingType_t`)에 따라, 주파수 감쇄 프로필을 역 보상해 주는 **피킹/이퀄라이저 필터(Peaking Equalizer Filter)**를 DSP 초입부에 구성하여 물리적 체결 특성 불일치를 해소합니다.
```cpp
// T240_DspEng_250.hpp
enum class EM_MountingType_t : uint8_t {
    STUD = 0,
    ADHESIVE,
    MAGNET
};

class CL_T2_DspEqualizer {
private:
    float _eq_coeff_b[3]; // EQ 바이쿼드 필터 계수
    float _eq_coeff_a[2];
    float _state[2] = {0.0f, 0.0f};
public:
    void setupEqualizer(EM_MountingType_t mounting) {
        if (mounting == EM_MountingType_t::MAGNET) {
            // 자석 장착 시 고주파가 억제되므로 4kHz 이상 고역대 피킹 부스트 적용
            // Biquad peaking EQ 계수 계산 적용
            _eq_coeff_b[0] = 1.25f; _eq_coeff_b[1] = -1.15f; _eq_coeff_b[2] = 0.35f;
            _eq_coeff_a[0] = -1.15f; _eq_coeff_a[1] = 0.30f;
        } else {
            // Stud 장착 등 플랫한 응답에 대해서는 바이패스 계수 설정
            _eq_coeff_b[0] = 1.0f; _eq_coeff_b[1] = 0.0f; _eq_coeff_b[2] = 0.0f;
            _eq_coeff_a[0] = 0.0f; _eq_coeff_a[1] = 0.0f;
        }
    }
    float processEQ(float input) {
        float output = _eq_coeff_b[0]*input + _eq_coeff_b[1]*_state[0] + _eq_coeff_b[2]*_state[1]
                       - _eq_coeff_a[0]*_state[0] - _eq_coeff_a[1]*_state[1];
        _state[1] = _state[0];
        _state[0] = input;
        return output;
    }
};
```

```cpp
    AIRBORNE_DOMINANT            // 누설, 아크 등
};

    float _weight_aud = 0.5f;
public:
    void adjustFusionWeights(EM_FaultPhysicalOrigin_t origin) {
```

30. **고진동 동작 시의 자이로 MEMS 소자 동적 포화(Rectification Drift) 및 고주파 격리 차단 설계 (이슈 5 & 이슈 32 연계 보완)**
    * **물리적 모순:** 설비에 회전 비틀림 모멘트가 발생하지 않아도 강한 물리 충격 및 고진동(가속도 $1.5g$ RMS 초과)이 주입될 경우 자이로 소자 공진기가 동적 포화(Saturation)되어 가상의 각속도 드리프트가 발생하는 물리학적 모순이 있습니다.
    * **해결 설계:** 가속도 RMS 상태를 모니터링하여 고진동 상황으로 판단되면, 자이로 채널의 저역 성분(드리프트 누적치)을 물리 차단하는 가변 하이패스 필터(High-pass Filter)를 동적 적용해 정밀 비틀림 충격 주파수만 통과시킵니다.
```cpp
// T240_DspEng_250.cpp
class CL_T2_GyroDriftMitigator {
private:
    float _hpf_alpha_normal = 0.99f; // 일반 차단 계수 (낮은 Cut-off)
    float _hpf_alpha_high_vib = 0.90f; // 고진동 시 차단 계수 상향 (높은 Cut-off로 드리프트 급속 제거)
    float _prev_filtered[3] = {0.0f, 0.0f, 0.0f};
public:
    void filterGyroDrift(float out_gyro[3], const float raw_gyro[3], float accel_rms) {
        float alpha = (accel_rms > 1.5f) ? _hpf_alpha_high_vib : _hpf_alpha_normal;
        for (int i = 0; i < 3; i++) {
            _prev_filtered[i] = alpha * (_prev_filtered[i] + raw_gyro[i] - _prev_filtered[i]);
            out_gyro[i] = raw_gyro[i] - _prev_filtered[i]; // DC/드리프트 성분 소거
        }
    }
};
```

31. **과도 응답 충격 신호(Transient Shock)와 RMS 에너지 분석의 물리적 적분 시간(Integration Window) 모순 (이슈 24 & 이슈 43 연계 보완)**
    * **물리적 모순:** 기어 이빨 파손이나 베어링 외륜 크랙 시 발생하는 충격 신호는 수 ms 미만의 과도(Transient) 특성을 가집니다. 주파수 해상도를 위해 수백 ms 단위의 긴 시간 구간을 적분(RMS)하게 되면, 분모가 커져 충격파 에너지가 스미어링(Smearing)되어 감지가 차단됩니다.
    * **해결 설계:** 단순 RMS 파이프라인 외에, 순시 Peak 값과 RMS의 비를 계산하는 **크레스트 팩터(Crest Factor)** 지표와 30ms 단위의 **미세 슬라이딩 윈도우 Peak-Hold 감지기**를 동시 가동하여 평탄화 모순을 해소합니다.
```cpp
// T240_DspEng_250.cpp
struct ST_TransientFeatures_t {
    float peak_hold;
    float crest_factor;
};

class CL_T2_TransientAnalyzer {
private:
    float _peak_hold_val = 0.0f;
    uint32_t _peak_hold_timer = 0;
public:
    ST_TransientFeatures_t analyzeTransient(const float* raw_data, size_t len, float rms) {
        float max_val = 0.0f;
        for (size_t i = 0; i < len; i++) {
            float abs_val = std::abs(raw_data[i]);
            if (abs_val > max_val) max_val = abs_val;
        }

        // 30ms 단기 Peak Hold 동적 유지
        if (max_val > _peak_hold_val) {
            _peak_hold_val = max_val;
            _peak_hold_timer = millis();
        } else if (millis() - _peak_hold_timer > 30) {
            _peak_hold_val = max_val; // decay
        }

        ST_TransientFeatures_t feats;
        feats.peak_hold = _peak_hold_val;
        feats.crest_factor = (rms > 0.0001f) ? (_peak_hold_val / rms) : 1.0f;
        return feats;
    }
};
```

32. **자이로와 가속도의 기하학적 배치 오프셋(Geometric Offset / Lever Arm Effect)에 의한 측정 위상 모순 (이슈 5 & 이슈 26 연계 보완)**
    * **물리적 모순:** 동일 패키지 내부나 외부 장착 브래킷 무게중심과 센서 간에 거리가 생기면, Lever Arm 효과($a_{lever} = \alpha \times r + \omega \times (\omega \times r)$)로 인해 가속도 측정치에 위상 천이(Phase Shift) 및 추가 외란 가속도가 주입되어 진단 물리량이 모순됩니다.
    * **해결 설계:** 센서 구조에 **레버 암 편차 벡터(Lever Arm Vector $\vec{r}_{lever}$)** 오프셋 상수를 설정하고, 자이로 각가속도($\alpha$) 및 각속도($\omega$)를 결합 연산하여 가속도 측정치에서 기하 중심 이탈 오차를 역 필터링합니다.
```cpp
// T230_Sensor_250.cpp
class CL_T2_LeverArmCompensator {
private:
    // 기하학적 레버 암 오프셋 벡터 (x, y, z) - 단위: m
    const float _r_lever[3] = {0.01f, 0.005f, 0.02f};
    float _prev_gyro[3] = {0.0f, 0.0f, 0.0f};
public:
    void compensateLeverArm(float acc[3], const float gyro[3], float dt) {
        if (dt <= 0.0f) return;

        // 각가속도 (Angular Acceleration = d(gyro)/dt) 산출
        float alpha[3];
        for (int i = 0; i < 3; i++) {
            alpha[i] = (gyro[i] - _prev_gyro[i]) / dt;
            _prev_gyro[i] = gyro[i];
        }

        // Lever Arm 보정식 유도: acc_corrected = acc_measured - (alpha x r + w x (w x r))
        // 1) alpha x r (크로스 프로덕트)
        float alpha_cross_r[3] = {
            alpha[1] * _r_lever[2] - alpha[2] * _r_lever[1],
            alpha[2] * _r_lever[0] - alpha[0] * _r_lever[2],
            alpha[0] * _r_lever[1] - alpha[1] * _r_lever[0]
        };

        // 2) w x r (크로스 프로덕트)
        float w_cross_r[3] = {
            gyro[1] * _r_lever[2] - gyro[2] * _r_lever[1],
            gyro[2] * _r_lever[0] - gyro[0] * _r_lever[2],
            gyro[0] * _r_lever[1] - gyro[1] * _r_lever[0]
        };

        // 3) w x (w x r) (크로스 프로덕트)
        float w_cross_w_cross_r[3] = {
            gyro[1] * w_cross_r[2] - gyro[2] * w_cross_r[1],
            gyro[2] * w_cross_r[0] - gyro[0] * w_cross_r[2],
            gyro[0] * w_cross_r[1] - gyro[1] * w_cross_r[0]
        };

        // 가속도 데이터에서 오차 벡터 감산
        for (int i = 0; i < 3; i++) {
            acc[i] -= (alpha_cross_r[i] + w_cross_w_cross_r[i]);
        }
    }
};
```

33. **온도 변화에 따른 공기 전파 음향 속도 왜곡 및 동적 지연 오프셋 정합 모순 (이슈 22 & 이슈 26 연계 보완)**
    * **물리적 모순:** 공기 중 음속은 온도의 영향($v = 331.5 + 0.607 T_c \text{ [m/s]}$)을 심하게 받습니다. 주변 온도가 $10^\circ\text{C}$에서 $50^\circ\text{C}$로 변동할 때 음속은 약 $7.2\%$ 변하며, 센서 간 이격이 있는 경우 고속 위상 동기 시 수십 샘플에 달하는 위상 스큐(Skew) 오차가 유발됩니다. 고정 지연 오프셋을 사용하면 환경 온도 변화 시 정합이 붕괴되는 모순이 있습니다.
    * **해결 설계:** `MultiRateTimeAligner` 내부에서 `_sensor`의 온도 피드백 값 $T_c$를 리드하여 동적 전파 지연 변수 $Delay(T_c) = d / (331.5 + 0.607 T_c) \times 10^6 \text{ [us]}$을 실시간 보정 계수로 탑재합니다.
```cpp
// T248_SeqBuild_250.cpp
class CL_T2_ThermalPropagationAligner {
private:
    const float _distance_m = 0.5f; // 마이크와 진동 센서 간 배치 거리
public:
    uint64_t calculateDynamicDelayUs(float temp_c) {
        // 음속 계산 v = 331.5 + 0.607 * T
        float speed_of_sound = 331.5f + 0.607f * temp_c;
        // 지연 시간(us) 계산
```

41. **I2S DMA 오디오 APLL과 가속도 물리 클럭 간 비동기 표류(Drift) 보정용 DPLL 소프트웨어 동기화 설계 (이슈 22 & 이슈 36 연계 보완)**
    * **물리적 모순:** 하드웨어 I2S DMA 수집 클럭은 ESP32 내장 APLL(Audio PLL) 소스를 받아 고정밀도로 동작하는 반면, 가속도 센서(BMI270)의 인터럽트 주기는 칩 내부의 저가형 RC 발진기(허용오차 $\pm2\%$)에 의존합니다. 두 도메인을 타임스탬프 결합 시 시간에 따라 물리 클럭 드리프트(Clock Drift)가 축적되어 AI 텐서 정렬 위상이 점진적으로 무너집니다.
    * **해결 설계:** 오디오 APLL 클럭 타임스탬프를 **마스터 클럭(Master Clock)**으로 고정하고, 가속도 샘플 입력 주기를 디지털 위상 동기 루프(DPLL) 피드백 필터로 감시하여 샘플 주기 수집 속도의 누적 편차를 동적 비례 보간(Rescaling)하는 보정 필터를 탑재합니다.
```cpp
// T248_SeqBuild_250.cpp
class CL_T2_DpllTimeSync {
private:
    double _drift_factor = 1.0;
    uint64_t _last_master_ts = 0;
    uint64_t _last_sensor_ts = 0;
public:
    void updateDpll(uint64_t master_ts, uint64_t sensor_ts) {
        if (_last_master_ts > 0 && _last_sensor_ts > 0) {
            double master_delta = static_cast<double>(master_ts - _last_master_ts);
            double sensor_delta = static_cast<double>(sensor_ts - _last_sensor_ts);

            // 드리프트 팩터 동적 추적 및 EMA 스무딩
            if (sensor_delta > 0) {
                double current_drift = master_delta / sensor_delta;
                _drift_factor = 0.95 * _drift_factor + 0.05 * current_drift;
            }
        }
        _last_master_ts = master_ts;
        _last_sensor_ts = sensor_ts;
    }

    uint64_t getCompensatedTimestamp(uint64_t raw_sensor_ts) {
        // 동기 보정된 타임스탬프 출력
        int64_t delta = static_cast<int64_t>(raw_sensor_ts - _last_sensor_ts);
        return _last_master_ts + static_cast<uint64_t>(delta * _drift_factor);
    }
};
```

43. **ISR과 일반 태스크 간의 공유 Queue 경합 데드락 및 인터럽트 지연(Latency) 방어 설계 (이슈 13 & 이슈 22 연계 보완)**
    * **시스템적 모순:** FSM Command 수신 큐(`_qSessionCmd`)는 ISR(가속도 임계 인터럽트)과 일반 통신 태스크(MQTT/WebSocket) 양측에서 데이터를 수신합니다. 일반 태스크가 큐의 임계 영역(Critical Section)을 획득하고 락을 잠근 상황에서 인터럽트가 기동되고 ISR 내에서 `xQueueSendFromISR`을 호출하게 되면, 데드락이 유발되거나 인터럽트 처리 지연(Interrupt Latency)이 유발되어 실시간 센서 타이밍이 무너집니다.
    * **해결 설계:** ISR과 태스크가 직접 마주치는 신호단은 커널 큐 잠금에 의존하지 않고, 원자적 비트마스크 변수(`std::atomic<uint32_t> _isrCmdPending`) 또는 단방향 비차단 **락프리 단일생산자-단일소비자(SPSC) 링버퍼**를 사용하여 대기 없는 non-blocking 상태로 인터럽트를 최우선적으로 리턴합니다.
```cpp
// T290_FsmMgr_250.hpp
class CL_T2_FsmManager {
private:
    // ISR이 커맨드를 쓰는 원자적 non-blocking 레지스터 버퍼
    std::atomic<uint32_t> _isrCmdPending{0};
public:
    void IRAM_ATTR dispatchCommandFromISR(uint8_t cmd) {
        // 비차단형 원자적 OR 연산 (락 없음, 대기 없음)
        _isrCmdPending.store(cmd, std::memory_order_release);
    }

    void processPendingIsrCommands() {
        uint8_t cmd = _isrCmdPending.load(std::memory_order_acquire);
        if (cmd != 0) {
            _isrCmdPending.store(0, std::memory_order_relaxed);
            // 실제 FSM 태스크 내 안전 영역에서 커맨드 디스패치
            executeCommandInternal(cmd);
        }
    }
};
```

44. **PSRAM 대용량 AI 텐서 버퍼 캐시 미스(Cache Miss) 유발과 실시간 오디오 가공 프레임(Hop) 드롭 방지 설계 (이슈 4 & 이슈 38 연계 보완)**

```cpp
}
```

47. **Policy Traits 메타프로그래밍의 런타임 C-Style 설정 구조체 통합 단순화 (이슈 4 & 이슈 33 연계 보완)**

    * **단순화 설계:** 메타프로그래밍 구조체를 전면 철폐하고, 일반 런타임 C-Style 구조체(`ST_DynamicConfig_t`)에 `bool enable_fft` 및 `uint8_t band_count` 멤버 변수를 단순 바인딩하여 직관적인 `if (config.enable_fft)` 분기문만으로 런타임 튜닝과 핫스왑 유연성을 동시 확보합니다.

48. **SPI 비비동기 트랜잭션 큐 스케줄러 태스크의 하드웨어 바이너리 세마포어(Mutex) 단순화 (이슈 2 & 이슈 12 연계 보완)**
    * **불필요한 복잡성:** 단일 SPI 센서 버스 상의 동시 접근 예외를 처리하기 위해, 전송 큐(`ST_SpiTransaction_t`)와 이를 처리하는 독자적인 SPI 비동기 스케줄러 백그라운드 태스크를 두어 과도하게 많은 SRAM과 스레드 컨텍스트 스위칭 비용을 지불하고 있습니다.

49. **std::atomic 메모리 장벽(memory_order) 펜스를 ESP-IDF 표준 Ringbuf API로 교체 단순화 (이슈 15 & 이슈 36 연계 보완)**

50. **비동기 StorageTask 및 링버퍼 포인터 큐의 SD_MMC 기본 버퍼링 구조 대체 단순화 (이슈 16 & 이슈 25 연계 보완)**
    * **불필요한 복잡성:** SD 카드 파일 쓰기 병목 회피를 위해, 별도 백그라운드 I/O 스레드(`StorageTask`)를 가동하고 원시 데이터 링버퍼(`_asyncAudRing`)와 인덱스 동기화 큐(`_qAudStorage`)를 결합함으로써 중복 락 및 레이스 컨디션의 잠재 오류 범위가 불필요하게 큽니다.
    * **단순화 설계:** 비동기 파일 입출력 태스크와 링버퍼 인덱스 큐를 제거하고, FATFS/SD_MMC 드라이버 자체에 기본 내장된 섹터 단위 캐시 시스템을 최대한 신뢰하도록 합니다. 애플리케이션 레벨에서는 내부 SRAM 고갈을 방지하기 위해 외부 PSRAM 영역(`EXT_RAM_ATTR` 또는 `MALLOC_CAP_SPIRAM`)에 512KB의 대용량 이중 버퍼(Double Buffer)를 배치하여 데이터를 순차적으로 수집했다가 버퍼가 완전히 채워진 시점에만 동기식 `write`를 실행해 흐름을 직선화합니다.

51. **FSM 매니저 WARM_UP 상태 노드 폐기 및 단순 시간 가드(millis) 적용 단순화 (이슈 41 & 이슈 43 연계 보완)**

    * **단순화 설계:** FSM의 `WARM_UP` 상태 정의를 완전 삭제하고 상태 머신 구조를 기동 상태(READY)로 유지하되, 트리거 엔진(`CL_T2_TriggerEngine`)의 `evaluateTrigger()` 판정 구문 맨 위에 `if (millis() < 30000) return false;` 형태의 단순 런타임 가드 1줄만을 적용하여 상태머신의 복잡도 증가 없이 기동 오폭 격리를 실현합니다.

52. **ArduinoJson V7 전역 풀의 과도한 shrinkToFit() 수동 압축 연산 완전 폐기 단순화 (이슈 17 & 이슈 20 연계 보완)**
    * **불필요한 복잡성:** 통신 및 설정 처리 시마다 전역 풀로 선언된 `JsonDocument`에 대해 `clear()` 직후 메모리를 반환 및 평탄화하기 위해 `shrinkToFit()`을 수동 강제하고 있으며, 멀티스레드 락까지 겹쳐 CPU 오버헤드와 힙 단편화 발생률을 오히려 높이고 있습니다.
    * **단순화 설계:** ArduinoJson V7의 내부 동적 메모리 재사용 메커니즘을 신뢰하여, 인스턴스의 `shrinkToFit()`을 전면 삭제하고 단순 `clear()`만으로 풀의 내부 메모리 슬롯을 무부하 재사용하도록 설계를 극도로 평탄화합니다.

53. **이종 샘플링 레이트 보간(Interpolation) 연산의 타임스탬프 헤더 소프트 매핑(Soft Mapping) 단순화 (이슈 22 & 이슈 41 연계 보완)**
    * **불필요한 복잡성:** 가속도 센서와 오디오 APLL 간의 하드웨어 클럭 편차를 보정하기 위해, 취득된 특징량 데이터 전체에 소수점 보간 연산(DPLL 및 Linear Interpolation)을 매 수집 주기마다 수행하여 FPU 연산 부담과 코드 복잡도를 가중시킵니다.
    * **단순화 설계:** 특징 데이터 자체를 연산 보간하여 위상을 동기화하는 무거운 구조를 폐기하고, 수집 시각 데이터의 타임스탬프 헤더 값만 마스터 오디오 시각 기준으로 대치하는 **타임스탬프 소프트 매핑(Soft Timestamp Mapping)** 방식만을 적용하여 데이터 가공 비용을 제로(0)로 축소합니다.

54. **SD_MMC 파일 쓰기 병목용 물리 공간 선할당(Pre-allocation) 폐기 단순화 (이슈 16 & 이슈 39 연계 보완)**
    * **불필요한 복잡성:** 파일 쓰기 시 가비지 컬렉션(GC)에 따른 버퍼 넘침을 방지하기 위해 파일 기동 때마다 `f_lseek`와 dummy write로 10MB 이상의 공간을 0으로 미리 물리 선할당하는 방식을 사용하여 파일 오픈 지연시간을 크게 유발하고 파이프라인 개시 타이밍을 해칩니다.
    * **단순화 설계:** 비정상적으로 지연을 초래하는 물리 공간 채우기 루틴을 완전 제거하고, 드라이버 고유의 Cluster allocation을 따르도록 설계하되, 메모리 버퍼링 단의 링버퍼 깊이 임계치를 500ms 수준으로 동적으로 넓히는 가볍고 안전한 소프트웨어 버퍼링 구조만으로 대기 지연을 상쇄합니다.

55. **가변 heap_caps_aligned_alloc 텐서 메모리의 정적 alignas 멤버 배열 고정 단순화 (이슈 14 & 이슈 19 연계 보완)**
    * **불필요한 복잡성:** 텐서 추출 빌더에서 SIMD 정렬을 위해 런타임 힙에 aligned allocation을 수행하고, 파라미터 업데이트 시 누수를 막기 위해 소멸자에서 `heap_caps_free`를 감시하는 등 힙 관리 및 메모리 생명주기 복잡도를 증대시켰습니다.
    * **단순화 설계:** AI 모델 입력 특징 차원수가 실시간으로 변경되지 않는 환경적 고정 특성을 신뢰하여, 힙 할당 프로세스를 삭제하고 클래스 멤버 변수 영역에 **최대 텐서 크기 규격의 정적 정렬 배열(`static float _dataFlat[MAX_SIZE] alignas(16)`)**로 단순 선언 및 고정하여 힙 단편화와 해제 누수 위험을 영(0)으로 고정화합니다.

56. **설정 저널링(WAL) 및 background 백업 루프의 ESP32 표준 NVS API 대체 단순화 (이슈 3 & 이슈 10 연계 보완)**
    * **불필요한 복잡성:** 설정의 무결성과 마모 방지를 위해 복잡한 저널링 헤더(`ST_WalHeader_t`) 관리, CRC32 계산, 그리고 LittleFS 백업을 수행하는 별도의 WAL 드라이버를 개발해 연계시킴으로써 코드 복잡도와 연산 지연이 증가합니다.
    * **단순화 설계:** ESP32의 공식 SDK가 내부적으로 마모 평활화(Wear-leveling) 및 무결성 저널링을 완벽히 제공하는 **NVS Flash 라이브러리(`nvs_flash.h`)**를 직접 호출하도록 구조를 전면 대체하여 설정 관리 코드를 수십 줄 단위로 축소합니다.

57. **크래시 진단 영역(`g_CrashDiag`) WDT 패닉 시의 원자적 장벽 폐기 단순화 (이슈 26 & 이슈 27 연계 보완)**
    * **불필요한 복잡성:** 시스템 WDT 패닉 발생 시 최종 상태 백업 구조(`g_CrashDiag`)에 쓰기를 유도할 때, 듀얼코어 레이스 컨디션을 방어하기 위해 어셈블리 메모리 배리어(`asm volatile("memw")`)와 atomic_thread_fence를 중첩 구성하여 디버깅 복잡성을 유발합니다.
    * **단순화 설계:** WDT 리셋 및 패닉 예외는 OS 커널 스케줄러가 완전히 멈추고 Core 단독 모드로 기동 중인 시점에 단발성으로 수행됩니다. 따라서 듀얼코어 레이스 컨디션의 물리적 가능성이 없으므로 복잡한 장벽을 지양하고 **일반 C-Style 구조체 변수 직접 대입**만 가동하도록 단순화합니다.

### 2.34 [18] Non-Monotonic 시간의 동기화 오염 방지 (Monotonic Time 사용 강제)

* **목표:** SNTP 시간 동기화 시 발생할 수 있는 시간 도약(Time Jump/Skew)이 멀티레이트 정렬(`MultiRateTimeAligner`)의 시간축을 오염시키는 것을 방지하기 위해, 모든 실시간 데이터 수집 및 연산 타임스탬프에 `get_monotonic_timestamp_us()` (단조 증가 Monotonic Time)만 사용하도록 강제합니다.
* **구현 설계:**
```cpp
// T210_Def_250.hpp / T248_SeqBuild_250.hpp
// 타임스탬프 부여 시 Monotonic Time API로 강제 통일
inline uint64_t get_monotonic_timestamp_us() {
    return static_cast<uint64_t>(esp_timer_get_time());
}
```
* **타모듈 영향도:** RTC 시간(Wall-Clock)은 오직 로그 파일 생성이나 최상위 관리 화면 표시 등 사람이 식별하는 용도로만 격리 사용함.

### 2.35 [29] [Feature ↔ Storage ↔ Config] 학습된 환경 노이즈 프로필의 영속성 확보
* **목표:** 엣지 단에서 자가 학습된 배경 소음 노이즈 프로필(`_noiseProfile`)이 리부팅 시 휘발되어 오경보를 유발하는 것을 방지하기 위해 LittleFS에 바이너리로 저장하고 부팅 시 자동으로 복구합니다.
* **구현 설계:**
```cpp
// T260_Storage_250.cpp
bool CL_T2_StorageManager::saveNoiseProfile(const float* p_profile, size_t p_size) {
    File v_file = LittleFS.open("/sys/noise_profile.bin", "w");
    if (!v_file) return false;
    size_t written = v_file.write(reinterpret_cast<const uint8_t*>(p_profile), p_size * sizeof(float));
    v_file.close();
    return (written == p_size * sizeof(float));
}

bool CL_T2_StorageManager::loadNoiseProfile(float* p_profile, size_t p_size) {
    if (!LittleFS.exists("/sys/noise_profile.bin")) return false;
    File v_file = LittleFS.open("/sys/noise_profile.bin", "r");
    if (!v_file) return false;
    size_t read_bytes = v_file.read(reinterpret_cast<uint8_t*>(p_profile), p_size * sizeof(float));
    v_file.close();
    return (read_bytes == p_size * sizeof(float));
}
```
* **타모듈 영향도:** `CL_T2_ConfigManager`의 초기화 로직 및 `CL_T2_FeatureExtractor`(`T245`)에서 배경 노이즈가 학습 완료되는 시점에 파일 덤프를 수행해야 합니다.

### 2.36 [30] [FSM ↔ Commu] Zero-Copy 바이너리 텔레메트리 패킷 브릿지
* **목표:** 실시간 웹 모니터링 및 고속 전송을 위한 16바이트 정렬된 텔레메트리 패킷 `ST_PktTelemetry_t` 규격을 가공 파이프라인에서 정상 조립하여 `T270` 전송 브릿지에 던지도록 구현합니다.
* **구현 설계:**
```cpp
// T290_FsmMgr_250.cpp
void CL_T2_FsmManager::broadcastTelemetryPayload(const T2_Type::ST_FeatureSlot_Vib_t& p_vib, const T2_Type::ST_FeatureSlot_Aud_t& p_aud) {
    if (!_commu.hasActiveWebsockets()) return;

    // 16바이트 정렬을 유지하기 위해 alignas 선언
    alignas(16) T2_Type::ST_PktTelemetry_t v_pkt;
    v_pkt.header.magic = 0x54454C4D; // 'TELM'
    v_pkt.header.timestamp_us = get_monotonic_timestamp_us();

    // 특징량 복사 및 구조체 패킹 (Zero-Copy를 위한 direct write)
    std::copy(p_vib.features, p_vib.features + T2_Def::Vib::FEAT_CNT, v_pkt.payload.vib_feats);
    std::copy(p_aud.features, p_aud.features + T2_Def::Aud::FEAT_CNT, v_pkt.payload.aud_feats);

    _commu.broadcastBinary(reinterpret_cast<uint8_t*>(&v_pkt), sizeof(v_pkt));
}
```
* **타모듈 영향도:** `CL_T2_CommuManager`의 WebSocket 전송 버퍼 및 FSM의 브로드캐스트 분기 로직에 적용.

### 2.37 [38] [FsmMgr ↔ DspEng] 코어 마이그레이션 방지(Core Binding) 및 Task WDT 기아 현상 방어
* **목표:** 고부하 DSP 연산이 Core 0의 네트워크 및 센서 ISR과 경합하지 않도록 CPU 코어 바인딩을 고정하고, 연산 루프 중 Task WDT 리셋을 방어합니다.

```cpp

    // 수집 및 제어 태스크는 Core 0에 바인딩
    xTaskCreatePinnedToCore(SensorAcqTask, "SensorAcqTask", 4096, this, 12, &_hSensorTask, 0);
```

* **목표:** 대용량 파형 버퍼 등의 데이터 복사를 방지하도록 포인터(참조)를 직접 획득해 채워 넣는 Zero-Copy API를 설계합니다.
* **구현 설계:**
```cpp
// T216_RingBuf_250.hpp
template <typename T, size_t Cap>
class CL_T2_ZeroCopyRingBuf {
private:
    T _slots[Cap];
    std::atomic<size_t> _head{0};
    std::atomic<size_t> _tail{0};
public:
    T* reserveWriteSlot() {
        size_t h = _head.load(std::memory_order_relaxed);
        size_t t = _tail.load(std::memory_order_acquire);
        if ((h + 1) % Cap == t) return nullptr; // Buffer full
        return &_slots[h];
    }
    void commitWrite() {
        size_t h = _head.load(std::memory_order_relaxed);
        _head.store((h + 1) % Cap, std::memory_order_release);
    }
};
```

## 5. 설계 항목 간 상호 충돌 및 영향도 검증/보완 설계

설계서에 반영된 리팩토링 및 55개 이슈 해결 설계안 간에 상호 발생할 수 있는 하드웨어/소프트웨어적 충돌 요인을 식별하고, 이에 대한 구체적인 보완 설계 지침을 정의합니다.

### 5.1 SD 카드 전력 피크(전압 강하)와 센서 SPI 통신 에러 간의 충돌
* **원인 및 영향:** SD_MMC 쓰기 동작 시 발생하는 전류 피크(최대 100mA 이상)로 인한 VDD 전압 강하가 SPI 버스 전송 노이즈로 작용하여 BMI270 센서의 통신 무결성이 훼손될 수 있습니다. 이때 단순 SPI 통신 일시 에러를 센서 물리 고장으로 판단해 `reinitializeSensor()` 및 NVS 캘리브레이션 핫로드를 수행하면, 수백 ms의 수집 유실이 반복됩니다.
* **보완 설계:**
  - SPI 트랜잭션 연속 실패 카운터(임계치: 3회)를 도입하고, SD 카드 플러시(`SD_MMC Write`)가 현재 액티브하게 진행 중인 경우에는 즉시 센서 리셋을 유예하고 재시도 간격(Retry Delay)을 비동기식으로 보정합니다.
  - 전압 안정화를 위해 하드웨어 설계팀과 정합하여 VDD_SD 및 VDD_IMU 라인에 디커플링 커패시터(최소 10uF 및 100nF 조합) 배치를 권장하는 하드웨어 제약사항을 추가합니다.
```cpp
// T230_Sensor_250.cpp
bool CL_T2_Sensor::checkSpiIntegrityWithSdGuard() {
    if (CL_T2_StorageManager::getInstance().isWritingActive()) {
        // SD 쓰기가 활발할 때는 연속 에러 임계값을 5회로 완화하여 가짜 Sag 리셋 예방
        return (_spiErrCount < 5);
    }
    return (_spiErrCount < 3);
}
```

### 5.2 512KB 정적 이중 버퍼와 내부 SRAM 용량 충돌
* **원인 및 영향:** Karpathy 단순화 가이드에 부합하기 위해 512KB 크기의 이중 버퍼를 정적으로 할당할 경우, ESP32-S3 내부 SRAM(총 520KB)의 가용량을 초과하여 링커 에러(Ld Error)가 발생하거나 힙 공간 고갈로 인한 OOM 패닉이 불가피합니다.
* **보완 설계:**
  - 스토리지용 512KB 이중 버퍼는 반드시 외부 PSRAM 영역에 할당하도록 유도하기 위해 `EXT_RAM_ATTR` 컴파일 타임 특성을 강제하거나, PSRAM 전용 Allocator인 `MALLOC_CAP_SPIRAM`을 사용하도록 설계를 보완합니다.
  - 대조적으로, 실시간성이 극대화되어야 하는 I2S DMA 버퍼 및 SPI FIFO 수집용 임시 버퍼는 내부 SRAM (`MALLOC_CAP_INTERNAL | MALLOC_CAP_DMA`)에 강제 바인딩하는 **하이브리드 메모리 배치(Hybrid Memory Allocation)** 사양을 강제하여 캐시 미스 오버헤드와 SRAM 고갈을 동시에 예방합니다.
```cpp
// T260_Storage_250.cpp
// 외부 PSRAM에 배치되도록 강제 할당
EXT_RAM_ATTR uint8_t g_storageDoubleBuffer[2][512 * 1024] alignas(16);
```

### 5.3 WiFi/BLE RF 프로토콜 스택과 실시간 센서 수집(I2S DMA / SPI Polling) 코어 점유 경쟁
* **원인 및 영향:** ESP32의 WiFi/BLE 프로토콜 스택은 Core 0에서 최고 수준의 하드웨어 인터럽트 및 시스템 스레드 우선순위로 기동됩니다. 이로 인해 Core 0에 함께 바인딩된 센서 수집 태스크가 WiFi 트래픽 버스트 시 밀려 데이터 유실 및 링 버퍼 오버플로우가 초래됩니다.
* **보완 설계:**
  - WiFi/BLE 이벤트 루프의 우선순위보다 센서 데이터 패킷을 수집하는 `ImuAcqTask` 및 I2S DMA 핸들러의 태스크 우선순위를 상위로 격상(`configMAX_PRIORITIES - 1`)하고 Core 0에 단단히 고정(Pinning)시킵니다.
  - WiFi 송수신 처리 지연 시간(최대 15~20ms)을 감당할 수 있도록, I2S DMA 버퍼 깊이를 최소 6개 이상의 청크(Stride 구조)로 설계하여 수집 측 백로그 버퍼를 강화합니다.

### 5.4 esp_timer 단조 시계 백업 스위칭과 Software PLL 위상 스큐(Skew) 충돌
* **원인 및 영향:** 오디오 APLL 갱신 누락 시 esp_timer 기반 시스템 시계로 전환될 때, 두 소스 간 클럭 트리거 메커니즘과 드리프트 오차가 달라 Software PLL(`MultiRateTimeAligner`)의 `skew` 계산 값이 일시적으로 튀게 됩니다. 이는 Drop & Shift 필터를 오작동시켜 진동 데이터의 위상을 왜곡합니다.
* **보완 설계:**
  - 단조 시계로의 백업 스위칭이 감지되는 시점에 Software PLL 내부의 위상 누적 오차를 0으로 리셋하고, 스위칭 시점부터 500ms 동안은 급격한 데이터 드롭/쉬프트를 막는 **과도기 위상 Muting(안정화 필터)** 기능을 작동시킵니다.
  - APLL과 esp_timer 간의 평균 동적 드리프트를 계수화하여, 백업 모드 실행 시 계산되는 시간 왜곡에 이 보정 오프셋을 상쇄 반영하도록 알고리즘을 보완합니다.
```cpp
// T248_SeqBuild_250.cpp
void MultiRateTimeAligner::notifyClockSourceSwitch() {
    _prev_vib.timestamp_us = 0;
    _curr_vib.timestamp_us = 0;
    _mutingRemainingTicks = 25; // 약 500ms(20ms 슬롯 기준) 동안 드롭 제어 일시 동결
}
```

### 5.5 NVS 캐시 병합 지연(10초)과 비정상 전원 차단(Blackout) 시 상태 데이터 유실 충돌
* **원인 및 영향:** NVS 플래시 마모 예방 및 쓰기 지연 차단을 위한 10초 주기 RAM 캐시 병합(`checkLazyWrite`)은, 장비 캘리브레이션이나 네트워크 보안 키 등록 등 즉시 기록되어야 할 중요 데이터가 Blackout에 의해 손실되는 모순을 야기합니다.
* **보완 설계:**
  - NVS 트랜잭션의 성격에 따라 쓰기 방식을 **Immediate Commit**과 **Lazy Commit**으로 분리합니다.
  - 사용자 센서 캘리브레이션 고정(Lock), 장비 설정 영속화(`serializeConfig`), 그리고 시스템 비상 예외 진단 데이터(`g_CrashDiag`)는 캐시를 우회하여 NVS 메모리에 강제 플러시(`nvs_commit()`)를 유도하는 동기식 즉시 쓰기 API 사양을 적용하도록 설계를 강화합니다.
```cpp
// T220_CfgMgr_250.cpp
void CL_T2_ConfigManager::saveCriticalConfig(const ST_DynamicConfig_t& cfg) {
    _cachedConfig = cfg;
    writeConfigToFlashDirect(cfg); // 10초 데몬 틱 대기 없이 즉시 nvs_commit 수행
}
```

### 5.6 OTA 시작 시 태스크 강제 일시정지(Suspend)와 버스 뮤텍스(Mutex) 소유 간의 데드락 모순
* **원인 및 영향:** `CL_T2_FsmManager::handleOtaStart()`에서 실시간 처리 및 스토리지 태스크를 `vTaskSuspend`로 강제 중지시킬 때, 해당 태스크가 SPI 버스 락(`_lock`), LittleFS 쓰기 파일 락, 혹은 데이터 세션 뮤텍스를 획득(Locked)한 컨텍스트 내에 머무르고 있다면, 영구적인 우선순위 역전 및 데드락(Deadlock)이 유발됩니다. OTA 프로세스 중 해당 리소스에 접근하려는 FSM 스레드가 영구 블록됩니다.
* **보완 설계:**
  - 강제 `vTaskSuspend`를 배제하고, FSM 상태 기계의 `SYS_STATE_OTA` 전이 상태를 감지하여 개별 태스크 루프 내부에서 락을 완전히 반환한 안전 지점(Safe Point)에서 자발적으로 대기하도록 **Graceful Pause** 방식을 채택합니다.
```cpp
// T290_FsmMgr_250.cpp
void CL_T2_FsmManager::handleOtaStartSafe() {
    // 1. 상태 전이를 통해 태스크들이 루프 내 Safe Point에서 자발적으로 락을 반환하고 대기 유도
    setSystemState(SYS_STATE_OTA);
    
    // 2. 동적 세마포어 확인 기법 적용 (최대 100ms 대기 후 미릴리즈 시 강제 회수 복구)
    int waitLimit = 10;
    while (xSemaphoreGetMutexHolder(_spiBusMutex) != nullptr && --waitLimit > 0) {
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
```

### 5.7 SD 카드 Detect(CD) ISR 탈거와 SD_MMC 호스트의 물리적 Lock-up 모순
* **원인 및 영향:** SD 카드 무단 이탈 감지 시 ISR을 탈거하고 저장 세션을 닫도록 설계하였으나, 고속 전송(SD_MMC 1bit/4bit) 중 하드웨어 연결이 물리적으로 끊기면 호스트 컨트롤러 인터페이스가 FIFO 에러 상태로 멈춰(Lock-up) 버립니다. 단순히 ISR만 떼어내면 이후 카드 재삽입 시 하드웨어 블록이 초기화되지 않아 인식이 불가능해집니다.
* **보완 설계:**
  - CD 인터럽트 트리거 감지 시 물리 이탈 디바운스 타이머(50ms)를 적용하여 일시적 진동 오감지를 방지합니다.
  - 이탈이 확정되면 스토리지 드라이버 수준에서 `sdmmc_card_deinit()` 및 `sdmmc_host_deinit()`을 호출하여 **SD_MMC 물리 호스트 모듈 전체를 리셋 및 디이닛** 상태로 만듭니다.
```cpp
// T260_Storage_250.cpp
void CL_T2_StorageManager::handleCardDetectionUnplug() {
    detachInterrupt(digitalPinToInterrupt(SD_CARD_DETECT_PIN));
    
    // 호스트 물리 블록 하드웨어 리셋 강제 실행 (Lock-up 상태 원천 제거)
    sdmmc_card_deinit();
    sdmmc_host_deinit();
    
    _cardState = EM_CardState::UNPLUGGED;
}
```

### 5.8 3색 LED 표시기 동기 루프와 Task WDT 기아 상태 간의 성능 충돌
* **원인 및 영향:** LED 깜빡임(Blinking) 등 장시간에 걸친 물리적 지연(`delay` 또는 `vTaskDelay`)이 수반되는 LED 제어 함수(`CL_T2_LedIndicator`)가 메인 FSM 제어 태스크나 센서 수집 루프의 실행 스레드와 동기식으로 결합될 경우, CPU 독점으로 인해 Task Watchdog이 발동하거나 20ms 이내의 특징량 연산 타이밍이 훼손됩니다.
* **보완 설계:**
  - LED 인디케이터 구동부는 동기 루프를 배제하고, `esp_timer` 기반의 비동기 하드웨어 타이머 혹은 저우선순위(우선순위: `tskIDLE_PRIORITY + 1`)로 격리된 독립 **LED 데몬 태스크**를 도입합니다. FSM은 큐를 통해 상태 이벤트만 비차단형(`xQueueSend`)으로 통지하도록 분리합니다.
```cpp
// T290_FsmMgr_250.cpp
void CL_T2_FsmManager::updateLedIndicatorNonBlocking(EM_LedMode_t mode) {
    // LED Task로 비차단 명령 하달하여 실시간 제어 스레드와 LED 물리 딜레이 완벽 격리
    xQueueSend(_qLedCmd, &mode, 0); 
}
```

### 5.9 LittleFS 파일 쓰기 뮤텍스와 NVS 캐시 플러시 간의 물리 플래시 버스 독점 충돌
* **원인 및 영향:** WAL 백그라운드 플러시(`flushToLittleFSAndEraseNext`), NVS 캐시 강제 쓰기(`nvs_commit()`), 그리고 OTA 이미지 기록 동작은 모두 동일한 물리 SPI 플래시 컨트롤러를 점유합니다. 쓰기 연산 시 물리 플래시 쓰기 비지 상태(Busy)로 인해 CPU 캐시 로드가 일시 블로킹되며, 실시간 코드가 RAM에 없으면 실행 지연이 급증해 펌웨어 패닉이 일어납니다.
* **보완 설계:**
  - **코드의 RAM 상주 강제화:** 실시간 가공 핵심 함수인 `longRunningDspLoop`, SPI 인터럽트 핸들러 및 데이터 파이프라인 버퍼 관리 함수는 소스 코드 선언부에 `IRAM_ATTR` 및 `dram_attr`을 수식하여 물리적으로 SPI 플래시 버스 점유 상태에 영향을 받지 않도록 강제합니다.
  - **플래시 I/O 실행 윈도우 스케줄링:** 녹화 수집 모드(`SYS_STATE_WAV_RECORDING`) 시에는 대량의 LittleFS 정리 작업이나 비치명적 NVS 커밋을 유예하고, 장비 대기(`SYS_STATE_IDLE`) 상태로 전이될 때 플래시 I/O를 순차적으로 집중 처리하도록 제어 스케줄러를 보완합니다.
```cpp
// T220_CfgMgr_250.cpp
void CL_T2_ConfigManager::checkLazyWrite(EM_SystemState_t currState) {
    // 실시간 녹화 모드 시에는 Flash 쓰기를 철저히 대기시키고 IDLE 상태에서만 커밋 허용
    if (currState == SYS_STATE_WAV_RECORDING) {
        return; 
    }
    if (_isDirty && (millis() - _lastWriteMs > 10000)) {
        nvs_commit(_nvsHandle);
        _isDirty = false;
    }
}
```

### 5.10 SD_MMC 디이닛 후 버스 플로팅(Floating) 누설 전류 및 RF 간섭 충돌
* **원인 및 영향:** [이슈 29]에 따라 SD 카드가 무단 탈거되어 `sdmmc_host_deinit()`을 수행하면 SD_MMC 버스 핀들이 하이임피던스(Floating) 상태가 됩니다. 이때 플로팅된 D0~D3, CLK, CMD 라인들이 WiFi/BLE 고주파(RF) 신호의 안테나 기생 용량으로 작용하여 송수신 감도를 낮추거나, 내부 누설 전류가 발생하여 딥슬립 모드에서 전력 소모를 높이는 물리적 부작용이 생깁니다.
* **보완 설계:**
  - SD_MMC 호스트 리셋 디이닛 직후 모든 SD_MMC 버스 IO 핀들을 하드웨어적으로 풀업/풀다운(GPIO_PIN_MUX) 고정 상태로 변경하여 기생 유도 기전력 및 플로팅 누설을 방지합니다.
```cpp
// T260_Storage_250.cpp
void CL_T2_StorageManager::handleCardDetectionUnplug() {
    detachInterrupt(digitalPinToInterrupt(SD_CARD_DETECT_PIN));
    forceCloseFiles();
    
    sdmmc_card_deinit();
    sdmmc_host_deinit();
    
    // 이탈 시 버스 핀 기생 방전 제어 (GPIO 풀업/풀다운 강제)
    gpio_set_pull_mode((gpio_num_t)T2_HardwarePinConfig::PIN_SD_MMC_D0, GPIO_PULLUP_ONLY);
    gpio_set_pull_mode((gpio_num_t)T2_HardwarePinConfig::PIN_SD_MMC_D1, GPIO_PULLUP_ONLY);
    gpio_set_pull_mode((gpio_num_t)T2_HardwarePinConfig::PIN_SD_MMC_D2, GPIO_PULLUP_ONLY);
    gpio_set_pull_mode((gpio_num_t)T2_HardwarePinConfig::PIN_SD_MMC_D3, GPIO_PULLUP_ONLY);
    
    _cardState = EM_CardState::UNPLUGGED;
}
```

### 5.11 Stack Watermark 주기적 스캔 연산과 실시간 데이터 가공 지연 충돌
* **원인 및 영향:** [이슈 35] 해결을 위해 스택 하이워터마크(`uxTaskGetStackHighWaterMark`)를 쿼리할 때, FreeRTOS는 내부적으로 모든 스레드 스케줄러를 서스펜드(Suspend All)시킨 상태에서 스택 전체 버퍼를 역방향 스캔합니다. 이는 수 ms 이상의 블로킹 지연을 유발하여 실시간 FFT/특징량 연산 주기(20ms) 타이밍을 붕괴시키고 데이터 유실을 초래합니다.
* **보완 설계:**
  - `uxTaskGetStackHighWaterMark`는 실시간 가공 루프 내부에서 매번 호출하는 것을 절대 금지하고, 10초에 한 번 동작하는 저우선순위 FSM 메인터넌스 틱(`runMaintenance`)으로 실행 주기를 철저히 제한합니다.
```cpp
// T200_Main_250.cpp
void checkStackWatermarkSafe() {
    static uint32_t last_stack_check = 0;
    // 10초 주기로만 스캔을 제한하여 실시간 연산 스레드 블로킹 타임아웃 방지
    if (millis() - last_stack_check > 10000) {
        if (uxTaskGetStackHighWaterMark(nullptr) < 512) {
            ESP_LOGE("STACK", "Stack warning on current task!");
        }
        last_stack_check = millis();
    }
}
```
