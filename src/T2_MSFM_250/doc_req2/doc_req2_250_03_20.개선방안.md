## 2. Phase 1: 크래시 방지 및 실시간성 패치 (최우선 반영)

### [이슈 1] GDMA 전송 및 CPU L1 캐시 일관성 (Cache Coherency) 제어 로직
* **이슈 검토 결과 (Issue Validation):**
  * GDMA가 PSRAM이나 외부 버퍼와 데이터 직접 전송 시 CPU L1 Cache의 복사본이 동기화되지 않아 데이터 오염이 발생할 수 있는 리스크가 매우 큽니다. `esp_cache_msync()` 호출 및 버퍼 배치 선언이 누락되었습니다.
* **개선 방안 (Proposed Resolution):**
  * 버퍼 할당 시 16/32바이트 정렬을 맞추고, DMA 수집 전후로 아래 API를 명시 호출하여 일관성을 확보합니다.
  ```cpp
  // DMA로 PSRAM에 데이터를 받기 전: 캐시 영역 무효화 (Invalidate)
  esp_cache_msync((void*)_psramFftWindow, FFT_SIZE * sizeof(float), ESP_CACHE_MSYNC_FLAG_INVALIDATE);
  // CPU가 PSRAM 데이터를 수정한 후 DMA로 보낼 때: Write-back 플러시 (Dirty)
  esp_cache_msync((void*)_psramFftWindow, FFT_SIZE * sizeof(float), ESP_CACHE_MSYNC_FLAG_DIRTY | ESP_CACHE_MSYNC_FLAG_UNALIGNED);
  ```
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * 캐시 동기화에 따른 미세 지연 트레이드오프보다 데이터 신뢰성이 절대적이므로, 예외 없이 전체 캐시 일관성 제어 로직을 활성화 적용합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통 - ESP-IDF 표준 캐시 제어 API 적용으로 Feasible.

### [이슈 9] FSM 매니저 내부의 제로 카피(Zero-Copy) 원칙 위배 (memcpy 남발)
* **이슈 검토 결과 (Issue Validation):**
  * `T290_FsmMgr_250.cpp` 내부의 `_vibProcessTask`에서 `memcpy`로 임시 구조체에 데이터를 깊은 복사하여 DMA의 성능적 이점을 잠식하고 있습니다.
* **개선 방안 (Proposed Resolution):**
  * 데이터 교환을 값 복사가 아닌 락 프리 큐 포인터 기반의 소유권 스왑 구조로 리팩토링합니다.
  ```cpp
  ST_FeatureSlot_Vib_t* v_slotPtr = nullptr;
  if (_ringBuf.dequeue(&v_slotPtr)) {
      _dsp.processAccel(v_slotPtr->raw_data); // 제로카피 접근
  }
  ```
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 힙 단편화와 동적 메모리 제어 지연을 방지하기 위해, 락프리 링버퍼는 **고정 정적 배열 기반의 인덱스 순환 방식**으로 수명 주기를 고정 적용합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 높음 - 전체 파이프라인의 데이터 교환 아키텍처 리팩토링 공수 필요.

### [이슈 12] ESP-DSP FFT 복소수 버퍼 크기 불일치
* **이슈 검토 결과 (Issue Validation):**
  * `_sramFftPing[1024]`에 `dsps_fft2r_fc32_ae32`를 호출하면 복소수 연산(실수/허수 쌍, $2\times N$)으로 인해 1024개 범위를 넘어선 힙 파괴가 즉각 발생하여 치명적입니다.
* **개선 방안 (Proposed Resolution):**
  * 버퍼 크기를 2048 float 크기로 2배 증설하고 Interleaved 방식으로 전처리 배열을 채웁니다.
  ```cpp
  alignas(16) float _sramFftPing[2048]; // 1024-point 복소수 FFT용
  for (int i = 0; i < 1024; i++) {
      _sramFftPing[2 * i] = raw_input[i];     // Real
      _sramFftPing[2 * i + 1] = 0.0f;         // Imag
  }
  dsps_fft2r_fc32_ae32(_sramFftPing, 1024);
  ```
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음. (즉각 교정 적용)
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통 - 버퍼 구조 선언과 Interleaving 전처리 루프 구성으로 가능.

### [이슈 13] FreeRTOS ISR 컨텍스트 위반
* **이슈 검토 결과 (Issue Validation):**
  * 인터럽트인 `T200_handleTriggerISR()` 내에서 일반 뮤텍스/블로킹 동기식 명령 디스패치 함수를 호출하여 즉각적인 커널 크래시(패닉) 유발 위험이 있습니다.
* **개선 방안 (Proposed Resolution):**
  * FSM에 비블로킹 전용 `dispatchCommandFromISR()`를 신설하고 내부에서 `xQueueSendFromISR` 및 `portYIELD_FROM_ISR`을 통해 명령을 전달합니다.
  ```cpp
  BaseType_t CL_T2_FsmManager::dispatchCommandFromISR(uint32_t p_cmd) {
      BaseType_t xHigherPriorityTaskWoken = pdFALSE;
      xQueueSendFromISR(_cmdQueue, &p_cmd, &xHigherPriorityTaskWoken);
      return xHigherPriorityTaskWoken;
  }
  ```
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음. (커널 안정성을 위해 즉시 적용 필수)
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통 - FreeRTOS 표준 ISR 통신 매크로 활용으로 용이.

### [이슈 15] 락 프리 링버퍼 오버라이트 시 메모리 오더링(Memory Ordering) 역전
* **이슈 검토 결과 (Issue Validation):**
  * `enqueue()`가 꽉 찼을 때 `_tail` 포인터를 무거운 데이터 복사 전에 먼저 변경하여 읽기 단과의 동시성 오염 버그가 숨어 있습니다.
* **개선 방안 (Proposed Resolution):**
  * 데이터 쓰기 복사가 끝난 후에만 포인터를 갱신하고 메모리 배리어(`std::memory_order_release`)로 기계적 최적화 차단.
  ```cpp
  _buffer[head] = item; // 데이터 복사 완료
  std::atomic_thread_fence(std::memory_order_release); // 하드웨어 배리어
  _tail.store((tail + 1) % _capacity, std::memory_order_relaxed); // 그 후 tail 갱신
  ```
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통 - C++ 원자적 펜스 연산 적용.

### [이슈 16] 스토리지 I/O 뮤텍스 블로킹에 의한 실시간 파이프라인 붕괴
* **이슈 검토 결과 (Issue Validation):**
  * SD 카드의 물리 병목(최대 500ms 지연) 동안 동일한 `_lock`을 공유하는 실시간 데이터 수집 태스크까지 일시 락업(정지)되어 센서 버퍼가 유실되는 구조적 모순이 확인됩니다.
* **개선 방안 (Proposed Resolution):**
  * 락 획득 임계 구역(Critical Section)을 포인터 교환부로만 축소(Lock Decoupling)하고, 실제 Write 및 Flush 물리 IO는 뮤텍스를 쥐지 않은 백그라운드 태스크에서 비차단식 수행하도록 분리합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** SD_MMC 물리 플러시 지연을 극복하기 위해 백그라운드 SD 기록 전용 링버퍼의 크기를 **3~5초 분량(약 500KB~1MB)**으로 설정하여 임시 할당합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 높음 - 백그라운드 I/O 데몬 태스크 전면 이원화 및 락 생명주기 관리 필요.

### [이슈 33] 지연 쓰기(Lazy Write) 데몬 틱(Tick)의 고아화(Orphaned)
* **이슈 검토 결과 (Issue Validation):**
  * 설정 플래시 마모 예방용 Lazy Write `checkLazyWrite()` 함수가 어디에서도 호출되지 않아 RAM 설정 변경 후 전원 차단 시 영구 유실되는 결함이 있습니다.
* **개선 방안 (Proposed Resolution):**
  * FSM 유지보수 태스크 또는 T200 루프 내에 1초 단위로 폴링 호출하는 데몬 시퀀스 브릿지를 통합합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 낮음 - 타이머 틱/폴링 바인딩만으로 Feasible.

### [이슈 38] 코어 마이그레이션과 Task WDT 기아(Starvation) 현상
* **이슈 검토 결과 (Issue Validation):**
  * DSP 태스크에 코어 바인딩을 주지 않아 Core 0(네트워크/센서 ISR 전담)으로 스케줄링 시 시스템 정체와 Task WDT 리셋 패닉을 유발합니다.
* **개선 방안 (Proposed Resolution):**
  * `xTaskCreatePinnedToCore`로 DSP/ML 태스크를 Core 1에 고정시키고, 대량 연산 루프에 `esp_task_wdt_reset()` 및 `vTaskDelay`를 강제 삽입합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통 - RTOS 태스크 생성 설정 재조율로 Feasible.

## 3. Phase 2: 데이터 구조 일반화 및 최적화

### [이슈 4] Policy Traits 메타프로그래밍 구조체 불완전 (마스킹 제약 부족)
* **이슈 검토 결과 (Issue Validation):**
  * `T2_General` 네임스페이스 하단에 제어 상수들이 생략되어, 설계안에 기획된 도메인별 연산 Pruning(가지치기)이 런타임 분기 조건식으로 우회되고 있습니다.
* **개선 방안 (Proposed Resolution):**
  * `static constexpr bool` 상수들을 Traits 구조체에 온전히 구현하고 `if constexpr` 기법을 통해 컴파일 타임 최적화를 보장합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 낮음.

### [이슈 5] 자이로(Gyro) 전용 초경량 IIR 메모리 구조 미반영
* **이슈 검토 결과 (Issue Validation):**
  * 자이로는 고주파 대역이 불필요함에도 가속도 필터 구조체와 동일한 거대 FIR 필터 상태 버퍼를 상속받아 메모리 힙 공간이 낭비되고 있습니다.
* **개선 방안 (Proposed Resolution):**
  * 자이로 구조체(`ST_GyroDspRuntime`)의 FIR 필터 필드를 제거하고 초경량 IIR 필터 상태인 `_gyroIirState[3][4]`로 대체 적용합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 8] SMEA_FLASH_RODATA 매크로의 실제 적용 누락 (SRAM 낭비)
* **이슈 검토 결과 (Issue Validation):**
  * 필터 계수들이 런타임 구조체 내 alignas(16) float 멤버 배열로 선언되어 있어, 구조체 힙 할당 시 불필요한 복사 및 내부 SRAM을 수 KB 낭비합니다.
* **개선 방안 (Proposed Resolution):**
  * Notch 및 HPF 고정 필터 계수 배열들을 멤버 변수에서 제거하고 `const alignas(16)`를 결합해 Flash ROM 영역(XIP)에 직접 정적 상수로 배치하고 참조합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 14] TinyML AI 텐서 정렬(Alignment) 누락 (SIMD 로드 페널티)
* **이슈 검토 결과 (Issue Validation):**
  * 외부 SPIRAM에 `heap_caps_malloc`으로 할당된 텐서 버퍼가 32비트 정렬만 보장되므로, S3의 SIMD 벡터 연산 구동 시 정렬되지 않은 메모리 로드로 인한 심각한 성능 지연을 보입니다.
* **개선 방안 (Proposed Resolution):**
  * `heap_caps_aligned_alloc(16, size, MALLOC_CAP_SPIRAM)`을 적용해 16바이트 정렬을 강제 보장합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 향후 도입될 텐서 가속 라이브러리의 공통 표준 호환성을 위해, 정렬 요구 사양은 **16바이트 정렬**로 강제 준수하여 적용합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 17] JsonDocument 풀링 미반영 및 지역 변수 남발 (힙 단편화)
* **이슈 검토 결과 (Issue Validation):**

* **개선 방안 (Proposed Resolution):**
  * CfgMgr 내에 공용 멤버 변수 `JsonDocument _docPool`을 도입하고, 사용 전후로 `clear()` 및 `shrinkToFit()`을 호출하는 정적 풀링 기법을 적용합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 공용 `_docPool`의 멀티코어 충돌을 제어하기 위해, ConfigManager의 임계 접근부를 감싸는 최소한의 세마포어 뮤텍스 락킹 구조를 가볍게 배치하여 동시성을 격리합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 19] 비원자적 변수(Non-Atomic)에 대한 메모리 배리어 무효화
* **이슈 검토 결과 (Issue Validation):**

  * 상태 제어 플래그 변수를 `std::atomic<bool>` 또는 `volatile` 형태로 변경 선언하여 최적화 고착을 방지합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 30] Zero-Copy 바이너리 텔레메트리의 패킷 조립 브릿지 증발
* **이슈 검토 결과 (Issue Validation):**

## 4. Phase 3: 하드웨어 모듈 및 비동기 파이프라인 연동

### [이슈 2] SPI 트랜잭션 큐(Transaction Queue) 기반 비동기 스케줄링
* **이슈 검토 결과 (Issue Validation):**
  * SPI 통신이 동기식 blocking으로 처리되어 타 스레드가 대기하고, vTaskDelay(0)로 우회하고 있어 전송 주기에 불규칙한 지터가 생기고 실시간성이 저하됩니다.
* **개선 방안 (Proposed Resolution):**
  * SPI 전송 구조를 캡슐화한 `ST_SpiTransaction_t` 큐 엔진으로 리팩토링하고 백그라운드 SPI 비동기 인터럽트 구동 드라이버(`spi_device_queue_trans`)로 전면 개편합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 비동기 전송 시 발생하는 하드웨어 오류는 런타임에 즉시 개입하기 어렵기 때문에, 단순 오류 카운트를 증가시킨 후 연속 3회 실패 시 FSM에 디바이스 폴트(ERROR)를 던지는 단순 임계 판정형 콜백을 적용합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 높음 - SPI 드라이버 전체 계층 및 큐 아키텍처 재설계 필요.

### [이슈 11] I2S DMA 디스크립터 경계와 제로 카피 스트라이드(Stride) 충돌
* **이슈 검토 결과 (Issue Validation):**

  * `FFT_SIZE`와 `OVERLAP_RATIO`를 결합하여 `I2S_DMA_CHUNK_SIZE`를 컴파일 타임에 강제 도출하고, 이를 I2S 하드웨어 DMA 초기화 설정에 바인딩합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):** 없음. (수학적 결합을 통해 오버헤드를 원천 제거)

### [이슈 20] 핫스왑 설정 변경 후 백그라운드 데몬 동기화 누락
* **이슈 검토 결과 (Issue Validation):**
  * SSID나 IP, 브로커 주소가 핫스왑 저장되더라도 구동 중인 통신 데몬(`T270`)은 이 사실을 알 수 없어 하드 리부팅 전까지 기존 네트워크 소켓을 강제 유지하는 모순이 존재합니다.
* **개선 방안 (Proposed Resolution):**
  * 변경 감지 시 FSM에서 `CMD_RESTART_NETWORK` 명령을 하달하고, `T270`이 스스로 기존 소켓을 닫고 재기동하도록 런타임 시퀀스를 링킹합니다.

### [이슈 21] 사전 트리거(Pre-Trigger) 버퍼의 파일 덤프(Dump) 연동 누락
* **이슈 검토 결과 (Issue Validation):**

* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 24] 모드 전환 시 하드웨어 FIFO 잔여 데이터 오염 (Flush 무결성 결함)

### [이슈 25] 세션 닫기 전 '보류 중인(Pending) 데이터' 소실 (Graceful Shutdown 결함)

* **개선 방안 (Proposed Resolution):**

* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 10] WAL 플래시 수명 단축 (Write Amplification) 및 저널링 누락

### [이슈 18] Non-Monotonic 시간의 동기화 오염 (SNTP Time Jump)
* **이슈 검토 결과 (Issue Validation):**
  * 타임스탬프 계산에 NTP/RTC 시간을 사용하여 Wi-Fi 재동기화 시 시계열 타임스탬프가 앞뒤로 튀며(Time Jump) 멀티레이트 정렬 모듈이 데드락에 빠지는 논리 붕괴가 관측됩니다.
* **개선 방안 (Proposed Resolution):**
  * 정밀 시계열 분석 및 센서 융합용 타임라인에는 RTC 시각을 전면 배제하고, 하드웨어 단조 증가 시간인 `esp_timer_get_time()`만 일방 사용합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 부팅 시각 1회에 한해 RTC 시각과의 오프셋 관계를 체킹 갱신하여, 파일 네이밍 시점에는 Monotonic Time 기준의 정확한 절대 시각 추적이 매칭되도록 헬퍼 모듈을 구성합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 22] I2S와 SPI 이종 클럭 간의 시간 편차 (Clock Drift) 누적
* **이슈 검토 결과 (Issue Validation):**
  * APLL 클럭(오디오)과 SPI 폴링 틱(진동) 간 클럭 드리프트가 장시간 구동 시 누적되어 `MultiRateTimeAligner` 정렬 허용 오차를 벗어나 텐서 바인더가 데드락에 빠집니다.
* **개선 방안 (Proposed Resolution):**
  * 오디오 샘플 누적을 Master Clock으로 세팅하고 진동 스트림 데이터를 가상 동기화하며 편차가 어긋날 시 가장 가까운 과거 프레임을 강제 보정/보간하는 방식을 사용합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[의사결정 완료 및 권장안 확정]** 물리 인터럽트 설계를 보존하기 위해 하드웨어적 피드백 루프는 배제하며, 편차 임계 범위를 완화하고 오류 누적 시 프레임을 버려 재매칭하는 **소프트웨어 Drop & Shift 방식의 예외 회복 모듈**을 도입 적용합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 매우 높음 - 정밀 시계열 데이터 이종 보간/보정 로직 구현.

### [이슈 23] SD 카드 I/O 에러 발생 시 FSM 예외 처리 블랙홀
* **이슈 검토 결과 (Issue Validation):**

### [이슈 27] MQTT LWT와 로컬 진단 결과의 동기화 결함

* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 36] 오버라이트(Overwrite)에 의한 위상 불연속성과 스펙트럼 붕괴
* **이슈 검토 결과 (Issue Validation):**
  * 버퍼 꽉 참 시 단순 1샘플 오버라이트를 실행하여 신호 파형 위상에 `Hard Step(단차)`을 유발하고 스펙트럼 누설로 인한 100% 허위 결함 트리거 오동작을 일으킵니다.
* **개선 방안 (Proposed Resolution):**
  * 단일 샘플 드롭을 차단하고 1024 샘플 청크(FFT 윈도우 단위)로 프레임을 통째로 탈락(`Frame Drop`)시킨 후 신호 히스토리를 리셋하여 위상 연속성을 보호합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 오버플로우로 인한 신호 유실은 심각한 현장 결함 전조이므로, 프레임 드롭 발생 빈도는 **실시간 웹 UI 모니터링 페이지 및 내부 텔레메트리 에러 지표**에 명시적으로 노출 적용하도록 확정합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 37] 비동기 NTP 지연과 MQTT TLS 핸드셰이크 경합 (데드락)
* **이슈 검토 결과 (Issue Validation):**
  * NTP 타임 동기화 완료 전 MQTT MQTTS(TLS) 접속 시도 시 내부 시각(1970년)으로 인해 TLS 인증서 기간 만료 거부 연결 실패 교착이 발생합니다.
* **개선 방안 (Proposed Resolution):**
  * NTP 타임 동기화 API를 구동한 후 `timeinfo.tm_year > 120`을 만족할 때까지 MQTT 연결 루틴의 진입을 지연시키고 유보합니다.
* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 내부망 또는 외부 NTP 통신이 불가능한 전용 폐쇄망 구동 환경에 대응하기 위해, 시간 동기화 대기 시간의 최대 임계치(Timeout)는 **30초**로 구성하고, 초과 시 1970년 가상 시각 기준으로 로컬 수집 저장 동작을 강제 개시하도록 조율합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 39] 플래시 가비지 컬렉션에 의한 텐서 조립 타임아웃

* **개선 방안 (Proposed Resolution):**

* **사용자 결정 완료 사항 (User Decision Adopted):**

* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 높음 - FATFS 물리 클러스터 사전 할당 및 관리 제어 필요.

### [이슈 41] STA/LTA의 '콜드 스타트(Cold Start)' 초기화 모순에 의한 오경보 폭주
* **이슈 검토 결과 (Issue Validation):**

* **개선 방안 (Proposed Resolution):**

* **사용자 결정 완료 사항 (User Decision Adopted):** 없음. (WARM_UP 30초 시퀀스 기본 적용)
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.

### [이슈 43] MLOps 데이터 파이프라인의 '레이블 모호성' 발생
* **이슈 검토 결과 (Issue Validation):**
  * 결함 진단 트리거로 스토리지에 데이터를 덤프할 때 파일 내부에 어떤 결함 인자(임계치 초과 지표, 특정 주파수 대역 등)로 이상 판정이 났는지 상세 정보(그라운드 트루스)가 기록되지 않아 후속 학습 분석에 활용하기 어려움이 존재합니다.

* **사용자 결정 완료 사항 (User Decision Adopted):**
  * **[권장안 적용]** 엣지 시스템 내 데이터 직렬화 부하를 O(1) 수준으로 극소화하기 위해, 이상 사유 전달 헤더 규격은 가변 규격을 배제하고 **바이너리 고정 크기 구조체(ST_TriggerReason_t)** 형태로 바인딩하여 확정 적용합니다.
* **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** 보통.
