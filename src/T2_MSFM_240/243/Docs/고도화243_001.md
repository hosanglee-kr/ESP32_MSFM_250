**1. Context Alignment: 요구사항 요약**
 * **분석 대상:** Audio(소음)와 Vib(진동)의 샘플링 주기 비대칭성이 단일 태스크 및 단일 구조체(UnifiedFeatureSlot) 운용에 미치는 현실적 문제 검토.
 * **핵심 과제:** 이종 센서(Heterogeneous Sensors) 간의 시간 영역(Time Domain) 불일치가 유발하는 I/O 블로킹 및 데이터 유실 가능성 분석. 통합 유지 vs 도메인 분리 아키텍처의 장단점 비교 및 해결책 제시.
**2. Sequential Reasoning Process**
**[Thought #1] 센서별 물리적 시간 윈도우(Time Window) 비대칭성 분석**
 * **Thought:** Audio와 Vib의 설정된 샘플링 레이트와 FFT 윈도우 크기에 따른 데이터 수집 소요 시간을 산출한다.
 * **MECE Analysis:**
   * **Audio 도메인:** 샘플링 레이트 42kHz, FFT 기본 사이즈 1024. 1회 프레임 수집 소요 시간 = 1024 / 42,000 ≈ **24.3ms**.
   * **Vib 도메인:** 샘플링 레이트 1.6kHz, FFT 기본 사이즈 256. 1회 프레임 수집 소요 시간 = 256 / 1,600 = **160ms**. (FFT 1024 시 640ms).
 * **Potential Risk:** 물리적 시간의 격차가 약 6.5배~26배에 달함. 이를 하나의 동기식 태스크(_captureTask)와 단일 구조체(UnifiedFeatureSlot)로 묶을 경우 심각한 지연(Latency) 병목이 발생함.
**[Thought #2] I/O 블로킹 충돌 및 하드웨어 오버런(Overrun) 검증**
 * **Thought:** 단일 수집 태스크(Core 0)에서 두 센서를 동기식으로 읽을 때 발생하는 하드웨어 버퍼 상태를 분석한다.
 * **Reasoning:** T230_Sensor_243.cpp의 I2S 수집부(readAudioChunk)는 portMAX_DELAY를 사용하여 DMA 버퍼가 찰 때까지 블로킹됨. 반면 BMI270(SPI)은 FIFO를 폴링(readVibFifoBatch)함.
 * **Potential Risk:**
   * 태스크가 160ms 동안 Vib의 256 샘플이 모이기를 기다린다면, 그동안 I2S DMA 수신 링버퍼(DMA_BUF_COUNT_DEF = 16)가 오버플로우되어 Audio 데이터가 유실(Drop)됨.
   * 반대로 Audio 주기(24ms)에 맞춰 루프를 돌면, Vib FIFO에는 고작 38 샘플만 모여 있어 주파수 분석(FFT)을 수행할 수 없음.
**[Thought #3] AI 텐서 및 특징량 추출 주기의 정합성 문제**
 * **Thought:** 단일 UnifiedFeatureSlot에 Audio와 Vib 데이터를 융합(Sensor Fusion)할 때의 데이터 신선도(Freshness)를 검토한다.
 * **Reasoning:** 슬롯 조립을 위해서는 4채널(Vib 3 + Aud 1)의 MFCC 연산이 모두 완료되어야 함.
 * **Potential Risk:** 두 센서의 처리 주기가 다름에도 1개의 구조체로 방출(Emit)해야 하므로, Audio는 6번의 데이터가 버려지거나 평균화되어야 하고, Vib는 동일한 데이터가 중복(Stale Data) 전송되는 문제(Impedance Mismatch)가 발생함.
**[Thought #4] 통합(현재) vs 분리 아키텍처 비교**
 * **MECE Analysis:**
   * **통합 아키텍처 (Current - Early Fusion):** 1개의 구조체, 1개의 통신/저장 파이프라인.
   * **분리 아키텍처 (Separated - Late Fusion):** Audio/Vib 각각의 수집/처리 태스크, 독립된 구조체 및 Queue.
| 구분 | 현재 통합 구조 (Single Task & Slot) | 도메인 분리 구조 (Multi Task & Slot) |
|---|---|---|
| **I/O 병목** | I2S 블로킹 시 SPI FIFO 오버플로우 위험 큼 | 태스크 분리로 하드웨어 블로킹 원천 차단 |
| **연산 효율** | Audio 처리 대기 중 CPU 유휴 발생 가능 | 코어 점유율 최적화, 비동기 파이프라인 |
| **융합 레벨** | Feature-level (특징량 생성 시점 결합) | Decision-level (결함 판정 시점 결합) |
| **메모리/통신** | 1개 큐/저장소로 단순명료 (복잡도 낮음) | 2개 큐 운용으로 동기화 및 타임스탬프 관리 복잡 |
**3. Final Solution: 현실적 문제 해결 및 아키텍처 재설계 제언**
현재의 **"단일 태스크 기반 동기식 수집 및 단일 구조체 조립" 방식은 물리적 한계(데이터 유실 및 블로킹)가 명확하여 수정이 불가피**합니다. 기존 4-Tier 아키텍처의 장점(SSOT 유지, 메모리 관리 단순화)을 해치지 않으면서 현실적 문제를 해결하기 위한 방안을 제안합니다.
**[권장 아키텍처 수정안: Asynchronous Decoupling & Fixed-Rate Emit]**
 1. **수집(Capture) 태스크의 비동기 링버퍼화 (도메인 분리):**
   * Core 0 내에서 Audio I2S 수집과 Vib SPI 수집을 동기식으로 묶지 말고, 각각 독립된 내부 링버퍼에 비동기적으로 쌓아야 합니다.
   * (대안) Core 0 내에 2개의 얇은 태스크(_audioCaptureTask, _vibCaptureTask)를 생성하여 I2S 블로킹과 SPI 폴링을 물리적으로 분리합니다.
 2. **DSP 엔진의 Overlap & Add 기법 적용:**
   * Audio(24ms)와 Vib(160ms) 버퍼가 각각의 FFT_SIZE만큼 찼을 때 독립적으로 processAudio와 processVibration을 구동시킵니다.
 3. **UnifiedFeatureSlot 방출(Emit) 주기의 고정 (Fixed Frame Rate):**
   * 시스템의 공통 Frame Rate(예: TELEMETRY_HZ_DEF = 10Hz, 100ms)를 설정합니다.
   * 100ms 주기가 도래할 때마다, **현재까지 가공된 가장 최신의 Audio 특징량과 Vib 특징량을 하나의 UnifiedFeatureSlot에 스냅샷(Snapshot) 형태로 합쳐서 방출**합니다 (Zero-Order Hold 방식).
   * 이 방식을 사용하면 단일 구조체의 이점(통신/저장 파이프라인의 단순화)을 유지하면서도, 센서 간 샘플링 속도 차이로 인한 I/O 병목을 완벽히 해결할 수 있습니다.
**4. Conclusion**
서로 다른 샘플링 레이트를 가진 멀티모달 센서를 하나의 제어 루프와 동기식 버퍼로 묶는 것은 실시간(RTOS) 시스템에서 하드웨어 버퍼 오버플로우를 유발하는 안티패턴(Anti-pattern)입니다. 따라서 **"데이터 수집 및 DSP 가공"은 철저히 도메인별로 분리(Asynchronous)**하되, **"특징량 융합 및 통신/저장"은 기존의 UnifiedFeatureSlot으로 통합(Synchronous Snapshot)**하는 하이브리드 패턴으로의 로직 교정이 필요합니다.

#### **1. Vibration: 포락선 처리 (Envelope Demodulation) 추가**
초기 베어링 결함(미세한 찍힘)은 기계적 고주파 공진을 유발하며, 이는 결함 주파수로 진폭 변조됩니다. 이를 해독하기 위해 FIR 필터 체인에 포락선 복조 로직을 추가해야 합니다.
 * **처리 위치:** processVibration 내부, 기존 HPF 통과 직후.
 * **처리 단계 (SIMD 최적화):**
   1. **Band-Pass Filtering:** 공진 대역(예: 2kHz~5kHz)만 통과하도록 IIR/FIR BPF 적용. (기존 HPF 재활용 가능)
   2. **Rectification (절대값화):** for 루프에서 std::abs()를 취해 신호를 양수로 뒤집음 (전파 정류).
   3. **Low-Pass Filtering:** 기존 LPF 인스턴스(_firInstLpfVib)를 통과시켜 포락선(Envelope)만 추출.
   4. **DC Removal & FFT:** 이 포락선 신호를 FFT 하면, 숨어있던 BPFO(외륜), BPFI(내륜) 주파수가 명확한 피크로 검출됩니다.
 * **구조체 반영:** DynamicConfig::ST_Vib_Sensor 내부에 bool use_envelope; 스위치를 추가하여 베어링 진단 모드일 때만 활성화.
#### **2. Vibration: 속도(Velocity) 변환을 위한 누설 적분기 (Leaky Integrator)**
ISO 10816 설비 진단 규격을 충족하려면 가속도(G)가 아닌 속도(mm/s) 기반의 RMS 판정이 필요합니다. 주파수 도메인 적분은 연산이 무거울 수 있으므로, 시간 도메인 누설 적분기를 추가합니다.
 * **처리 로직:**
   ```cpp
   // 가속도를 속도로 변환 (Integration)
   // v[n] = alpha * v[n-1] + a[n] * dt
   // alpha는 0.99~0.995 (저주파 드리프트, 즉 누설 방지용)
   float dt = 1.0f / p_vibSampleRate;
   float alpha = 0.99f;
   for (uint32_t j = 0; j < p_len; j++) {
       _velStateVib[i] = alpha * _velStateVib[i] + v_out[i][j] * dt * 9806.65f; // G -> mm/s^2 -> mm/s
       v_out[i][j] = _velStateVib[i];
   }
   
   ```
 * **적용:** 저주파수(언밸런스, 미스얼라인먼트) 대역 감시용 파이프라인으로 활용하며, 이 데이터를 기반으로 산출된 RMS를 UnifiedFeatureSlot에 vel_rms[3]으로 별도 저장하는 것을 권장합니다.
#### **3. Audio: 공간 위상차(IPD) 및 상호 상관(Cross-Correlation) 지표화**
에어 리크(Air Leak)나 특정 부품의 마찰음은 지향성을 가집니다. 단순 덧셈 빔포밍(L + R)은 잡음 제거에 유리하지만, 소음원의 위치 이동(위상 변화)을 추적하지 못합니다.
 * **처리 로직:** Stereo 모드일 때 L과 R 신호의 상호 상관도(Cross-Correlation) 또는 위상차(IPD)를 계산하여 통계 지표로 뽑아냅니다.
 * **특징량 추가:** T245_FeatExtra_243.cpp에서 L과 R의 내적(Dot Product)을 통해 공간 유사도(Coherence)를 구하고, 이를 p_slot.audio.coh (기존 슬롯 구조체에 예약된 공간 활용)에 할당합니다. 이 값의 급격한 변화는 새로운 진원의 이상 소음(예: 밸브 터짐)이 발생했음을 의미합니다.
#### **4. Shared: 오버랩(Overlap) 버퍼링 아키텍처**
현재 T290_FsmMgr_243.cpp 구조상 1024 샘플이 차면 즉시 FFT를 수행합니다. 윈도우링에 의한 양 끝단 신호 소실을 막기 위해 50% 오버랩 버퍼링 구조를 DSP단 앞단에 두어야 합니다.
 * **해결책:** CL_T2_SensorEngine에서 데이터를 넘겨줄 때, 이전 프레임의 하프(Half) 버퍼를 보존하여 현재 프레임의 앞부분과 합쳐서 넘기는 구조(Ring Buffer 기반의 슬라이딩 윈도우)로 개선해야 찰나의 기계적 충격음이 윈도우 사각지대에 빠지는 것을 방지할 수 있습니다.
**4. Conclusion**
현재의 DSP 파이프라인은 신호 처리를 위한 인프라(FIR, FFT, MFCC)가 SIMD 기반으로 매우 훌륭하게 구축되어 있습니다.
여기에 산업용 설비 진단의 도메인 지식(Domain Knowledge)을 결합하기 위해, **진동 도메인에는 베어링 분석용 '포락선 복조(Envelope)'와 '속도 적분(Velocity)'**을, **소음 도메인에는 공간 이상을 감지할 '위상차(IPD) 기반 Coherence'** 지표를 추가한다면, 단순 Edge AI를 넘어 완벽한 산업용 진단기기 아키텍처로 거듭날 것입니다.

#### **1. Vibration: 3축 공간 궤도(Orbit) 및 3D Vector 지표화**
 * **개념:** X축과 Y축(또는 Z축) 간의 거동 패턴을 수치화하여 언밸런스와 미스얼라인먼트를 분류.

 * **처리 내용:**
   1. **3D RMS (Total Energy):** RMS_{3D} = \sqrt{RMS_x^2 + RMS_y^2 + RMS_z^2}. 센서 부착 방향에 구애받지 않는 절대적인 진동 에너지 지표 산출.
   2. **XY Cross-Correlation (Orbit 형태 지표):** R_{xy} = \frac{\sum (X_i \cdot Y_i)}{\sqrt{\sum X_i^2 \cdot \sum Y_i^2}}.
   * 이 값이 0에 가까우면 원형 거동(언밸런스), 1 또는 -1에 가까우면 선형/타원형 거동(미스얼라인먼트, 기계적 풀림 방향성)으로 AI 모델이 명확히 분류할 수 있게 됩니다.

#### **3. Vibration: 기어박스 특화 진동 켑스트럼 (Vib-Cepstrum)**

 * **적용 위치:** T245_FeatExtra_243.cpp의 진동 FFT 처리 이후.
 * **처리 내용:**

   * 진동 파워 스펙트럼에 \log를 취하고 다시 IFFT(또는 DCT)를 수행. 특정 회전비(RPM) 간격으로 발생하는 기어 파손이나 롤링 베어링의 다중 결함을 단 하나의 지배적인 피크로 요약하여 AI 텐서에 공급합니다.
#### **4. Time-Domain 미시 지표: P2P & ZCR 추가**
 * **개념:** 연산 부하가 O(N)으로 매우 가볍지만, 기계적 결함 상태를 직관적으로 나타내는 시간 도메인 지표 추가.
 * **적용 위치:** FFT 수행 전 전처리된 버퍼(v_out) 순회 루프.
 * **처리 내용:**
   * **Vib P2P:** float p2p = max_val - min_val; 기계의 바닥 고정 볼트 풀림(Structural Looseness) 시 파형이 한쪽으로 튀는 현상을 즉각 포착합니다.
   * **Audio ZCR:** 인접 샘플 간 부호가 바뀌는 횟수를 카운트. 펌프의 캐비테이션(Cavitation)이나 베어링 윤활 부족으로 인한 '쇳소리(Hiss, Squeal)' 발생 시 ZCR 값이 평소 대비 수 배 이상 급증하는 것을 룰베이스 트리거 조건으로 활용할 수 있습니다.

 * **MECE Analysis:**
   * 비동기 노이즈 제거: **Spectral Whitening (스펙트럼 백색화)**
   * 동기 노이즈 부각: **TSA (Time-Synchronous Averaging, 시간 동기 평균화)**
 * **Reasoning:** 외부 타코미터(Tachometer) 없이 엣지 디바이스 단독으로 구동해야 하므로, 위상 동기화가 필요한 TSA 대신 **Spectral Whitening** 도입이 타당함. 이는 신호의 자가 회귀(Autoregressive) 성분을 제거하여 기어 맞물림 주파수(GMF) 등 지배적인 정상 상태 노이즈를 억제하고, 베어링 결함으로 인한 미세한 충격파(Impulse)만 날카롭게 돌출시킴.
 * **Next Step:** LPC(Linear Predictive Coding) 계수를 활용한 잔차(Residual) 신호 추출 로직 설계.
**[Thought #2] 자이로(Gyro) 특화 노이즈 제거: 비틀림 진동(Torsional Vibration) 추출**

 * **MECE Analysis:**
   * 정적 에러: 센서 초기 오프셋 (현재 runCalibration으로 해결됨).
   * 동적 에러: 온도/시간에 따른 저주파 드리프트.
 * **Reasoning:** 드리프트를 제거하지 않고 FFT를 수행하면 0Hz 근처의 DC 성분이 폭발하여 1X RPM 분석을 마비시킴. 매우 가파른 차단 특성을 가진 극저주파 차단 필터(Ultra-Low HPF) 또는 단순화된 **상보 필터(Complementary Filter) 기반의 DC 블로킹**이 필수적임.
 * **Next Step:** 자이로 도메인 전용 DC 블로커 및 적분 오차 상쇄 로직 설계.
**[Thought #3] 가속도-자이로 센서 퓨전 (Cross-Axis Fusion)을 통한 노이즈 상쇄**
 * **Thought:** 가속도계는 중력(Gravity) 벡터의 영향을 받으며, 설비 진동 시 센서 자체가 미세하게 회전하면 가속도 신호에 자이로 성분(회전 구심 가속도)이 노이즈로 섞임.
 * **MECE Analysis:**

   * 기계 진동/소음: 기본 구동 주파수(RPM)의 정수배(Harmonics) 피크, 그리고 베어링 파손에 의한 고주파(수 kHz 이상) 미세 충격파 발생.
 * **Reasoning:** MFCC의 Mel-Filterbank는 고주파 대역으로 갈수록 필터의 대역폭이 넓어짐. 따라서 고주파 영역에 나타나는 좁고 날카로운 결함 주파수(예: BPFO)가 뭉뚱그려져 하나의 특징으로 합쳐짐. AI가 결함을 '음색의 변화'로는 인지할 수 있으나, '정확히 어느 부품이 고장 났는지(Rule-base 매칭)'는 역추적(Explainability)할 수 없음.
 * **Next Step:** 센서의 물리적 특성(가속도, 자이로, 음압)에 맞는 도메인 특화 비-MFCC(Non-MFCC) 특징량 도출.
**[Thought #2] 가속도(Acceleration) 도메인 대체/보완 기법**
 * **Thought:** 고주파 충격파와 회전체 주파수를 어떻게 명확히 분리해 낼 것인가?
 * **Reasoning:**
   1. **스펙트럴 첨도 (Spectral Kurtosis, SK):** 시간 도메인의 첨도(Kurtosis)는 간헐적인 충격을 잘 잡지만, 노이즈가 심하면 무용지물임. 주파수 대역별로 첨도를 계산(SK)하면, "정확히 어느 주파수 대역에서 충격(베어링 타격)이 발생하고 있는지"를 AI 개입 없이 수학적으로 찾아낼 수 있음 (Fast Kurtogram의 기초).
   2. **무회전속도계 오더 분석 (Tacholess Order Tracking):** 설비의 RPM은 부하에 따라 미세하게 변동함. 주파수(Hz) 축을 RPM의 배수(Order) 축으로 변환하지 않으면, 스펙트럼 피크가 번짐(Smearing). 메인 피크(1X)를 FFT에서 찾아내어 이를 기준으로 스펙트럼의 X축을 리샘플링하는 기법이 필요.
 * **Potential Risk:** SK와 리샘플링은 연산량이 큼.
 * **자가 교정 (Revision):** 전체 주파수에 대한 SK 대신, 기존 Band Energy 8개 대역 내에서의 통계적 분산(Variance)과 피크 팩터(Peak Factor)를 추출하는 경량화 방식으로 대체 구현.
**[Thought #3] 자이로스코프(Gyroscope) 도메인 대체/보완 기법**
 * **Thought:** 자이로 센서는 각속도(Angular Velocity)를 측정함. 이를 설비 진단에 어떻게 직관적으로 쓸 것인가?
 * **Reasoning:**
   * **비틀림 진동 위상차 (Torsional Phase Modulation):** 기어 박스나 모터 커플링에 결함이 생기면, 회전축이 일정하게 돌지 못하고 미세하게 가감속을 반복함(비틀림 진동).
   * 자이로 Z축(회전축과 평행)의 FFT 스펙트럼에서 기본 주파수(1X RPM)의 주변에 발생하는 **사이드밴드(Sideband)** 에너지만을 적분하면, 순수한 기어 편심/커플링 마모도를 수치화할 수 있음. 가속도계로는 횡방향(Lateral) 진동과 섞여 구분하기 매우 어려운 지표임.
**[Thought #4] 소음(Audio) 도메인 대체/보완 기법**
 * **Thought:** MFCC의 Mel 스케일을 대체하면서 에어 리크(Air Leak)나 마찰음을 기계적으로 분류할 방법은?
 * **Reasoning:**
   1. **스펙트럴 평탄도 (Spectral Flatness / Wiener Entropy):**  스펙트럼 파워의 '기하 평균'을 '산술 평균'으로 나눈 값.
     * 정상 모터 소음 (Tonal Noise): 특정 주파수에 에너지가 집중되어 Flatness가 0에 수렴함.
     * 에어 리크 / 베어링 쇳소리 (Broadband Noise): 백색 잡음처럼 넓은 대역에 걸쳐 에너지가 퍼져 Flatness가 1에 가까워짐.
     * 에어 리크 감지에 있어 MFCC나 단순 RMS보다 압도적으로 직관적이고 연산이 가벼움.
   2. **스펙트럴 플럭스 (Spectral Flux):** 이전 프레임의 스펙트럼과 현재 프레임의 스펙트럼 간의 유클리드 거리(변화량). 금속이 부딪히는 '딱!' 하는 돌발 타격음(Transient)이 발생할 때 값이 폭발적으로 상승함.

**A. Audio 도메인: 스펙트럴 평탄도 (Spectral Flatness) 구현**
 * **목표:** 에어 리크(Air Leak) 및 마찰(Friction) 특화 감지 지표.
 * **코드 설계 (SIMD 친화적):**
```cpp
// T245_FeatExtra_243.cpp 내 추가
float CL_T2_FeatureExtractor::_computeSpectralFlatness(const float* p_power, uint32_t p_bins) {
    float v_sum = 0.0f;
    float v_logSum = 0.0f;
    const float MIN_POWER = 1e-10f; // log(0) 방어

    for (uint32_t i = 1; i < p_bins; i++) { // DC 성분(i=0) 제외
        float v_val = p_power[i] + MIN_POWER;
        v_sum += v_val;
        v_logSum += std::log(v_val);
    }
    
    float v_arithmeticMean = v_sum / (p_bins - 1);
    float v_geometricMean = std::exp(v_logSum / (p_bins - 1));
    
    return (v_arithmeticMean > MIN_POWER) ? (v_geometricMean / v_arithmeticMean) : 0.0f;
}
// 결과: UnifiedFeatureSlot의 audio.flatness 에 저장

```
**B. Vibration(가속도) 도메인: 하모닉 에너지 비(Harmonic Energy Ratio, HER)**
 * **목표:** 회전체(모터)의 언밸런스와 기계적 풀림을 구분.
 * **개념:** 1X RPM 주파수 에너지 대비, 그 정수배(2X, 3X, 4X...) 하모닉스 에너지의 비율.
 * **코드 설계:**
```cpp
// 1. FFT 스펙트럼에서 가장 에너지가 큰 피크의 인덱스(RPM 1X)를 찾음
uint32_t v_idx1X = _findFundamentalFreq(p_powerVib, p_bins);

// 2. 1X의 에너지 계산
float v_energy1X = p_powerVib[v_idx1X];

// 3. 2X, 3X 인덱스 주변의 에너지를 합산 (미세 RPM 변동을 고려해 인덱스 윈도우링)
float v_energyHarmonics = 0.0f;
for (int mult = 2; mult <= 4; mult++) {
    uint32_t v_targetIdx = v_idx1X * mult;
    if (v_targetIdx < p_bins) {
        // 주변 3개 Bin 에너지를 합산
        v_energyHarmonics += p_powerVib[v_targetIdx - 1] + p_powerVib[v_targetIdx] + p_powerVib[v_targetIdx + 1];
    }
}

// 4. HER 지표 산출
float v_her = v_energyHarmonics / (v_energy1X + 1e-6f);
// 결과: HER > 1.0 이면 심각한 기계적 풀림(Looseness)을 확정할 수 있음.

```
**C. Gyroscope 도메인: 비틀림 사이드밴드 편차 (Torsional Sideband Spread)**
 * **목표:** 커플링 불량 및 기어 편심의 즉각적 도출.
 * **개념:** 메인 회전 주파수 주변으로 새어나가는 에너지(사이드밴드)의 비율 측정.
 * **적용:** 자이로 Z축(회전축)의 파워 스펙트럼에 대해, 스펙트럴 센트로이드(무게중심) 주변의 분산(Variance) 값을 도출하여 특징량 구조체에 저장합니다. 분산 값이 넓어질수록 회전축의 거동이 불안정함을 나타냅니다.

**3. Final Solution: 도메인별 진단 특화 특징량 추출 기법 (MFCC 대체/보완)**
현재 시스템(T2_MSFM_240 v243)의 ESP32-S3 SIMD 환경에서 즉시 구현 및 확장이 가능한 현실적인 방법론을 제안합니다.
#### **1. 가속도(Acceleration) 센서 관점**
 * **기법 1: Spectral Kurtosis (SK) 및 Fast Kurtogram**
   * **개념:** 주파수 대역별로 신호의 '첨도(Kurtosis, 충격성)'를 계산하여, 충격파가 가장 강하게 발생하는 최적의 공진 대역(Optimal Frequency Band)을 자동으로 찾아내는 기법입니다.
   * **장점:** 설비의 베어링 스펙이나 구조적 공진 주파수를 몰라도, 수학적으로 가장 결함 확률이 높은 대역을 자율적으로 추적할 수 있습니다.
   * **적용:** FFT 후 주파수 Bin들을 일정한 대역(Band)으로 나누고, 각 대역 통과 신호의 시간 도메인 첨도를 구하여 텐서로 활용합니다.
 * **기법 2: Order Tracking (차수 분석)**
   * **개념:** 주파수(Hz)를 회전 속도(RPM) 단위인 '차수(Order)'로 정규화하는 기법입니다. (예: 60Hz 모터에서 1X는 60Hz, 2X는 120Hz).
   * **장점:** 가변속 설비(인버터 모터 등)에서 RPM이 변하면 주파수 피크가 번지는데(Smearing), 이를 Order 도메인으로 변환하면 결함 피크가 제자리에 선명하게 고정됩니다.
   * **적용:** 1X RPM에 해당하는 가장 강한 저주파 피크를 찾아내고, 이를 기준으로 스펙트럼의 인덱스를 리샘플링(Resampling)하여 특징 벡터를 만듭니다.
#### **2. 자이로(Gyroscope) 센서 관점**
 * **기법 1: IAS (Instantaneous Angular Speed) 분석**
   * **개념:** 자이로 센서의 출력값 자체가 '각속도'이므로, DC 성분(평균 RPM)을 제거하고 남은 AC 성분(각속도의 미세한 출렁임)만 추출하는 기법입니다.
   * **장점:** 유도 전동기의 로터 바(Rotor Bar) 파손, 기어의 이빨 깨짐, 모터 토크 리플(Torque Ripple) 등 '회전력의 불균형'을 진동 센서보다 훨씬 직관적으로 잡아냅니다.
   * **적용:** 자이로 Z축(회전축) 데이터에 LPF를 적용해 평균 회전 속도를 구하고, 원본에서 빼서 IAS Fluctuation RMS 및 피크 지표를 추출합니다.
 * **기법 2: Torsional Resonance Energy (비틀림 공진 에너지)**
   * **개념:** IAS 신호를 FFT하여 특정 주파수 대역의 에너지를 구합니다.
   * **장점:** 축(Shaft)이 굽었거나 커플링(Coupling)이 마모되었을 때 발생하는 특유의 비틀림 공진 대역을 감시할 수 있습니다.
#### **3. 오디오(Audio) 센서 관점**
 * **기법 1: GFCC (Gammatone Frequency Cepstral Coefficients)**
   * **개념:** MFCC의 Mel-Filter 대신, 인간의 달팽이관 막 특성을 더 정밀하게 모델링한 Gammatone Filterbank를 사용하는 켑스트럼 기법입니다.
   * **장점:** MFCC보다 백색 잡음(공장 배경 소음)에 대한 저항성(Robustness)이 월등히 높아, 시끄러운 환경에서의 기계음 분류 성능이 뛰어납니다.
   * **적용:** esp-dsp 환경에서 IIR 필터 체인을 병렬로 구성하여 Gammatone 필터를 근사 구현할 수 있습니다.
 * **기법 2: WPD (Wavelet Packet Decomposition) 기반 밴드 에너지**
   * **개념:** 신호를 고주파와 저주파 대역으로 계속 쪼개어 내려가는 트리(Tree) 구조의 필터링 기법입니다.
   * **장점:** FFT는 시간에 따른 주파수 변화를 볼 수 없지만, Wavelet은 짧은 시간에 발생하는 펄스(에어 리크의 팝핑 소리, 밸브 닫힘 타격음)를 완벽하게 분리해 냅니다.
   * **적용:** 심플한 Haar 또는 Daubechies 웨이블릿 필터를 적용하여, 특정 노드(주파수-시간 대역)의 에너지를 추출해 AI의 입력 피처로 사용합니다.
 * **기법 3: 음향심리학적 지표 (Sharpness / Roughness)**
   * **개념:** Sharpness(날카로움)는 고주파 에너지의 무게중심을 측정하며, Roughness(거칠기)는 15~300Hz로 진폭 변조되는 신호의 거슬림을 측정합니다.
   * **장점:** 베어링 윤활 부족 시 나타나는 쇳소리는 Sharpness를, 펌프의 캐비테이션(기포 파열) 현상은 Roughness 지표를 극단적으로 상승시킵니다.
**4. Conclusion: 수석 아키텍트 종합 제언**
현재 v243 아키텍처는 **MFCC(39D)라는 훌륭한 패턴 인식 텐서**를 보유하고 있습니다. 그러나 이는 고장 진단의 관점에서 볼 때 '모양(Pattern)'을 보는 눈이지, '물리적 충격(Physics)'을 정량화하는 지표는 아닙니다.
따라서 MFCC를 버리는 것이 아니라, UnifiedFeatureSlot 구조체에 다음의 물리 기반 특징량(Physics-informed Features)을 병합하는 **하이브리드 피처 엔지니어링(Hybrid Feature Engineering)**을 제안합니다.
 1. **Vib (가속도):** MFCC + **Spectral Kurtosis (최대 공진 대역의 첨도치)**
 2. **Vib (자이로):** MFCC + **IAS Fluctuation RMS (각속도 변동률)**
 3. **Audio (소음):** MFCC + **Sharpness Index (고주파 거칠기 지표)**
이 세 가지 지표만 추가되더라도, AI 모델은 "단순히 소리 모양이 달라졌다(MFCC 변화)"를 넘어서, "타격 충격이 커졌고(SK), 회전이 흔들리며(IAS), 금속 마찰음이 심해졌다(Sharpness)"는 물리적 근거를 바탕으로 기계 결함을 분류할 수 있게 됩니다.

**# 역할: 수석 아키텍트 (Sequential Thinking & MECE Specialist)**
**1. Context Alignment: 요구사항 요약**
 * **목적:** 산업용 회전 설비 진단(SMEA-100 프로젝트)의 신뢰성을 극한으로 끌어올리기 위한 가속도/자이로 진동 도메인의 추가적인 필터링 및 노이즈 제거 아키텍처 심층 검토.
 * **배경:** 앞서 제안한 포락선 복조(Envelope), 속도 변환, 자이로 DC Blocker, Spectral Whitening 만으로는 완벽히 걸러낼 수 없는 '비동기식 충격 잡음' 및 '초기 미세 결함'을 타겟팅.
 * **조건:** ESP32-S3의 연산 제약(OOM 방어, SIMD 활용)을 고려한 Edge AI 맞춤형 알고리즘.
**2. Sequential Reasoning Process**
**[Thought #1] 베어링 미세 충격음의 SNR(Signal-to-Noise Ratio) 극대화**
 * **Thought:** 초기 베어링 결함은 매우 짧고 미세한 충격파(Impulse)를 발생시키나, 무거운 모터의 정상 구동 진동(1X, 2X)과 노이즈에 완전히 묻힌다. FIR HPF나 Whitening 이후에도 남아있는 노이즈를 어떻게 억제할 것인가?
 * **MECE Analysis (충격파 강조 기법):**
   * 통계적 접근: Kurtosis (이미 사용 중)
   * 에너지 접근: RMS (순간적인 충격을 평균화시켜버리는 단점)
   * 비선형 접근: **TKEO (Teager-Kaiser Energy Operator)**
 * **Reasoning:** TKEO는 인접 샘플 간의 비선형 조합(x^2[n] - x[n-1]x[n+1])을 통해 신호의 '진폭'과 '주파수'가 동시에 급변하는 순간(충격파)의 에너지만 기하급수적으로 증폭시키고, 일정한 주파수를 가진 배경 노이즈(모터 정상 소음)는 상쇄시킨다. 연산량은 $O(N)$으로 매우 가벼워 MCU에 최적화되어 있다.
 * **Next Step:** 진동 DSP 파이프라인에 TKEO 적용 로직 추가.
**[Thought #2] 기어박스의 비주기적(비동기) 노이즈 억제**
 * **Thought:** 설비 주변을 지나는 지게차 진동, 이웃한 다른 펌프에서 전달되는 공진 등 타겟 설비의 회전 주기(RPM)와 무관한 '비동기 잡음(Asynchronous Noise)'은 어떻게 제거할 것인가?
 * **Reasoning:** 센서에 타코미터(Tachometer/엔코더)가 있다면 TSA(Time-Synchronous Averaging)를 쓰면 되지만, 현재 SMEA-100 아키텍처는 센서 단독(Sensorless) 구동이다. 따라서 자기상관함수(Autocorrelation)를 통해 기본 회전 주기(Fundamental Period)를 스스로 추정한 뒤, 이 주기에 맞춰 파형을 잘라 겹쳐서 평균을 내는 **Virtual TSA (Tacholess TSA)**가 필요하다. 이를 통해 회전 주기와 일치하는 기어 물림음(GMF)만 남고, 나머지 외부 노이즈는 0으로 수렴한다.
**[Thought #3] 기계의 고유 '지문(Signature)' 마스킹**
 * **Thought:** 오디오 도메인에서는 스펙트럼 감산법(Spectral Subtraction)을 쓴다. 진동에서도 설비마다 고유의 정상 상태 진동 스펙트럼이 있는데, 이를 노이즈로 간주하고 제거할 수 없는가?
 * **Reasoning:** 기계가 정상일 때의 파워 스펙트럼을 '베이스라인(Baseline)'으로 학습한 뒤, 실시간 스펙트럼에서 이를 빼버리는 **Baseline Spectral Masking** 기법이 매우 유효하다. 이를 적용하면 모터의 정상 1X, 2X 피크는 사라지고, 베어링이 마모되면서 '새로 생성된' 결함 주파수 피크만 솟아오르게 되어 룰베이스/AI 판정이 압도적으로 쉬워진다.
**3. Final Solution: 심층 진동 필터/노이즈 제거 보완 아키텍처**
현재 시스템(T240_DspEng_243.cpp)의 진동 처리 파이프라인에 다음 3가지 핵심 필터링 층을 추가할 것을 제안합니다.
#### **보완 1. 베어링/기어 충격 노이즈 제거 및 피크 증폭 (TKEO)**
 * **개념:** 배경 진동 노이즈를 누르고, 충격(Impact) 성분만 날카롭게 뽑아내는 비선형 에너지 필터입니다.
 * **적용 위치:** processVibration 내에서 HPF 통과 후, Envelope 처리 전단계.
 * **처리 로직 (C++ 구현):**
   ```cpp
   // T240_DspEng_243.cpp 내 내부 헬퍼로 추가
   void CL_T2_DspEngine::_applyTKEO(float* p_data, uint32_t p_len) {
       // 내부 스크래치 버퍼 필요 (SIMD alignas 16)
       alignas(16) float v_temp[T2_Def::Vib::Sensor::FFT_SIZE_MAX]; 
   
       v_temp[0] = p_data[0] * p_data[0];
       v_temp[p_len - 1] = p_data[p_len - 1] * p_data[p_len - 1];
   
       // y[n] = x[n]^2 - x[n-1]*x[n+1]
       for (uint32_t i = 1; i < p_len - 1; i++) {
           v_temp[i] = (p_data[i] * p_data[i]) - (p_data[i - 1] * p_data[i + 1]);
           // TKEO의 결과는 음수가 나올 수 없으나 수학적 안정성을 위해 abs 처리
           if (v_temp[i] < 0.0f) v_temp[i] = 0.0f;
       }
       memcpy(p_data, v_temp, p_len * sizeof(float));
   }
   
   ```
 * **기대 효과:** 이 필터를 거친 후 스펙트럼을 분석하면, 기존에 노이즈 플로어(Noise Floor)에 묻혀 보이지 않던 초기 베어링 결함(BPFO 등)이 거대한 피크로 돌출됩니다.
#### **보완 2. 외부 비동기 노이즈 소거 (Virtual TSA / Auto-correlation)**
 * **개념:** 타겟 모터의 회전과 무관한 주변 지게차, 인접 기계의 진동 등 외부 노이즈를 상쇄합니다.
 * **적용 위치:** processVibration 초입 (저주파 성분 포함).
 * **처리 로직:**
   1. esp-dsp의 dsps_corr_f32 (교차 상관 함수)를 원본 데이터 자기 자신에게 적용하여 자기상관(Autocorrelation) 배열을 얻습니다.
   2. 가장 큰 첫 번째 피크(0 Lag 제외)의 인덱스를 찾아 타겟 설비의 1회전 샘플 수(Fundamental Period)를 도출합니다.
   3. 원본 버퍼를 이 샘플 수 단위로 잘라 여러 개의 블록을 만든 뒤, 블록끼리 더해서 평균을 냅니다.
 * **기대 효과:** 주기적인 기계음만 선명하게 남고, 랜덤한 진동(외부 충격)은 수학적으로 0에 수렴하여 노이즈가 제거됩니다.
#### **보완 3. 기계 고유 정상 진동 마스킹 (Vibration Baseline Subtraction)**
 * **개념:** 진동 스펙트럼에도 오디오의 Spectral Subtraction과 유사한 '정상 상태 마스킹'을 적용합니다.
 * **적용 위치:** T245_FeatExtra_243.cpp의 진동 FFT 연산 직후.
 * **처리 내용:**
   * 초기 설치 시 며칠간 정상 구동 상태의 평균 파워 스펙트럼(_vibBaselineProfile[3])을 추출하여 SD카드 또는 Flash에 저장합니다.
   * 실시간 모니터링 시: S_{anomaly}(f) = \max(S_{current}(f) - S_{baseline}(f), \ 0)
   * 이후 이 S_{anomaly} 스펙트럼을 기반으로 Band Energy와 MFCC를 추출합니다.
 * **기대 효과:** 1X, 2X, GMF 등 매우 거대한 정상 피크들을 평탄하게 깎아버립니다. AI 모델(TinyML)은 '이미 존재하는 정상 진동'에 의한 혼란 없이, '새로 생긴 고장 주파수'의 미세한 변화에만 온전히 집중(Attention)할 수 있게 됩니다.
**4. Conclusion**
가속도/자이로 센서는 본질적으로 센서가 부착된 표면의 '모든 떨림'을 흡수합니다. 지금까지의 아키텍처가 FIR/IIR을 통해 '불필요한 주파수 구역을 잘라내는(Cut-off)' 방식이었다면,
추가 검토된 **TKEO(충격 증폭), Virtual TSA(주기성 외 노이즈 상쇄), Baseline Subtraction(정상 스펙트럼 제거)**은 진동 데이터 속에 숨은 **"결함의 물리학적 특성"**을 이용해 노이즈를 걸러내는 스마트 필터링입니다.
특히 연산량이 극도로 적은 **TKEO 필터의 도입**은 ESP32-S3 기반의 엣지 진단 시스템에서 베어링 결함 검출력을 비약적으로 끌어올릴 수 있는 가성비 최고의 '은탄환(Silver Bullet)'이 될 것입니다.
