T2_MSFM  시스템 코딩 규칙 및 원칙


본 문서는 T2_MSFM 펌웨어 개발에 적용된 코딩 표준과 아키텍처 원칙을 정의합니다.
Claude Code를 포함한 향후 개발에서 일관된 품질과 유지보수성을 보장하기 위한 참조 문서입니다.
---
- 문서 버전: 1.0
- 적용 대상: T240 펌웨어 v245 이상
- 유지보수자: 시스템 아키텍트
- 갱신 주기: 주요 버전 업데이트 시

1. 기본 철학 (Core Philosophy)

SSOT (Single Source of Truth): 모든 설정, 상수, 파라미터는 단 하나의 진실 공급원에서 파생되어야 한다.

· 하드코딩 금지: 모든 숫자 값은 의미 있는 이름의 상수로 정의.
· 매직 넘버 제로: 코드 내에 직접 숫자(예: 1024, 1600)가 나타나지 않도록 함.
· 계산식 정의: 종속된 값은 반드시 컴파일 타임 계산식( constexpr )으로 정의.

---

2. 코드 구조 원칙 (Architectural Principles)

2.1 도메인 완벽 격리 (Domain Isolation)

4개의 독립적인 도메인을 유지하며, 도메인 간 의존성을 최소화한다.

계층 설명 예시 네임스페이스
- Global : 시스템 인프라, 통신, 저장소, 공통 수학 상수 T2_Def::Global
- Accel : 가속도계 전용 파이프라인 T2_Def::Accel
- Gyro : 자이로스코프 전용 파이프라인 T2_Def::Gyro
- Audio : 소음(마이크) 전용 파이프라인 T2_Def::Audio
- AI : 텐서 조합 및 추론 T2_Def::AI

규칙:

· 각 도메인은 자신의 Sensor, FeatureLimit, Dsp, Trigger, Calib 하위 네임스페이스를 가진다.
· 도메인 간 상수 참조는 금지 (필요시 Global로 이동).
· 모든 설정 구조체(ST_*_Config)는 자신의 도메인에 속한다.

2.2 리소스 이중화 (Resource Duality)

정적 메모리 할당 안전성과 런타임 유연성을 동시에 확보한다.

· _MAX : 정적 할당 상한선 (OOM 방어). 배열 크기, 버퍼 크기.
· _DEF : 런타임 기본값 (실제 연산 루프 제어).

```cpp
inline constexpr uint16_t SEQUENCE_FRAMES_MAX   = 32;   // 정적 상한
inline constexpr uint16_t SEQUENCE_FRAMES_DEF   = 16;   // 런타임 기본
```

2.3 컴파일 타임 계산 (Compile-time Derived Values)

종속 파라미터는 하드코딩하지 않고 계산식으로 정의한다.

```cpp
// MFCC 차원 = 계수 * 컴포넌트 * 총 채널 수 (8)
inline constexpr uint32_t MFCC_DIM_MAX = MFCC_COEFFS_MAX * MFCC_COMPONENTS_MAX * CHANNELS_MAX;
inline constexpr uint32_t MFCC_DIM_DEF = MFCC_COEFFS_DEF * MFCC_COMPONENTS_DEF * CHANNELS_MAX;
```

3. 네이밍 규칙 (Naming Conventions)

3.1 파일 및 네임스페이스

종류 형식 예시
헤더 파일 T2xx_Name_yyy.hpp (xx=모듈 번호, yyy=버전) T210_Def_245.hpp
구현 파일 T2xx_Name_yyy.cpp T230_Sensor_245.cpp
네임스페이스 T2_Def::도메인::하위 T2_Def::Accel::Sensor

3.2 상수 (Constants)

· inline constexpr 사용.
· 접미사: _CONST (고정 하드웨어), _MAX (정적 상한), _DEF (기본값).
· 단위는 이름에 포함 (예: MS_PER_SEC_CONST).

```cpp
inline constexpr uint32_t SPI_FREQ_HZ_CONST  = 10000000;
inline constexpr uint8_t  BAND_MAX           = 16;
inline constexpr float    RMS_THRESH_DEF     = 0.5f;
```

3.3 타입 (Types)

· 구조체 : ST_ 접두사 , _t 접미사
· 열거형 클래스 (enum class) 사용, EM_접두사, _t 접미사

```cpp
struct ST_Global_System_t { ... };
enum class EM_SystemState_t : uint8_t {  ... };
```


3.4 변수 (Variables)

종류 접두사 예시
- 지역 변수 v_ v_sum, v_idx
- 함수 매개변수 p_ p_len, p_outBuf
- 클래스 멤버 (private) _ (언더스코어) _lock, _isInitialized
- 전역 변수 (최소화) g_ g_systemState

3.5 함수 (Functions)

· 카멜케이스 (낙타 표기법) 사용.
· 동사 + 명사 형태.

```cpp
bool init();
void setState(SystemState p_newState);
uint16_t readVibFifoBatch(...);
```

4. 메모리 관리 규칙 (Memory Management)

4.1 정적 할당 (Static Allocation)

· 모든 배열과 버퍼는 _MAX 상수로 크기 결정.
· VLA(Variable Length Array) 금지.

```cpp
float band_energy[AXIS_MAX][BAND_MAX];  // OK
float buffer[size];                     // size가 constexpr이 아니면 금지
```

4.2 동적 할당 (Dynamic Allocation)

· PSRAM 사용 시 heap_caps_aligned_alloc(16, size, MALLOC_CAP_SPIRAM).
· SRAM 필요 시 MALLOC_CAP_INTERNAL | MALLOC_CAP_8BIT.
· 반드시 할당 실패 검사 후 처리.

```cpp
float* buffer = (float*)heap_caps_aligned_alloc(16, size, MALLOC_CAP_SPIRAM);
if (!buffer) { ESP_LOGE(...); return false; }
```

4.3 정렬 (Alignment)

· 모든 연산 버퍼 및 SIMD 대상 배열: alignas(16).
· 구조체 전체 정렬: struct alignas(16) ST_Slot_Header { ... };

---

5. 동시성 및 태스크 관리 (Concurrency)

5.1 RTOS 태스크

· 태스크 스택 크기는 _MAX와 _DEF로 정의.
· 각 태스크에 고정 CPU 코어 할당 가능 (CORE_PROCESS_DEF).

```cpp
xTaskCreatePinnedToCore(_captureTask, "CapTask", 8192, this, 10, &_hCaptureTask, 0);
```

5.2 동기화 (Synchronization)

· 공유 자원 접근 시 SemaphoreHandle_t 뮤텍스 사용.
· 인터럽트 서비스 루틴(ISR)은 최소한의 작업만 수행 (플래그 설정).

5.3 큐 (Queues)

· 태스크 간 데이터 전달은 FreeRTOS 큐 사용.
· 큐 크기는 QUEUE_LEN_MAX로 상한 설정.

---

6. 오류 처리 및 디버깅 (Error Handling)

6.1 반환 값

· 성공/실패는 bool 반환.
· 초기화 함수: true(성공) / false(실패).

6.2 로깅

· ESP-IDF 로깅 매크로 사용: ESP_LOGI, ESP_LOGE, ESP_LOGW.
· 각 파일에 static const char* TAG 정의.

6.3 상태 텍스트

· 센서 엔진 등은 _statusText[32] 멤버로 사람이 읽을 수 있는 상태 유지.

---

7. DSP 및 SIMD 규칙 (DSP & SIMD)

7.1 윈도우 함수

· FFT 윈도우(Hann, Hamming, Blackman)는 dsps_wind_*_f32 사용.
· 진폭/에너지 보상 계수는 상수로 정의 (WINDOW_AMPLITUDE_CORR_HANN).

7.2 필터

· FIR 필터 계수는 _MAX 기반 배열.
· IIR/Notch 필터는 dsps_biquad_gen_*_f32로 계수 생성.
· 각 축/채널별 독립 필터 인스턴스 허용.

7.3 수학적 안전

· 0 나눗셈 방지: fmaxf(x, MATH_EPSILON_CONST).
· 로그/제곱근 0 방지: MATH_EPSILON_12_CONST.

---

8. 패킷 및 직렬화 (Packet & Serialization)

8.1 네트워크 패킷

· 구조체에 #pragma pack(push, 1) 적용.
· WsHeader는 8바이트 정렬로 시작.
· 이후 float 배열들은 4바이트 정렬이 보장되어 JavaScript Float32Array와 호환.

8.2 파일 저장

· 바이너리 파일 헤더(FileHeader)에 설정 JSON(config_dump[8192]) 포함 (MLOps).
· 원자적 쓰기: .tmp 파일에 저장 후 rename.

8.3 엔디안 (Endianness)

· 리틀 엔디안 가정 (ESP32). 네트워크 전송 시 변환하지 않음.

---

9. 설정 관리 (Configuration Management)

9.1 동적 설정 구조체

· 모든 설정은 DynamicConfig 하나로 통합.
· 중첩 구조체로 도메인별 설정 포함.

9.2 JSON 직렬화

· ArduinoJson 사용.
· _applyJson() 함수로 JSON → 구조체 변환.
· cfgSet(), cfgStr(), cfgSetArray() 헬퍼 사용.

9.3 지연 쓰기 (Lazy Write)

· 설정 변경 시 _isDirty = true.
· checkLazyWrite()에서 3초 후 저장 (플래시 수명 보호).

9.4 프리뷰/튜닝 모드

· updatePreview(): RAM만 변경 (플래시 미기록).
· commitSave(): 현재 RAM 설정을 플래시에 저장.
· revertCancel(): 마지막 저장 상태로 복원.

---

10. 특수 장치 규칙 (Device-Specific)

10.1 BMI270 센서

· SPI 모드 0, 10MHz, MSB 우선.
· 읽기 명령 시 MSB=1, 더미 바이트 1회 필요.
· FIFO 헤더(0x84: Accel, 0x88: Gyro) 기반 프레임 파싱.

10.2 I2S 마이크 (ICS43434)

· 32비트 데이터, 오른쪽 정렬.
· 스테레오 모드: L/R 인터리브.
· PCM_32BIT_SCALE_CONST로 정규화.

11. 코드 스타일 일관성 (Code Style)

11.1 중괄호

· 함수, 클래스, 구조체, 제어문: K&R 스타일 (여는 중괄호 같은 줄).
· 네임스페이스: 중괄호 새 줄 (들여쓰기 없음).

```cpp
namespace T2_Def {
    namespace Accel {
        inline constexpr int VALUE = 10;
    }
}
```

11.2 들여쓰기

· 4칸 공백 (탭 금지).

11.3 라인 길이

· 최대 120자 권장. 초과 시 줄바꿈.

11.4 주석

· 파일 상단: 기능, 버전, 변경 이력.
· 복잡한 알고리즘 앞에 설명 주석.
· 함수 한줄 앞에 라인 주석(함수의 목적,매개변수,반환값 등 )

---

12. 보안 및 안전 (Security & Safety)

· 워치독(Watchdog): 메인 루프에서 esp_task_wdt_reset() 주기적 호출.
· 스택 오버플로우 방지: 태스크 스택을 _MAX로 제한, uxTaskGetStackHighWaterMark()로 모니터링.
· 민감 정보: WiFi 비밀번호, MQTT 패스워드는 NVS에 암호화 없이 저장됨 (외부 보안 고려).

---

13. 버전 관리 (Versioning)

· 모든 헤더 파일 상단에 File: T2xx_Name_yyy.hpp 및 Summary 포함.
· Global::System::VERSION_STR에 버전 문자열 (예: "T240_v245_1").
· 바이너리 파일 헤더에 ver 필드 (uint16_t) 포함.

---

14. 예외 사항 (Exceptions)

· delay() 사용 금지 → vTaskDelay() 사용.
· Serial.print는 디버깅에만, 릴리스 빌드에서 제거 고려.
· new/delete 금지 → heap_caps_* 함수 사용.

- 프로젝트는 C++17(`-std=gnu++17`) 표준을 준수합니다.
