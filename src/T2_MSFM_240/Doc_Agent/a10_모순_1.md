1. 오디오 STA/LTA 샘플 개수 미수정

문제: 가속도/자이로는 고쳐졌으나 오디오는 여전히 RATE_DEF/1000 = 42 (STA), RATE_DEF/100 = 420 (LTA)로, 1ms/10ms 의도와 전혀 다른 42ms/420ms로 동작합니다.

수정 전 (T210_Def_245.hpp – Audio::FeatureLimit)

```cpp

inline constexpr uint32_t LTA_SAMPLES_DEF = Sensor::RATE_DEF / 100;    // 42000/100 = 420
```

수정 후 (가속도/자이로와 동일한 패턴 적용)

```cpp

inline constexpr uint32_t STA_DURATION_MS = 1;
inline constexpr uint32_t LTA_DURATION_MS = 10;
inline constexpr uint32_t STA_SAMPLES_DEF =
    (Sensor::RATE_DEF * STA_DURATION_MS + 500) / 1000;   // (42000*1+500)/1000 = 42.5 → 42
inline constexpr uint32_t LTA_SAMPLES_DEF =
    (Sensor::RATE_DEF * LTA_DURATION_MS + 500) / 1000;   // (42000*10+500)/1000 = 420.5 → 420
```

참고: 42kHz에서는 1ms=42샘플, 10ms=420샘플이므로 결과는 같지만, 물리적 의미가 명확해지고 다른 센서와 일관된 정의가 됩니다.

수정 후 (클래스 멤버 함수로 올바르게 정의)

```cpp
void CL_T2_FeatureExtractor::_computeMfcc(const float* p_power, float* p_outMfcc,
                                          uint8_t p_chIdx, bool isAudio) {
    if (p_chIdx >= 8) return;

    // IMU와 오디오의 bin 패딩값을 분기
    const uint16_t BINS_PADDED_IMU = (T2_Def::Accel::Sensor::FFT_SIZE_DEF / 2 + 1 + 3) & ~3; // 516
    const uint16_t binPadded = isAudio ? BINS_PADDED : BINS_PADDED_IMU;
    const uint16_t binMax = isAudio ? BINS_MAX : (T2_Def::Accel::Sensor::FFT_SIZE_DEF / 2 + 1);

    float v_melEnergies[MEL_BANDS_MAX] = {0};
    float* melBank = isAudio ? _melBankFlat : _melBankIMU;
    float* dctMat  = isAudio ? _dctMatrixFlat : _dctMatrixIMU;

    // Matrix Mult (Power * MelFilterbank)
    for (int k = 0; k < binPadded; k += T2_Def::Audio::FeatureLimit::MEL_CHUNK_ROWS_CONST) {
        int v_currRows = fminf(T2_Def::Audio::FeatureLimit::MEL_CHUNK_ROWS_CONST, binPadded - k);
        memcpy(_melScratchBuf, &melBank[k * MEL_PADDED], v_currRows * MEL_PADDED * sizeof(float));
        alignas(16) float v_tempOut[MEL_PADDED] = {0};
        dspm_mult_f32(&p_power[k], _melScratchBuf, v_tempOut, 1, v_currRows, MEL_PADDED);
        for (int m = 0; m < MEL_BANDS_MAX; m++) v_melEnergies[m] += v_tempOut[m];
    }

    for (int i = 0; i < MEL_BANDS_MAX; i++) {
        v_melEnergies[i] = log10f(fmaxf(v_melEnergies[i], T2_Def::Global::System::MATH_EPSILON_12_CONST));
    }

    alignas(16) float v_dctOut[MFCC_PADDED] = {0};
    memcpy(_dctScratchBuf, dctMat, MEL_PADDED * MFCC_PADDED * sizeof(float));
    dspm_mult_f32(v_melEnergies, _dctScratchBuf, v_dctOut, 1, MEL_PADDED, MFCC_PADDED);

    // 이하 히스토리 및 Delta 연산 동일 (생략) ...
}
```

필수 추가사항: 헤더 파일(T245_FeatExtra_245.hpp)의 _computeMfcc 선언에도 isAudio 인자를 추가하고, _melBankIMU, _dctMatrixIMU 멤버 변수를 선언해야 합니다. (현재 헤더에는 이미 선언되어 있음)

3.1 IMU Mel 뱅크 생성 (init 함수 내 추가)

```cpp
// 수정 후: init() 내, Audio Mel 뱅크 생성 후에 아래 코드를 추가

// --- IMU 전용 Mel Filterbank 생성 (나이퀴스트 800Hz) ---
constexpr uint16_t BINS_IMU_MAX = (T2_Def::Accel::Sensor::FFT_SIZE_DEF / 2) + 1;  // 513
constexpr uint16_t BINS_IMU_PADDED = (BINS_IMU_MAX + 3) & ~3;                     // 516

float v_lowFreq_imu = 10.0f;
float v_highFreq_imu = 800.0f;   // IMU 나이퀴스트
float v_lowMel_imu = 1127.0f * log1p(v_lowFreq_imu / 700.0f);
float v_highMel_imu = 1127.0f * log1p(v_highFreq_imu / 700.0f);

for (int m = 0; m < MEL_BANDS_MAX; m++) {
    float v_mCenter = v_lowMel_imu + (v_highMel_imu - v_lowMel_imu) * (m + 1) / (MEL_BANDS_MAX + 1);
    float v_mLeft   = v_lowMel_imu + (v_highMel_imu - v_lowMel_imu) * m / (MEL_BANDS_MAX + 1);
    float v_mRight  = v_lowMel_imu + (v_highMel_imu - v_lowMel_imu) * (m + 2) / (MEL_BANDS_MAX + 1);

    float v_hzC = 700.0f * (expm1(v_mCenter / 1127.0f));
    float v_hzL = 700.0f * (expm1(v_mLeft / 1127.0f));
    float v_hzR = 700.0f * (expm1(v_mRight / 1127.0f));

    for (int b = 0; b < BINS_IMU_MAX; b++) {
        float v_hzB = (float)b * (800.0f / (float)BINS_IMU_MAX);  // 800Hz 나이퀴스트
        float v_weight = 0.0f;
        if (v_hzB >= v_hzL && v_hzB <= v_hzC) v_weight = (v_hzB - v_hzL) / (v_hzC - v_hzL);
        else if (v_hzB > v_hzC && v_hzB <= v_hzR) v_weight = (v_hzR - v_hzB) / (v_hzR - v_hzC);
        _melBankIMU[b * MEL_PADDED + m] = v_weight;
    }
}

// IMU DCT Matrix (Audio DCT와 동일하므로 그냥 복사)
memcpy(_dctMatrixIMU, _dctMatrixFlat, MEL_PADDED * MFCC_PADDED * sizeof(float));
```

이 값은 reloadAudioMelFilter나 _computeMfcc에서 실제 생성할 Mel 대역 수로 사용되어야 합니다.(현재는 항상 MEL_BANDS_MAX(40)을 사용 중)

---

6. Accel/Gyro 비활성 축 MFCC 처리

extractAccel(), extractGyro()에서 축 마스크가 꺼져 있으면 MFCC 텐서 영역을 0으로 초기화합니다.

```cpp
// extractAccel() 내 for 루프 시작 부분에 추가
if (!(p_accCfg.axis_mask & (1 << i))) {
    // 비활성 축: MFCC 영역 0으로 설정
    const uint32_t singleChDim = T2_Def::AI::Tensor::MFCC_COEFFS_DEF * T2_Def::AI::Tensor::MFCC_COMPONENTS_DEF;
    float* v_finalOut = &p_slot.tensor.mfcc[i * singleChDim];
    memset(v_finalOut, 0, singleChDim * sizeof(float));
    memset(_mfccHistory[i], 0, sizeof(_mfccHistory[i]));
    memset(_deltaHistory[i], 0, sizeof(_deltaHistory[i]));
    _historyCount[i] = 0;
    continue;
}
```

7. 빔포밍 모드 전환 시 필터 상태 불일치

processAudio() 시작 부분에 모드 변경 감지 시 resetStates() 호출을 추가합니다.

```cpp
// processAudio() 맨 위에 추가
static bool s_prevBeamActive = false;
bool currentBeam = (v_useBeam); // v_useBeam은 기존 로직에서 계산되는 변수
if (currentBeam != s_prevBeamActive) {
    resetStates();
    s_prevBeamActive = currentBeam;
}
```

8. FIR 필터 차수 홀수 강제

reloadFilters()에서 FIR 필터 활성화 시 차수가 짝수이면 경고를 출력하고 홀수로 조정합니다.

```cpp
// reloadFilters() 내, 각 FIR 초기화 전에
if (v_dsp.hpf.en && (v_dsp.hpf.taps % 2 == 0)) {
    ESP_LOGW(TAG, "FIR HPF taps must be odd, adjusting %d -> %d", v_dsp.hpf.taps, v_dsp.hpf.taps+1);
    const_cast<uint16_t&>(v_dsp.hpf.taps) += 1;  // config가 const이므로 주의
}
```

또는 ST_FilterFIR_t를 수정할 수 있는 구조에서는 setter에서 강제하는 것이 더 안전합니다.

위 수정 사항들을 순차적으로 적용하면, 현재 코드에 잔존하는 수학적/물리적 모순이 모두 해소됩니다.
특히 2번(오디오 FFT 비트 리버스), 3번(IMU Mel 사용), 6번(비활성 축 MFCC) 은 즉시 수정해야 하는 치명적 결함입니다.


















각 모순별 해결방안

아래는 앞서 도출된 모든 모순에 대한 구체적인 해결 방안입니다. 각 항목은 현상 → 원인 → 해결 코드/설계 변경 순으로 제시합니다.

---

1. 수학적/물리적 모순 해결방안

1.1 Accel/Gyro STA/LTA 샘플 개수 정의 오류

현상:
STA_SAMPLES_DEF = 1600/1000 = 1, LTA_SAMPLES_DEF = 1600/100 = 16로 STA가 1샘플에 불과하여 STA/LTA가 무력화됨.

원인:
SSOT 상수 정의 시 ms 단위의 시구간을 샘플 수로 변환하는 곱셈(× rate/1000) 대신 나눗셈을 사용했으며, 정수 나눗셈으로 소수점 이하가 소실되었습니다. 설계 의도는 STA=1ms, LTA=10ms 지속시간을 확보하는 것입니다.

해결방안:
해당 상수를 (샘플레이트 * 시구간_ms) / 1000 형태로 재정의합니다. 동시에 uint32_t에 맞게 반올림 처리합니다.

```cpp
// Accel FeatureLimit
inline constexpr uint32_t STA_DURATION_MS = 1;   // 1ms
inline constexpr uint32_t LTA_DURATION_MS = 10;  // 10ms
inline constexpr uint32_t STA_SAMPLES_DEF =
    (Sensor::RATE_DEF * STA_DURATION_MS + 500) / 1000;   // (1600*1)/1000 = 1.6 → 2
inline constexpr uint32_t LTA_SAMPLES_DEF =
    (Sensor::RATE_DEF * LTA_DURATION_MS + 500) / 1000;   // (1600*10)/1000 = 16 → 16
```

Gyro 쪽도 동일하게 수정합니다.
영향: STA/LTA 이벤트 검출 로직이 정상 작동하며, T245_FeatExtra에서 계산 시 올바른 샘플 수를 사용하게 됩니다.

---

1.2 켑스트럼 계산에 Forward FFT 사용 (IFFT 미사용)

현상:
로그 파워 스펙트럼에 dsps_fft2r_fc32(정방향 FFT)를 적용하여 켑스트럼 계수가 왜곡됩니다.

원인:
켑스트럼은 로그 스펙트럼의 역 FFT(IFFT)로 정의되나, 코드에서 실수로 정방향 FFT를 호출하였습니다.

해결방안:
dsps_fft2r_fc32를 dsps_ifft2r_fc32로 변경하고, 스케일 보정(1/v_len)도 IFFT에 맞게 조정합니다. ESP-DSP 라이브러리에서 dsps_ifft2r_fc32는 내부적으로 켤레 대칭을 가정한 역변환을 수행하므로, 기존의 대칭 복사 로직은 유지합니다.

```cpp
// 기존:
dsps_fft2r_fc32(_cepsIfftWork, v_len);
dsps_bit_rev2r_fc32(_cepsIfftWork, v_len);
// 이후 스케일 보정:
for (uint32_t i = 0; i < v_len; i++) {
    _cepsIfftWork[i * 2] /= v_len;
    _cepsIfftWork[i * 2 + 1] /= -v_len;
}
```

수정 후:

```cpp
// IFFT 사용 (dsps_ifft2r_fc32 내부에서 1/N 스케일링이 이미 적용될 수 있으므로 확인 필요)
// 일반적으로 ESP-DSP의 ifft2r은 N으로 나누기를 수행합니다.
dsps_ifft2r_fc32(_cepsIfftWork, v_len);
dsps_bit_rev2r_fc32(_cepsIfftWork, v_len);  // 비트 리버스는 IFFT 후에도 필요
// 스케일 보정 제거 (라이브러리에서 처리된다면)
// 만약 라이브러리에서 스케일링을 안 하면 아래 주석 해제
// for (uint32_t i = 0; i < v_len; i++) {
//     _cepsIfftWork[i * 2] /= v_len;
//     _cepsIfftWork[i * 2 + 1] /= v_len;  // 허수부도 동일 스케일
// }
```

주의: ESP-DSP의 dsps_ifft2r_fc32 문서를 확인하여 스케일링 여부를 검증 후, 그에 맞게 처리합니다. 일반적으로 dsps_ifft2r_fc32는 입력을 1/N 스케일링하므로 추가 나눗셈은 필요하지 않습니다.

---

1.3 IMU(가속도/자이로)에 오디오용 Mel Filterbank 적용

현상:
진동 신호(가속도 1600Hz, 자이로 1600Hz)의 MFCC를 추출할 때, 오디오 샘플링레이트(42000Hz) 기반의 Mel 필터뱅크를 그대로 사용하여 물리적으로 무의미한 계수가 산출됩니다.

원인:
_computeMfcc() 함수가 전역적으로 하나의 Mel 뱅크/ DCT 행렬을 사용하며, 센서별 나이퀴스트 주파수 차이를 고려하지 않았습니다.

해결방안:
IMU 전용 Mel 필터뱅크와 DCT 행렬을 별도로 생성하고, extractAccel()/extractGyro()에서 해당 뱅크를 사용하도록 _computeMfcc()를 확장합니다.

구체적 변경:

1. CL_T2_FeatureExtractor 클래스에 다음 멤버 추가:
   ```cpp
   float* _melBankIMU;    // IMU용 Mel (BINS x MEL)
   float* _dctMatrixIMU;  // IMU용 DCT (MEL x MFCC)
   ```
2. init() 함수에서 IMU 전용 뱅크 할당 및 생성 (나이퀴스트 = IMU_RATE/2 = 800Hz):
   ```cpp
   _melBankIMU = (float*)heap_caps_aligned_alloc(16, BINS_PADDED_IMU * MEL_PADDED * sizeof(float), MALLOC_CAP_SPIRAM);
   _dctMatrixIMU = (float*)heap_caps_aligned_alloc(16, MEL_PADDED * MFCC_PADDED * sizeof(float), MALLOC_CAP_SPIRAM);
   // 필터 설계: v_lowFreq_imu = 10Hz, v_highFreq_imu = 800Hz (나이퀴스트)
   // 기존 Audio와 동일 알고리즘으로 주파수 범위만 변경하여 생성
   ```
   여기서 BINS_PADDED_IMU는 (Accel::Sensor::FFT_SIZE_DEF / 2 + 1 + 3) & ~3으로 정의합니다. (1024/2+1=513 → 516 패딩)
3. _computeMfcc() 시그니처에 bool isAudio 인자를 추가하거나, 오버로드합니다.
   ```cpp
   void _computeMfcc(const float* p_power, float* p_outMfcc, uint8_t p_chIdx, bool isAudio);
   ```
   내부에서 isAudio에 따라 _melBankFlat/_dctMatrixFlat 또는 _melBankIMU/_dctMatrixIMU를 선택하고, FFT 빈 개수(BINS_MAX vs BINS_IMU)도 분기합니다.
4. extractAccel()과 extractGyro()에서는 isAudio=false로 호출합니다.

이로써 진동 도메인의 MFCC는 0~800Hz 대역의 청각적 특성을 반영한 값으로 바뀌어, 실제 물리적 의미를 갖게 됩니다.

---

1.4 Mel Filterbank 생성 시 고정 샘플링레이트 사용

현상:
오디오 설정에서 샘플링레이트를 변경해도 init()은 42,000Hz 기준으로 Mel 필터뱅크를 생성합니다.

원인:
init()이 ST_Audio_Config_t를 인자로 받지 않아 실제 런타임 샘플링레이트를 알 수 없습니다.

해결방안:
init()의 시그니처를 변경하여 오디오 설정을 받도록 하거나, 별도의 configureAudioMelFilter(float sampleRate) 함수를 추가합니다.

```cpp
// 방안 A: init() 시점에 cfg 전달
bool init(const T2_Type::ST_Audio_Config_t& p_audioCfg); // 내부에서 _audioSampleRate 저장 및 Mel 뱅크 생성

// 방안 B: reload 시 업데이트 (선호)
void reloadAudioMelFilter(float sampleRate) {
    // 기존 Mel 뱅크를 새로 계산하여 _melBankFlat, _dctMatrixFlat 갱신
    const float v_nyquist = sampleRate / 2.0f;
    // Mel 뱅크 재생성...
}
```

T240_DspEng_245의 init()을 호출하는 상위 모듈에서 오디오 설정이 확정된 후 reloadAudioMelFilter를 호출하도록 합니다. 이렇게 하면 런타임에 샘플링레이트가 변경되어도 정합성이 유지됩니다.

2. 논리적 모순 해결방안

2.1 사용되지 않는 MEL_BANDS_DEF 상수

현상:
MEL_BANDS_DEF = 26이 선언만 되어 있고 전혀 사용되지 않음.

해결방안:
ST_Audio_Config_t에 mel_bands 필드를 추가하고, 기본값을 MEL_BANDS_DEF로 설정합니다. 런타임에 이 값을 읽어 _computeMfcc()에서 실제 사용할 Mel 대역 수를 결정합니다.

```cpp
// T215_Type_245.hpp의 ST_Audio_Config_t에 추가
uint8_t mel_bands;  // 기본값 = T2_Def::Audio::FeatureLimit::MEL_BANDS_DEF

// FeatExtra init() / reload 시 이 값을 사용하여 Mel 뱅크를 생성할 때 bands 수로 사용.
```

또한 init()에서 Mel 뱅크의 열 개수를 mel_bands에 맞춰 생성합니다. 이렇게 하면 주석대로 "런타임 연산 기본 개수" 역할을 수행하게 됩니다.

---

2.2 Accel/Gyro MFCC 추출 시 CHANNEL_MASK 무시

현상:
axis_mask로 비활성화된 축도 MFCC 추출을 시도하여, 이력 버퍼에 쓰레기 값이 남거나 0으로 초기화되지 않음.

해결방안:
extractAccel()과 extractGyro()에서 축이 마스크에 의해 비활성화된 경우, 해당 채널의 MFCC 텐서 영역을 명시적으로 0으로 초기화하고, 히스토리도 리셋합니다.

```cpp
// extractAccel() 내에서
if (!(p_accCfg.axis_mask & (1 << i))) {
    // 비활성 축: MFCC 영역 0으로
    float* v_finalOut = &p_slot.tensor.mfcc[i * singleChDim];
    memset(v_finalOut, 0, singleChDim * sizeof(float));
    // 히스토리 초기화
    memset(_mfccHistory[i], 0, sizeof(_mfccHistory[i]));
    memset(_deltaHistory[i], 0, sizeof(_deltaHistory[i]));
    _historyCount[i] = 0;
    continue;
}
```

이렇게 하면 AI 텐서에 유효하지 않은 값이 주입되는 것을 방지합니다.

2.3 오디오 빔포밍 경로의 필터 상태 공유 문제

현상:
빔포밍 활성 시 좌측 채널의 필터 상태만 사용하고, 결과를 우측에 복사하면서 상태 불일치 발생.

해결방안:
빔포밍 모드일 때는 모노 전용 필터 상태를 별도로 할당하거나, 처리 전에 좌/우 상태를 동기화합니다. 간단히는 빔포밍 모드 진입/해제 시 resetStates()를 호출하여 모든 이력을 초기화합니다.

또는 ST_AudioDspRuntime에 bool beamActive 플래그와 빔포밍 전용 상태 배열을 추가하는 방법도 있습니다. 그러나 메모리 제약을 고려할 때, 모드 전환 시 초기화가 더 현실적입니다.

```cpp
// processAudio 시작 부분에서 빔포밍 모드가 변경되었는지 감지
static bool s_prevBeam = false;
if (v_useBeam != s_prevBeam) {
    resetStates(); // 모든 필터 상태 초기화
    s_prevBeam = v_useBeam;
}
```

---

2.4 FIR 필터 차수 홀수 가정 미검증

현상:
_generateFirHpf()에서 p_coeffs[(p_taps - 1) / 2] += 1.0f;가 짝수 차수일 경우 대칭 중심이 틀어짐.

해결방안:

1. FIR 차수를 항상 홀수로 강제하는 유효성 검사를 reloadFilters()에 추가합니다.
2. 또는 짝수 차수일 경우 중심 보정을 생략하고, 전체 계수를 반전하고 다시 LPF로부터 계산하는 방식을 유지하되, p_taps가 짝수이면 중간 두 탭에 0.5씩 더하는 방식으로 변경합니다.

```cpp
// 안전한 홀수 강제
if (p_taps % 2 == 0) {
    ESP_LOGW(TAG, "FIR HPF taps must be odd, adjusting to %d", p_taps+1);
    p_taps++; // 또는 다음 홀수로
}
```

또한 T210_Def의 FIR_TAPS_DEF가 모두 홀수이므로, 런타임 재구성에서 짝수를 입력하지 못하도록 ST_FilterFIR_t의 setter에서 검증하거나 문서화합니다.

3. 경미한 잠재적 오류 처리

· readTemperatureSensor(): 반환 타입을 float로 변경하고, 호출 측에서 필요한 경우 캐스팅합니다. (안전성)
· _applyNoiseGate: std::abs → fabsf로 수정.
· FFT 크기 상수: Audio::Sensor::FFT_SIZE_DEF와 FFT_SIZE_MAX의 혼동을 줄이기 위해, FeatExtra에서 사용하는 오디오 버퍼는 FFT_SIZE_DEF 기준으로 할당(또는 p_len에 맞춤)하고, 주석을 명확히 합니다.

요약:
위 해결방안들은 v245 아키텍처의 SSOT 원칙을 유지하면서, 각 모순을 근본적으로 바로잡습니다. 특히 1.2(켑스트럼 IFFT), 1.3(IMU Mel), 1.1(STA/LTA)은 즉시 수정해야 할 치명적 결함이며, 나머지는 점진적 개선이 가능한 구조적 결함입니다.
