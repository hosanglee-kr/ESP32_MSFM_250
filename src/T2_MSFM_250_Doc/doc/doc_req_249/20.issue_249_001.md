다음은 각 도메인별로 발견된 물리적·수학적 모순점과 개선 방안을 표 없이 마크다운 형식으로 체계화한 분석 결과입니다.

T2_MSFM v248 v2 시스템 진단 파이프라인 도메인별 이슈 및 개선 방안

1. 가속도(Acceleration) 도메인

물리적 특성: 충격 진동, 베어링 결함, 기어 마모 등 고주파 대역의 구조계 응답을 포착합니다.

1.1 DSP 필터 이슈

· 메디안 필터의 충격파 소거 모순
  · 이슈: 윈도우 크기 3 이상의 메디안 필터가 베어링 결함의 핵심 징후인 피크성 충격(Impulse)을 노이즈로 오인하여 평탄화합니다. 이로 인해 결정적인 고장 특징이 소실됩니다.
  · 개선 방안: 충격파 진단 모드가 활성화될 경우, 초기 DSP 단계에서 메디안 필터를 강제로 바이패스(Bypass)하는 조건부 스위칭 로직을 구현합니다.
· 고차 FIR HPF의 과도한 연산 오버헤드
  · 이슈: DC 오프셋 제거를 위해 63 Taps의 FIR HPF를 사용하고 있습니다. 1600Hz ODR 환경에서 과도한 그룹 지연과 연산 오버헤드를 발생시켜 실시간 분석의 정합성을 저해합니다.
  · 개선 방안: 연산 윈도우가 매우 짧은 2차 바이쿼드(Biquad) IIR HPF(차단 주파수 5~10Hz)로 전면 대체하여 메모리 사용량과 그룹 지연을 최소화합니다.

1.2 통계 연산 이슈

· STA/LTA 윈도우의 통계적 무력화
  · 이슈: STA(단기평균) 시구간을 1ms, LTA(장기평균) 시구간을 10ms로 고정하여 실제 샘플 수가 각각 2개, 16개에 불과합니다. 이로 인해 파형 위상 변화에 따른 RMS 값의 출렁임이 극심해져 단기 급변 감지라는 본연의 기능을 상실합니다.
  · 개선 방안: ODR에 연동된 동적 윈도우 설계를 적용합니다. 가속도 1600Hz 기준으로 최소 STA는 32샘플(20ms), LTA는 320샘플(200ms) 이상으로 확정하여 통계적 신뢰성을 확보합니다.
· 왜도(Skewness) 및 첨도(Kurtosis) 신뢰성 저하
  · 이슈: 메디안 필터로 인해 피크 성분이 깎인 신호를 기반으로 왜도와 첨도를 계산하므로, 베어링 초기 결함의 핵심 지표인 첨도 값의 신뢰도가 급격히 저하됩니다.
  · 개선 방안: 위의 메디안 필터 바이패스와 연계하여, 원시 신호에 가까운 데이터로 첨도 및 왜도를 재계산하도록 파이프라인을 재구성합니다.

1.3 특징량(Feature) 이슈

· MFCC 적용의 부적합성 및 밴드에너지 필요성
  · 이슈: 인간의 청각 인지 특성(Mel-Scale)에 기반한 MFCC는 고주파 해상도를 의도적으로 압축합니다. 물리적 기계 진동에서는 고주파수 영역의 미세한 사이드밴드(Sideband) 성분이 매우 중요하므로, MFCC를 적용하면 결함 주파수의 정밀 라인이 손실되어 AI 모델의 설명 가능성이 파괴됩니다.
  · 개선 방안: MFCC 적용을 배제하고, 밴드에너지(Band Energy) 분석에 집중합니다. ISO 10816 등 표준에 근거하여 설비 회전수(RPM)의 배수 성분(1X, 2X, 3X) 및 베어링 결함 통과 주파수(BPFO, BPFI) 대역의 에너지를 16개 정밀 밴드로 분할하여 추적합니다.

2. 자이로(Gyroscope) 도메인

물리적 특성: 각속도(deg/s) 기반의 회전축 비틀림 진동, 편심 회전, 저주파 대역(주로 100Hz 미만)의 거동을 감시합니다.

2.1 DSP 필터 이슈

· 고주파수 대역 잡음 증폭 모순
  · 이슈: 신호의 물리적 유효 성분은 대부분 100Hz 미만에 집중되어 있으나, 가속도 도메인과의 대칭성 유지를 위해 ODR을 1600Hz로 강제하고 동일한 HPF 설정을 적용하고 있습니다. 이로 인해 고주파 영역(500~800Hz)의 센서 백색 열잡음(Thermal Noise)이 증폭되어 드리프트 추정 알고리즘의 수학적 수렴을 방해합니다.
  · 개선 방안: 자이로 도메인 전용 초기 DSP 단계에 100~150Hz 차단 주파수를 갖는 IIR LPF를 필수적으로 배치하여 하드웨어 레벨에서 고주파 노이즈를 감쇠시킵니다.

2.2 통계 연산 이슈

· 충격파 전용 통계치의 무분별한 적용
  · 이슈: 자이로 신호의 물리적 고장 특성은 급격한 충격파가 아닌 누적 변위나 저주파 변동(Drift)입니다. 그러나 현재 코드에서는 첨도, 왜도, 파고율(Crest Factor) 같은 충격파 전용 통계치를 가속도 코드에서 그대로 복사하여 계산하고 있습니다. 자이로 신호는 백색 잡음 성향 때문에 첨도가 항상 3 근처에 머물러 분별력(Sensitivity)이 없으며, 이는 불필요한 FPU 연산 자원만 낭비하는 모순입니다.
  · 개선 방안: 첨도, 왜도, 파고율 연산을 자이로 파이프라인에서 완전히 제외합니다. 그 자리에 각속도 적분 기반의 변위 추정 지표와 저주파 드리프트 변동량 지표를 신설하여 물리적 정합성을 확보합니다.

2.3 특징량(Feature) 이슈

· MFCC 및 고주파 밴드에너지의 무의미성
  · 이슈: MFCC의 로그 스케일 압축은 1kHz 이상에서 시작되므로, 유효 대역이 완전 선형 구간(0~200Hz)에 불과한 자이로 신호에 MFCC를 적용하는 것은 아무런 실익이 없습니다. 또한, 현재 설정된 최대 8개 밴드 중 저주파 1~2개 밴드를 제외한 고주파 밴드는 순수 노이즈 대역만 누적하게 됩니다.
  · 개선 방안: MFCC 연산을 완전히 배제하고 CPU 사이클 낭비를 제거합니다. 밴드에너지 분석은 저주파 고정 대역(0~50Hz) 1~2개 밴드로 제한하여 감시 효율을 극대화합니다.

3. 오디오(Audio) 도메인

물리적 특성: 공기 전파음 기반의 비접촉식 고주파 마찰음, 가스 누출, 전기적 아크 등 복잡한 무정형 스펙트럼과 공간 음향 정보를 포착합니다.

3.1 신호 처리 이슈

· 빔포밍(Beamforming)과 공간 지표 연산의 모순
  · 이슈: 빔포밍 연산으로 인위적 위상 합성과 노이즈 제거가 완료된 L채널 신호와, 아무런 가공을 거치지 않은 원본 R채널 신호를 이용하여 코히어런스(Coherence) 및 IPD(위상차) 같은 공간 지표를 계산하고 있습니다. 이는 한쪽 신호만 왜곡된 상태에서 상호 상관(Cross-correlation)을 구하는 것이므로, 공간 지표가 물리적 진실을 전혀 반영하지 못하는 심각한 모순입니다.
  · 개선 방안: 공간 지표 연산을 빔포밍 이전 단계로 분리합니다. processAudio 함수 진입 직후, 빔포밍 합성이 일어나기 전의 순수한 L/R 원시 데이터를 추출하여 코히어런스와 IPD를 먼저 계산하고, 빔포밍 필터링은 그 이후 AI 텐서 구축용으로만 독립 수행합니다.

3.2 통계 연산 이슈

· 켑스트럼(Cepstrum) 해상도 부족에 따른 주기성 오판
  · 이슈: 켑스트럼 피크 추출 시 42kHz 샘플링 레이트와 1024 FFT 크기를 사용하여 큐프런시(Quefrency) 해상도가 지나치게 촘촘합니다. 이로 인해 로그 스펙트럼에 FFT를 재수행할 때 하모닉 성분의 주기성을 물리적 주기에 정확히 매핑하지 못하고 오인 판정할 확률이 높아집니다.
  · 개선 방안: 켑스트럼 분석 전용 FFT 크기를 2048 또는 4096으로 확장할 수 있도록 설정을 변경하여 큐프런시 축의 물리적 해상도를 확보하고, 로컬 피크 마진의 오인식 문제를 방지합니다.

3.3 특징량(Feature) 이슈

· MFCC의 높은 필요성 및 활용 정당화
  · 이슈: 구조 전파 진동과 달리 공기 전파음은 비선형적 마찰과 다중 반사 등이 얽혀 복잡한 무정형 스펙트럼을 형성합니다. 이러한 기계 고유의 음향 패턴(Sound Signature)과 과도 현상(Transient Event)을 포착하기 위해서는 인간 음성 인식에서 검증된 MFCC의 특징량 압축 및 엔트로피 표현력이 매우 효과적입니다. 현재는 그 중요성에 비해 계산 구조의 정밀도가 부족합니다.
  · 개선 방안: 밴드에너지는 전체적인 노이즈 플로어 상승을 감시하는 보조 지표로 사용하고, MFCC를 음향 패턴 인식의 주요 특징량으로 적극 활용합니다.

4. 시스템 아키텍처 및 메모리 공통 이슈

전 도메인에 걸쳐 시스템의 실시간 안정성과 연산 무결성을 위협하는 공통 모순점입니다.

4.1 하드웨어 리소스 경합

· SPI 버스 공유로 인한 FIFO 오버플로우
  · 이슈: 센서 제어용 느린 연산 태스크가 _spiLock 뮤텍스를 점유하고 있는 동안, 최우선으로 처리되어야 할 고속 FIFO 인출 태스크가 블록(Block)됩니다. 이로 인해 BMI270 내부 FIFO 버퍼가 오버플로우되어 1600Hz 진동 데이터가 통째로 누락될 수 있습니다.
  · 개선 방안: 제어 레지스터 읽기/쓰기용 락과 FIFO 데이터 인출용 크리티컬 섹션(또는 바이너리 세마포어)을 완전히 분리합니다. 인터럽트 기반 인출부는 락 없이 즉시 내부 SRAM 더블 버퍼로 데이터를 옮기고, 메인 태스크는 이 더블 버퍼로부터 안전하게 데이터를 가져가도록 아키텍처를 변경합니다.
· 파일시스템 동기 쓰기로 인한 실시간성 붕괴
  · 이슈: 설정 저장 시 수백 밀리초(ms)가 소요되는 플래시 파일시스템(LittleFS) 동기 쓰기 작업이 메인 연산 루프와 동일한 락(_lock)을 공유하며 실행됩니다. 이로 인해 파일 I/O가 발생하는 순간마다 전체 실시간 진단 파이프라인이 일시 정지(Freeze)됩니다.
  · 개선 방안: 설정 저장을 우선순위가 가장 낮은 백그라운드 스토리지 전용 태스크로 완전히 비동기 분리합니다. 쓰기 요청은 큐(Queue)로 전달하고, 스토리지 태스크가 파일시스템 입출력을 전담하여 메인 루프의 실시간성을 보장합니다.

4.2 메모리 아키텍처 충돌

· 핵심 연산 버퍼의 PSRAM 밀려남 현상
  · 이슈: 지연 시간에 민감하지 않은 소형 JSON 파싱 데이터는 내부 고속 SRAM을 사용하는 반면, 캐시 미스 오버헤드가 치명적인 ST_AudioDspRuntime (255차 FIR 필터 상태 버퍼를 포함한 대규모 구조체)은 힙 부족 시 외부 PSRAM으로 할당될 가능성이 있습니다. 이는 고속 SIMD 연산 성능을 저하시키는 아키텍처적 모순입니다.
  · 개선 방안: ST_AudioDspRuntime, ST_AccelDspRuntime 등 매 샘플 고속 연산이 필요한 핵심 구조체는 MALLOC_CAP_INTERNAL 속성을 강제 지정하여 무조건 내부 고속 SRAM에만 할당합니다. 반대로, 대형 로그 파일 문자열 버퍼 등은 명시적으로 외부 PSRAM으로 할당하여 SRAM 공간을 확보합니다.
· SIMD 정렬(alignas(16))과 네트워크 팩킹(pack(1))의 충돌
  · 이슈: 16바이트 정렬이 필수인 진단 텐서 구조체(ST_Slot_Tensor_t)가 바이트 패딩이 제거된 통신 패킷 구조체(ST_PktTelemetry_t) 내부에 직접 포함되거나 참조될 경우, 컴파일러가 정렬 보장을 무력화시킵니다. 이 상태에서 SIMD 연산 함수(_computeMfcc 등)가 실행되면 비정렬 메모리 접근으로 인한 CPU 하드웨어 패닉 및 리부팅이 발생할 수 있습니다.
  · 개선 방안: 연산용 텐서 구조체와 통신용 팩킷 구조체 간의 멤버 직접 결합을 전면 금지합니다. 연산은 정렬이 보장된 독립 메모리 버퍼에서 완료하고, 통신 전송 직전에 전송부(CL_T2_CommManager)가 memcpy를 통해 값을 순차적으로 복사하는 직렬화 계층(Serialization Layer)을 추가합니다.

이상의 분석을 바탕으로 각 도메인의 물리적 정합성을 회복하고, 시스템의 실시간 처리 능력과 연산 신뢰성을 확보할 수 있습니다. 정리된 내용을 바탕으로 리팩토링을 진행하실 준비가 되시면 말씀해 주십시오.

제공해주신 심층 분석 자료를 바탕으로, 각 도메인(가속도, 자이로, 오디오)별로 발견된 이슈와 그에 대응하는 정밀 개선 방안을 정리했습니다.

1. 가속도(Acceleration) 도메인

핵심 물리량: 충격 진동, 베어링 결함, 기어 마모 (고주파수 대역)

구분 상세 이슈 개선 방안
DSP 필터 메디안 필터의 충격파 소거 모순  윈도우 크기 3 이상의 메디안 필터가 베어링 결함의 핵심 징후인 피크성 충격(Impulse)을 노이즈로 오인하여 평탄화시킵니다. 충격파 진단 모드 활성화 시, 초기 DSP 단계에서 메디안 필터를 강제로 바이패스(Bypass)하는 조건부 스위칭 로직을 적용합니다.
 고차 FIR HPF의 과도한 연산 오버헤드  DC 오프셋 제거를 위해 63 Taps의 FIR HPF를 사용하여 1600Hz ODR 환경에서 과도한 그룹 지연과 연산 오버헤드를 발생시킵니다. 63차 FIR 필터를 연산 윈도우가 짧은 2차 바이쿼드(Biquad) IIR HPF(차단 5~10Hz)로 대체하여 메모리와 그룹 지연을 최소화합니다.
통계 연산 STA/LTA 윈도우의 통계적 무력화  STA 1ms, LTA 10ms로 설정되어 실제 샘플 수가 2개, 16개에 불과하여 위상 변화에 따른 RMS 값의 극심한 출렁임이 발생, 단기 급변 감지 기능을 상실합니다. ODR에 연동된 동적 윈도우 설계를 적용합니다. (예: 1600Hz 기준 STA=32샘플(20ms), LTA=320샘플(200ms) 이상)으로 변경하여 최소 1주기 이상의 데이터를 확보합니다.
 왜도/첨도 신뢰성 저하  메디안 필터로 피크가 깎인 신호를 기반으로 왜도와 첨도를 계산하여 베어링 초기 결함 지표의 신뢰성이 급격히 저하됩니다. 메디안 필터 바이패스와 연계하여, 원시 신호에 가까운 데이터로 첨도 및 왜도를 계산하도록 파이프라인을 재구성합니다.
특징량 MFCC 적용의 부적합성  인간 청각 모델(Mel-Scale) 기반의 MFCC는 고주파 해상도를 압축하므로, 고주파 사이드밴드 성분이 중요한 기계 진동 분석에 적용 시 결함 주파수 라인이 손실됩니다. MFCC 적용을 배제하고, 밴드에너지(Band Energy) 기반 분석에 집중합니다. ISO 10816 등 표준에 따라 RPM 배수 및 결함 주파수 대역의 정밀 에너지를 추적하도록 합니다.

2. 자이로(Gyroscope) 도메인

핵심 물리량: 회전축 비틀림, 편심 회전, 저주파 대역 거동 (\text{deg/s})

구분 상세 이슈 개선 방안
DSP 필터 고주파수 대역 잡음 증폭 모순  유효 신호가 대부분 100Hz 미만에 집중되어 있으나, 가속도와의 대칭성을 위해 1600Hz ODR 및 동일한 HPF를 적용하여 고주파 백색 열잡음(Thermal Noise)이 증폭됩니다. 자이로 전용 초기 DSP 단계에 100~150Hz 차단 주파수의 IIR LPF를 필수 배치하여 센서 자체의 백색 잡음을 감쇠시킵니다.
통계 연산 충격파 전용 통계치의 무분별한 적용  첨도, 왜도, 파고율 등 충격파 진단 지표를 그대로 복사하여 사용하나, 자이로 신호는 백색 잡음 성향이 강해 지표의 분별력(Sensitivity)이 제로에 가깝고 연산 자원만 낭비합니다. 첨도, 왜도, 파고율 연산을 완전히 제외하고, 그 자리에 각속도 적분 기반의 변위 추정 지표와 저주파 드리프트 변동량 지표를 신설합니다.
특징량 MFCC 및 고주파 밴드에너지의 무의미성  MFCC의 로그 압축은 1kHz 이상에서 시작되므로 완전 선형 구간인 자이로 유효 대역(0~200Hz)에서는 실익이 없습니다. 또한 고주파 밴드에너지는 순수 노이즈 대역만 누적합니다. MFCC 연산을 완전히 배제하고, 밴드에너지 분석은 저주파 고정 대역(0~50Hz) 1~2개 밴드로 제한하여 감시합니다.

3. 오디오(Audio) 도메인

핵심 물리량: 비접촉식 고주파 마찰음, 가스 누출, 전기적 아크, 공간 음향 정보

구분 상세 이슈 개선 방안
신호 처리 빔포밍과 공간 지표 연산의 모순  빔포밍으로 가공된 L채널 신호와 원본 R채널 신호를 이용해 코히어런스(Coherence), IPD(위상차) 등 공간 지표를 계산합니다. 한쪽 신호만 인위적으로 위상이 합성되어 상호 상관 분석 결과가 물리적 진실을 반영하지 못하고 왜곡됩니다. 공간 지표 연산을 빔포밍 이전 단계로 분리하여, 순수한 L/R 원시 데이터로 코히어런스와 IPD를 먼저 계산합니다. 빔포밍 필터링은 그 이후 AI 텐서 빌드용으로만 독립 수행합니다.
통계 연산 켑스트럼 해상도 부족으로 인한 주기성 오판  42kHz 샘플링, 1024 FFT 환경에서 켑스트럼의 큐프런시(Quefrency) 해상도가 부족하여, 로그 스펙트럼 재변환 시 하모닉 성분의 주기성을 오인할 확률이 높습니다. 켑스트럼 분석용 FFT 크기를 2048 또는 4096으로 확장하여 큐프런시 축의 물리적 해상도를 확보하고, 로컬 피크 마진 오인식을 방지합니다.
특징량 MFCC의 높은 필요성 대비 부정확한 연산  공기 전파음의 복잡한 무정형 스펙트럼과 과도 현상 포착에 MFCC 특징량이 매우 유효합니다. 밴드에너지는 노이즈 플로어 감시용 보조 지표로만 사용하고, MFCC를 음향 패턴 인식의 주요 특징량으로 적극 활용합니다.

4. 시스템 아키텍처 및 메모리 공통 이슈 (추가 모순)

구분 상세 이슈 개선 방안
하드웨어 리소스 SPI 버스 공유로 인한 FIFO 오버플로우  센서 설정 변경 태스크가 SPI 락을 잡고 있는 동안 고우선순위 FIFO 인출 태스크가 블록되어, 1600Hz 데이터가 누락됩니다. 제어용 락과 데이터 인출용 크리티컬 섹션을 완전히 분리하고, 이중 버퍼 구조를 도입하여 FIFO 데이터 유실을 방지합니다.
 파일시스템 동기 쓰기로 인한 실시간성 붕괴  설정 저장 시 수백 ms의 파일 I/O가 메인 루프와 동기적으로 실행되어 전체 진단 파이프라인이 일시 정지(Freeze)됩니다. 파일 쓰기를 우선순위가 가장 낮은 백그라운드 스토리지 전용 태스크로 완전히 분리하여 비동기 처리합니다.
메모리 아키텍처 핵심 연산 버퍼의 PSRAM 밀려남 현상  캐시 미스 오버헤드가 치명적인 고속 FIR 필터 상태 버퍼가 외부 PSRAM에 할당될 가능성이 있는 반면, 상대적으로 덜 중요한 JSON 파싱 데이터는 내부 SRAM을 점유합니다. ST_AudioDspRuntime 등 핵심 연산 구조체는 강제로 내부 고속 SRAM에만 할당(MALLOC_CAP_INTERNAL)하고, 대형 로그 버퍼 등은 PSRAM으로 밀어내는 정책을 수립합니다.
 SIMD 정렬과 네트워크 팩킹의 충돌  alignas(16)으로 정렬된 연산 구조체가 #pragma pack(1)으로 선언된 통신 패킷 내부에 포함될 경우, 정렬 보장이 무력화되어 CPU 하드웨어 패닉을 유발할 수 있습니다. 연산용 텐서와 통신용 팩킷 구조체의 멤버 직접 결합을 전면 금지하고, 전송 직전에 값을 복사(memcpy)하는 직렬화 계층(Serialization Layer)을 추가합니다.

이상의 분석과 개선안을 통해 전체 진단 파이프라인의 물리적/수학적 정합성을 회복하고 실시간 성능과 안정성을 확보할 수 있습니다. 이 내용을 바탕으로 리팩토링을 진행하시려면 언제든지 말씀해 주십시오.

## 1. 도메인별 DSP 단계, Feature, 통계치 유효성 및 모순 점검

### 1.1 가속도(Acceleration) 파이프라인
가속도는 설비 진단에서 충격 진동, 베어링 결함, 기어 마모 등 구조적 결함을 포착하는 핵심 도메인입니다. 
물리적으로 가속도 신호는 고주파수 영역에서 질량과 강성에 따른 구조계 응답을 반영합니다.
 * **DSP 단계의 모순:** 현재 가속도 DSP 체인에는 메디안(Median) 필터와 FIR HPF, IIR HPF가 혼재되어 있습니다. 가속도 신호에서 발생하는 '피크성 충격(Impulse)'은 베어링 편심이나 균열을 알려주는 결정적인 고장 징후(Feature)입니다. 그러나 윈도우 크기 3 이상의 메디안 필터를 통과시키면 이러한 물리적 충격 스파이크가 노이즈로 오인되어 평탄화(소거)되는 치명적인 물리적 모순이 발생합니다. 또한, DC 오프셋을 소거하기 위해 고차 FIR HPF(63 Taps)를 적용하고 있는데, 가속도 ODR이 1600Hz인 상황에서 10Hz 차단 주파수를 갖는 FIR 필터는 과도한 그룹 지연(Group Delay)과 연산 오버헤드를 발생시켜 real-time 분석의 정합성을 깨뜨립니다.
 * **통계치 유효성 및 수학적 모순:** T210_Def_248.hpp에서 발생한 가장 큰 모순은 가속도의 런타임 샘플링 레이트가 1600Hz임에도 불구하고 STA(단기평균) 시구간을 1ms, LTA(장기평균) 시구간을 10ms로 고정한 점입니다. 수학적으로 계산하면 STA 샘플 수는 2개, LTA 샘플 수는 16개에 불과합니다. 1600Hz 신호에서 2개 샘플로 계산한 RMS는 물리적으로 파형의 위상(Phase) 변화에 따라 값이 극심하게 출렁이므로, 단기 급변 감지라는 본연의 수학적 목적을 완전히 상실하고 무력화됩니다. 최소한 주파수 1주기 이상을 커버하는 샘플 수가 확보되어야 정상적인 통계적 추정이 가능합니다. 또한 왜도(Skewness)와 첨도(Kurtosis) 연산 시, 메디안 필터로 인해 피크가 깎인 상태에서 계산되므로 베어링 결함의 초기 지표인 첨도 신뢰성이 급격히 저하됩니다.

### 1.2 자이로(Gyroscope/Angular Velocity) 파이프라인
자이로는 회전축의 비틀림 진동, 편심 회전, 대형 구조물의 흔들림 및 굽힘(Bending) 모드를 감시하는 도메인입니다. 자이로가 측정하는 물리량은 각속도(\text{deg/s})이며, 회전체의 저주파 대역 거동에 절대적으로 유효합니다.
 * **DSP 단계의 모순:** 자이로 센서(BMI270)의 ODR을 가속도와 1:1 결합하기 위해 1600Hz로 강제 잠금했습니다. 그러나 자이로 신호의 물리적 유효 성분은 대부분 100Hz 미만의 저주파 회전 성분에 집중됩니다. 이 상태에서 가속도와 동일한 1024 FFT 해상도 및 동일한 HPF 필터 설정을 적용하는 것은 대칭성 매칭을 위한 '논리적 오류'입니다. 특히 자이로의 고주파 영역(500Hz~800Hz)은 센서 자체의 백색 열잡음(Thermal Noise)이 지배적인 영역인데, 여기에 로우패스 필터를 켜지 않거나 가속도와 동일한 고역 통과 필터를 적용하면 백색 잡음이 증폭되어 드리프트 추정 알고리즘의 수학적 수렴을 방해합니다.
 * **통계치 유효성 및 수학적 모순:** 자이로의 물리적 고장 특성은 급격한 충격파보다는 시간에 따른 누적 회전각의 변위 및 저주파 변동(Drift)입니다. 그러나 현재 코드에서는 자이로 지표에 첨도(Kurtosis), 왜도(Skewness), 파고율(Crest Factor)과 같은 '충격파 전용 통계치'를 가속도 코드를 그대로 복사하여 계산하고 있습니다. 자이로 신호는 백색 잡음 성향이 강해 첨도가 항상 3 근처에서 미세하게 움직이므로 결함 진단 지표로서의 분별력(Sensitivity)이 제로에 가깝습니다. 이는 불필요한 FPU 연산 자원을 낭비하는 수학적 모순입니다. 자이로에는 회전 적분 오차나 주파수 도메인의 1X, 2X 회전 주파수 성분의 진폭 통계량이 훨씬 유효합니다.

### 1.3 오디오(Audio/Acoustic Emission) 파이프라인
오디오(공기 전파음)는 설비 내부의 미세 크랙 고주파 마찰음, 가스 누출, 전기적 아크(Arc) 현상 등 비접촉식 고속 현상을 진단하는 데 압도적인 유효성을 가집니다.
 * **DSP 단계의 모순:** 빔포밍(Beamforming) 연산 시 심각한 물리적 모순이 발견됩니다. 현재 코드는 좌우 마이크 신호를 더한 뒤 beam_gain을 곱해 L채널에 넣고, R채널에는 원본 오디오 신호를 그대로 우회시키고 있습니다. 물리적으로 빔포밍은 특정 지향각을 제외한 주변 공간 노이즈를 억제하기 위해 사용되는데, 이 가공된 L채널 신호와 원본 R채널 신호를 사용하여 다음 단계에서 코히어런스(Coherence, 결합도) 및 IPD(위상차) 공간 지표를 계산합니다. 한쪽은 인위적으로 위상이 합성되고 주변 노이즈가 제거된 신호이고, 다른 한쪽은 원본 노이즈가 그대로 살아있는 신호이기 때문에, 수학적으로 두 신호 간의 상호 상관(Cross-correlation)과 코히어런스는 물리적 진실을 반영하지 못하고 무조건 왜곡됩니다. 공간 지표를 연산할 목적이라면 빔포밍 필터링이 가해지기 전의 순수 독립 L/R 채널 신호를 사용해야만 수학적 모순이 발생하지 않습니다.
 * **통계치 유효성 및 수학적 모순:** 오디오 파이프라인의 켑스트럼(Cepstrum) 연산부에서 수학적 모순이 존재합니다. 켑스트럼 피크 추출 시 CEPS_NOISE_MARGIN_CONST = 5 빈(Bin)을 두고 로컬 피크를 찾는데, 42kHz 샘플링 레이트와 1024 FFT 크기 상황에서 켑스트럼의 큐프런시(Quefrency) 해상도는 오디오 파형의 주기성을 찾기에 너무 성급하게 촘촘합니다. 주파수 해상도가 낮은 상태에서 로그 스펙트럼에 다시 FFT를 수행하면, 켑스트럼 빈 간격이 물리적 주기에 매핑되지 않아 하모닉 성분(Harmonics)의 주기성을 오인 판정할 확률이 매우 높습니다.

## 2. 밴드에너지 및 MFCC 관점의 도메인별 필요성 및 차별화 분석
### 2.1 가속도 도메인
 * **밴드에너지(Band Energy)의 필요성:** **필수(Must-Have).** 물리적 설비 진단의 핵심 표준(ISO 10816 등)은 설비 회전수(RPM)의 배수 성분(1X, 2X, 3X) 및 베어링 결함 통과 주파수(BPFO, BPFI) 대역의 에너지를 직접 감시하는 것입니다. 따라서 가속도 진단에서 주파수 도메인을 16개 정밀 밴드로 쪼개어 에너지를 추적하는 것은 고장 위치를 특정하는 데 절대적으로 필요합니다.
 * **MFCC의 필요성:** **낮음(Optional/Avoid).** MFCC는 인간의 청각 인지 특성(Mel-Scale)을 반영하여 고주파수의 해상도를 의도적으로 압축하는 알고리즘입니다. 물리적 기계 진동은 주파수가 높아진다고 해서 그 분별 임계치가 무뎌지지 않으며, 오히려 고주파수 영역의 미세한 사이드밴드(Sideband) 성분이 중요합니다. 가속도에 MFCC를 적용하여 멜 밴드로 뭉개버리면 결함 주파수의 정밀 라인이 손실되므로 AI 모델의 물리적 설명 가능성(Explainability)이 파괴됩니다.
### 2.2 자이로 도메인
 * **밴드에너지(Band Energy)의 필요성:** **제한적 필요.** 회전축의 정적 편심이나 굽힘으로 인한 저주파 영역(예: 0~~50Hz)의 특정 고정 대역 에너지만 감시하면 충분합니다. 현재 설정된 8개 최대 밴드는 과하며, 하위 1~~2개 밴드 외 고주파 밴드는 순수 노이즈 대역이므로 에너지 누적이 의미가 없습니다.
 * **MFCC의 필요성:** **불필요(No-Use).** 자이로의 타겟 대역은 1600Hz ODR 기준에서도 극저주파 영역입니다. 멜 스케일 필터 뱅크는 1kHz 이상에서 로그 특성으로 압축이 시작되는데, 자이로 신호의 유효 대역은 압축이 일어나지도 않는 완전 선형 구간(0~200Hz)에만 존재합니다. 따라서 자이로 신호에 MFCC를 계산하는 것은 수학적 실익이 전혀 없는 무의미한 CPU 사이클 낭비입니다.
### 2.3 오디오 도메인
 * **밴드에너지(Band Energy)의 필요성:** **보조적 필요.** 공기 전파음의 경우 공진(Resonance)이나 환경 노이즈(배경음)가 특정 주파수 밴드에 넓게 분포하므로, 전체적인 노이즈 플로어 상승을 감시하는 매크로 지표로 유효합니다.
 * **MFCC의 필요성:** **매우 높음(Essential).** 구조 전파 진동과 달리 공기 전파음은 비선형적 마찰, 음향 방사, 다중 반사 등이 얽혀 복잡한 무정형 스펙트럼을 형성합니다. 기계의 고유 음향 패턴(Sound Signature)과 과도 현상(Transient Event)을 딥러닝/ML 연동 텐서로 표현하기에는 음성 인식 기술에서 검증된 MFCC의 특징량 압축 및 엔트로피 표현력이 최적의 효율을 발휘합니다.
## 3. 종합 개선 사항 도출
### [개념의 이해를 돕기 위한 전체 데이터 파이프라인의 개선 흐름도]
### 1단계: DSP 필터 체인의 도메인별 물리적 분리 및 최적화
 * **가속도 메디안 필터 조건부 스위칭:** 충격파 진단 모드가 활성화되어 있을 때는 초기 DSP단에서 메디안 필터를 강제로 바이패스(Bypass)하도록 제어 로직을 수정하여 결함 징후인 임펄스 성분을 원형 그대로 보존해야 합니다.
 * **자이로 저역 통과 필터(LPF) 마스터 적용:** 자이로 도메인 초기 DSP단에 100Hz 혹은 150Hz 차단 주파수를 가진 IIR LPF를 필수로 배치하여 고주파 백색 센서 노이즈를 하드웨어 레벨에 가깝게 감쇠시킨 후 통계량을 연산하도록 변경합니다.
 * **가속도 DC 제거 HPF를 IIR 구조로 변경:** 63차 FIR 필터 대신 계산 윈도우가 매우 짧고 선형 위상 왜곡이 진단에 영향을 주지 않는 2차 바이쿼드(Biquad) IIR HPF(차단 주파수 5Hz~10Hz)로 대체하여 메모리 절감 및 그룹 지연을 제로화합니다.
### 2단계: 통계치 연산의 수학적 정합성 리프레시
 * **ODR 연동형 동적 STA/LTA 윈도우 설계:** T210_Def_248.hpp에 하드코딩된 샘플 수 수식을 철저히 파괴하고, 도메인 ODR에 비례하여 최소 1주기 이상을 확보하도록 계산식을 강제합니다. 가속도(1600Hz) 기준 최소 STA는 32샘플(20ms), LTA는 320샘플(200ms) 이상으로 정립하여 위상 변화에 따른 RMS 흔들림 모순을 제거합니다.
 * **자이로 통계 지표의 전면 개정:** 의미 없는 첨도, 왜도, 파고율 연산을 자이로 파이프라인에서 완전히 제외하여 Core 1 연산 부하를 차단하고, 그 자리에 각속도 적분 기반의 변위 추정 지표 및 저주파 드리프트 추정 변동량 지표를 신설합니다.
### 3단계: 오디오 공간 지표 연산 및 켑스트럼 모순 해결
 * **공간 지표 연산용 독립 라인 분리:** processAudio 함수 내에서 빔포밍 합성이 일어나기 직전의 순수한 L/R 원시 데이터를 추출하여 코히어런스(coh)와 ipd 지표를 먼저 계산하도록 연산 순서를 전면 수정합니다. 빔포밍 필터링은 해당 공간 지표 연산이 완결된 후, 독립적으로 AI 텐서 빌드용(L채널)으로만 가공 처리되어야 수학적 모순이 발생하지 않습니다.
 * **오디오 켑스트럼 Resolution 확장:** 켑스트럼 분석용 FFT 크기를 기본 1024에서 2048 혹은 4096으로 확장할 수 있도록 설정을 변경하여 큐프런시 축의 물리적 해상도를 확보하고, 로컬 피크 마진의 오인 인식을 방지합니다.
### 4단계: 밴드에너지 Pre-mapping 기법 도입을 통한 성능 극대화
 * 매번 주파수 대역 연산 시 런타임 루프 내부에서 고정 소수점/부동 소수점 Hz 변환 및 대소 비교 분기문(\le, \ge)을 수행하는 현재의 구조를 전면 폐기합니다.
 * 시스템 부팅 및 설정 변경(reloadFilters) 시점에, 각 밴드의 주파수 범위에 대응하는 FFT 빈의 시작 인덱스(Start Bin Index)와 끝 인덱스(End Bin Index)를 컴파일 타임 상수를 활용해 미리 정수 배열로 계산해 두는 **'주파수 빈 인덱스 사전 매핑(Bin Index Pre-mapping)'** 기법으로 전환합니다. 이로 인해 특징량 추출 엔진은 주파수 변환 연산과 분기문 없이 즉시 메모리 루프(for(int b = start_bin; b <= end_bin; b++))만 돌며 에너지를 누적할 수 있게 되어, 추출단 연산 속도가 최소 3배 이상 대폭 향상됩니다.

동일하게 표를 사용하지 않고, 기계 진단 파이프라인의 신뢰성을 저해하는 치명적인 모순점들과 이에 대한 명확한 기술적 개선 사항을 상세히 설명해 드립니다.
## 1. 하드웨어 및 태스크 구조적 모순 점검
### 멀티코어 SPI 버스 공유 및 인터럽트 레이턴시 모순
 * **현상 및 모순점:** 현재 CL_T2_SensorEngine은 내부 가속도/자이로 수집을 위해 _spiLock이라는 뮤텍스(Mutex)를 사용하여 SPI 통신을 보호하고 있습니다. 이 엔진은 메인 루프나 캘리브레이션 태스크 등 여러 곳에서 접근합니다. 그러나 동시에, BMI270 관성 센서의 FIFO 워터마크 인터럽트 수신 핀(PIN_INT1_WATERMARK_CONST)은 높은 우선순위(Priority 12)를 가진 센서 데이터 수집 태스크(Core 0 바인딩)와 연결되어 주기적으로 FIFO 버스트 리드를 수행하도록 설계되어 있습니다.
 * **물리적 모순:** 인터럽트 서비스 루틴(ISR) 또는 초고속 수집 태스크가 수행되는 시점에, 다른 태스크(예: runAccelCalibration 또는 일반 제어부)가 BMI270 레지스터를 읽기 위해 _spiLock을 획득하고 있다면, 최우선으로 처리되어야 할 FIFO 인출 태스크가 뮤텍스 대기 상태(portMAX_DELAY)로 블록(Block)됩니다. 1600Hz ODR 상황에서 FIFO 버퍼가 인출되지 못하고 대기하는 시간이 길어지면, BMI270 내부 FIFO 오버플로우(Overflow)가 발생하여 진동 데이터가 통째로 누락(Drop)되는 하드웨어 리소스 관리적 모순이 발생합니다.
### 실시간 데이터 수집과 느린 파일시스템(LittleFS)의 동기적 결합 모순
 * **현상 및 모순점:** CL_T2_ConfigManager::save() 함수는 현재 플래시 메모리의 수명을 보호하고 파일 손상을 막기 위해 임시 파일에 먼저 쓰고 복사하는 원자적 쓰기(Atomic Write) 방식을 취하고 있습니다. 문제는 웹 UI나 외부 명령을 통해 런타임 갱신(updateFromJson)이 발생하면, 지연 쓰기 스케줄러(checkLazyWrite)가 동작하여 메인 연산 컨텍스트와 동일한 락(_lock)을 잡고 파일 시스템에 접근한다는 점입니다.
 * **수학적·시스템적 모순:** ESP32 내부 플래시 파일 시스템(LittleFS)의 물리적 쓰기 속도는 섹터 삭제(Sector Erase) 레이턴시로 인해 수십에서 수백 밀리초(ms)까지 튑니다. 메인 신호처리 파이프라인과 의사결정 엔진이 동일한 코어에서 가동 중이거나 동기적 구조체 참조 락을 공유하고 있다면, 플래시 파일 쓰기가 수행되는 수백 ms 동안 전체 센서 수집 및 DSP 가공 루프가 정지(Freeze)됩니다. 실시간(Real-Time) Edge AI 장비를 표방하면서 내부 파일 입출력(I/O) 오버헤드를 메인 동기식 락과 결합해 둔 구조는 시스템 논리적 모순입니다.
## 2. 메모리 아키텍처 및 정렬(Alignment) 모순 점검
### PSRAM 할당 거부 정책과 고차 FIR 필터 메모리의 SRAM 경합 모순
 * **현상 및 모순점:** T220_CfgMgr_248.cpp 내부 주석을 보면, "10KB 미만 JSON을 PSRAM에 담으면 캐시 미스 오버헤드가 발생하므로 기본 내부 힙(SRAM)을 사용한다"며 g_psramAlloc을 제거했습니다. 그러나 정작 T240_DspEng_248.cpp 내부를 보면, 마이크 센서용 오디오 DSP 런타임 구조체(ST_AudioDspRuntime) 할당 시 1차적으로 내부 SRAM 지정을 시도하고 실패할 경우에만 보조적으로 PSRAM(MALLOC_CAP_SPIRAM)을 할당하도록 코딩되어 있습니다.
 * **구조적 모순:** ST_AudioDspRuntime 구조체 내부에는 FIR_TAPS_MAX = 255 차수의 오디오 필터 계수 및 채널별 상태 버퍼(fir_state_hpf, fir_state_lpf)가 대규모 2차원 배열로 내장되어 있습니다. 이 구조체의 크기는 수십 킬로바이트(KB)에 달합니다. 지연 시간이 중요한 소형 JSON 파싱 데이터는 SRAM을 소모하도록 방치하면서, 정작 매 샘플마다 고속 SIMD 연산(dsps_fir_f32_aes3)을 수행해야 하는 핵심 FIR 필터 상태 버퍼들을 힙 마진 부족 시 캐시 미스 오버헤드가 극심한 외부 PSRAM 영역으로 밀려나도록 설계한 것은 연산 성능 극대화 관점과 완전히 정면 배치되는 아키텍처적 모순입니다.
### 구조체 메모리 정렬(alignas(16))과 1바이트 네트워크 팩킹(pack(1))의 충돌 모순
 * **현상 및 모순점:** T215_Type_248.hpp를 보면, 고속 SIMD 연산 정합성을 보장하기 위해 ST_Raw_Accel_t, ST_Slot_Tensor_t 등의 진단 데이터 구조체에는 alignas(16) 속성이 강력하게 붙어 있습니다. 하지만 네트워크 전송 및 웹소켓 데이터 파싱 최적화를 위한 플랫 규격 패킷 구조체인 ST_PktTelemetry_t 등은 바이트 패딩을 완전히 제거하는 #pragma pack(push, 1) 지시어로 강제 묶여 있습니다.
 * **수학적·컴파일러적 모순:** C++ 표준과 텐서플로우 라이브러리 연산단에서 alignas(16)는 데이터 주소의 하위 4비트가 무조건 0x0으로 끝남을 보장하여 FPU의 128비트 벡터 레지스터 전송 명령을 안전하게 수행하도록 유도합니다. 그러나 이 구조체들을 바이트 단위 팩킹 구조체 내부의 멤버로 밀어 넣거나, 팩킹 구조체 내부에서 대규모 배열(float mfcc[MFCC_DIM_MAX]) 형태로 참조할 경우 컴파일러는 pack(1)의 제약조건을 맞추기 위해 정렬 보장 속성을 무력화(Ignore)시킵니다. 결과적으로, 실시간 연산부(_computeMfcc 등)가 팩킹된 패킷 메모리 버퍼의 주소를 직접 참조하여 내부 SIMD 매크로 함수를 실행하는 순간, 정렬되지 않은 메모리 접근(Unaligned Memory Access)으로 인한 하드웨어 CPU 패닉 및 리부팅 모순이 발생할 수 있습니다.
## 3. 추가 진단 모순에 대한 핵심 개선 사항 도출
### 1. SPI 통신 락 분할 및 이중 버퍼 구조 채택
 * **개선안:** 런타임 제어 레지스터를 읽고 쓰는 느린 연산용 _spiLock 뮤텍스와, 고속 고주파 FIFO 데이터를 인출하는 태스크용 인터럽트 전용 크리티컬 섹션(또는 바이너리 세마포어)을 완전히 분리합니다. FIFO 데이터 인출부는 락 경합 없이 무조건 즉시 실행되어 하드웨어 FIFO 데이터를 내부 SRAM 더블 버퍼로 인출하고, 메인 프로세싱 태스크가 이 더블 버퍼로부터 데이터를 안전하게 팝(Pop)해가도록 아키텍처를 변경하여 FIFO 오버플로우 모순을 해결합니다.
### 2. 비동기식 지연 쓰기(Async Lazy Write) 전용 태스크 분리
 * **개선안:** CL_T2_ConfigManager 내부의 save() 및 checkLazyWrite() 함수가 메인 신호처리 태스크 컨텍스트 내에서 실행되지 않도록 구조를 개정합니다. 파일 쓰기 요청 발생 시 설정을 큐(Queue) 형식으로 밀어 넣고, 우선순위가 가장 낮게 설정된 백그라운드 스토리지 전용 태스크(STORAGE_PRIO_DEF = 2)가 큐를 모니터링하다가 파일시스템 입출력을 전담하여 수행하도록 수정함으로써, 실시간 진단 파이프라인의 일시 정지(Freeze) 현상을 완벽히 차단합니다.
### 3. 고속 연산 데이터의 SRAM 상주 보장 정책 정립
 * **개선안:** MALLOC_CAP_INTERNAL을 강제 지정하여 ST_AudioDspRuntime, ST_AccelDspRuntime, ST_GyroDspRuntime 구조체 전체가 무조건 내부 고속 SRAM에만 상주하도록 메모리 할당 정책을 잠금(Lock) 처리합니다. 대신 캐시 미스가 발생해도 제어 성능에 영향이 없는 웹 UI 응답용 대형 로그 파일 문자열 버퍼나 정적 JSON 텍스트 파싱 결과 버퍼들을 명시적으로 외부 PSRAM(MALLOC_CAP_SPIRAM)으로 밀어내어 내부 SRAM의 여유 공간을 확보합니다.
### 4. 네트워크 패킷 평탄화 직렬화 분리 (Serialization Layer 추가)
 * **개선안:** 연산용 텐서 구조체(ST_Slot_Tensor_t 등)와 통신용 팩킹 패킷 구조체(ST_PktTelemetry_t) 간의 멤버 직접 임베딩 결합을 전면 금지합니다. 연산은 완벽히 16바이트 정렬이 보장된 독립 내부 SRAM 버퍼에서 수행하여 벡터 가속 성능을 온전히 취하고, 통신 전송 직전 시점에 전송부(CL_T2_CommManager)가 값을 패킷 구조체 메모리에 순차적으로 복사(memcpy)하여 정렬 손실로 인한 하드웨어 덤프 크래시 모순을 원천 봉쇄합니다.
