## 1. 개요 및 분석 프레임워크

1. **이슈 검토 결과 (Issue Validation):** 현 소스 코드(V7 기준)와 설계 명세서 대비 정합성 검증 및 리스크 분석
2. **개선 방안 (Proposed Resolution):** 문제 해결을 위한 구체적인 아키텍처 및 구현 기법
3. **사용자 결정 필요 사항 (User Decision Needed):** 메모리, 정밀도, 응답성 간 트레이드오프 관계로 인해 개발자가 직접 정책을 결정해야 하는 항목
4. **구현 난이도 및 불가 여부 (Difficulty & Feasibility):** ESP32-S3 하드웨어 리소스 한계 또는 소프트웨어 스택 복잡도에 따른 구현 난이도 분류 (매우 높음 / 높음 / 보통 / 낮음)

## 2. 항목별 체계적 분석 및 개선 방안

### [1] GDMA 전송 및 CPU L1 캐시 일관성 (Cache Coherency) 제어 로직
* **이슈 여부:** **이슈 (치명적)**
  * GDMA가 PSRAM이나 외부 버퍼와 데이터 교환 시 CPU L1 캐시를 거치지 않고 직접 메모리(DMA)에 쓰기 때문에 캐시 미스 또는 데이터 오염 발생 가능. `esp_cache_msync()`를 통한 명시적 무효화/플러시 호출이 누락됨.
* **개선 방안:**
  * DMA 전송 시작 전: 수신 버퍼 영역에 대해 `esp_cache_msync(buf, size, ESP_CACHE_MSYNC_FLAG_DIRTY)`를 호출하여 CPU 캐시 내용을 메모리로 Write-back.
  * DMA 전송 종료 후: `esp_cache_msync(buf, size, ESP_CACHE_MSYNC_FLAG_INVALIDATE)`를 호출하여 CPU 캐시를 무효화함으로써 다음 읽기 시 갱신된 DMA 물리 메모리 데이터를 가져오도록 강제함.
* **구현 난이도:** 보통 (IDF 표준 API 적용)

### [2] SPI 트랜잭션 큐(Transaction Queue) 기반 비동기 스케줄링
* **이슈 여부:** **이슈 (높음)**
  * 현재 SPI 센서 리드/라이트(`_readRegs`, `_writeRegs`)가 동기식 Blocking으로 동작하며 태스크 양보(`vTaskDelay(0)`)를 통해 지연을 회피하고 있으나, 완전한 실시간 제어 및 버스 병합 처리를 위한 우선순위 큐(ST_SpiTransaction) 아키텍처가 부재함.
* **개선 방안:**
  * SPI 전송 명령을 캡슐화한 `ST_SpiTransaction_t` 구조체를 신설하고 FreeRTOS Queue로 전송 태스크에 전달.
  * SPI 비동기 인터럽트 구동 드라이버(`spi_device_queue_trans`)를 활성화하여 CPU 개입을 최소화하는 백그라운드 SPI 스케줄러 구축.
* **구현 난이도:** 높음 (SPI 드라이버 리팩토링 및 큐 엔진 설계 필요)

### [3] WAL 드라이버의 백그라운드 플러시 (Background Flush) 로직
* **이슈 여부:** **이슈 (보통)**
  * `CL_T2_WalDriver`에 빠른 커밋(`commitConfigFast`)은 구현되어 있으나, NVS/Flash 마모 방지 및 데이터 이관을 위한 백그라운드 `flushToLittleFSAndEraseNext()` 루틴이 비어있음.
* **개선 방안:**
  * 유휴 상태(Idle 상태) 또는 주기적 데몬 태스크에서 WAL 파티션의 최신 저널 데이터를 정규 LittleFS 설정 파일(`/sys/cfg_250.json`)로 복사 반영.
  * 복사가 정상 완료되면 WAL의 기록 포인터를 리셋하고 다음 섹터를 비동기적으로 미리 소거(`esp_partition_erase_range`)하여 쓰기 대기 지연 최소화.
* **구현 난이도:** 보통

### [4] Policy Traits 메타프로그래밍 구조체 불완전 (마스킹 제약 부족)
* **이슈 여부:** **이슈 (낮음/정합성)**
  * 헤더 내 `T2_General` 네임스페이스에 `enable_mfcc`, `enable_fft`만 존재하며 `ENABLE_TIMBRE`, `ENABLE_BAND_ENERGY`, 자이로용 저주파 대역 제한 상수 등이 누락되어 컴파일 타임 Pruning(연산 가지치기) 제약이 불완전함.
* **개선 방안:**
  * 각 `Policy` 구조체(`AccelPolicy`, `GyroPolicy`, `AudioPolicy`)에 세부 제어용 `static constexpr bool` 상수들을 완전하게 정의.
  * `std::conditional_t` 또는 `if constexpr`을 통해 불필요한 연산 코드(예: 자이로의 MFCC나 고대역 통과 연산)가 컴파일 결과물 바이너리에서 완전히 제외되도록 유도.
* **구현 난이도:** 낮음 (템플릿 상수 정비)

### [5] 자이로(Gyro) 전용 초경량 IIR 메모리 구조 미반영
* **이슈 여부:** **이슈 (보통/메모리 낭비)**
  * 자이로 데이터는 고주파 성분이 불필요해 대형 FIR 필터나 255차수 필터 상태 버퍼가 불필요함에도 가속도 필터 구조체와 동일하게 거대한 버퍼를 상속받아 사용 중임.
* **개선 방안:**
  * 자이로 전용 런타임 구조체(`ST_GyroDspRuntime`)에서 불필요하게 할당된 고차 FIR 버퍼를 제거하고, 가벼운 2차/4차 IIR 상태 버퍼(`_gyroIirState[3][4]`)로 대체.
  * 이를 통해 SRAM 힙 공간 수 KB 절약 가능.
* **구현 난이도:** 보통

### [8] SMEA_FLASH_RODATA 매크로의 실제 적용 누락
* **이슈 여부:** **이슈 (보통/메모리 낭비)**
  * 필터 계수 등의 읽기 전용 상수가 런타임 구조체 내에 일반 힙 영역 할당 필드로 잡혀있어 불필요한 SRAM 낭비 발생.
* **개선 방안:**
  * 모든 고정 필터 계수 테이블을 구조체 내부 멤버에서 제거하고, 파일 범위의 전역 상수 혹은 `static const` 배열로 정의하며 `SMEA_FLASH_RODATA` 매크로를 결합하여 Flash ROM(XIP)에 직접 고정.
* **구현 난이도:** 보통

### [9] FSM 매니저 내부의 제로 카피(Zero-Copy) 원칙 위배 (memcpy 남발)
* **이슈 여부:** **이슈 (높음/성능 저하)**
  * `T290_FsmMgr_250.cpp` 내부에서 DMA를 통해 안전하게 수집된 대량의 가속도/오디오 버퍼를 전달할 때 포인터만 교환하지 않고 `memcpy`를 사용해 CPU 직접 복사 오버헤드를 발생시킴.
* **개선 방안:**
  * 데이터 교환 수단으로 값 복사가 아닌 `T216_RingBuf_250`의 락 프리 링버퍼 버퍼 포인터(인덱스 및 주소)를 전달하는 구조로 전환.
  * 수집부와 연산부 간 버퍼 소유권을 양도(Take/Release)하는 Zero-Copy 핸들러 체계 구현.
* **구현 난이도:** 높음 (전체 데이터 흐름 리팩토링 필요)

### [10] WAL 드라이버의 플래시 수명 단축 (Write Amplification)
* **이슈 여부:** **이슈 (높음/수명 리스크)**
  * 설정 데이터를 수백 바이트 변경할 때마다 매번 4KB 섹터 단위 전체 소거(`esp_partition_erase_range`)를 진행하여 쓰기 증폭 및 플래시 수명 단축 유발.
* **개선 방안:**
  * 4KB 섹터 내에 `ST_WalHeader_t`와 설정 바이너리를 순차적으로 덧붙여 기록(`Append-only Sub-sector Journaling`).
  * 부팅 시 섹터를 스캔하여 순차 인덱스가 가장 높은 최신 레코드를 식별하고, 섹터 공간이 완전히 포화되었을 때만 다음 섹터를 소거 후 전환.
* **구현 난이도:** 높음

### [11] I2S DMA 디스크립터 경계와 제로 카피 스트라이드(Stride) 충돌
* **이슈 여부:** **이슈 (보통)**
  * 하드웨어 I2S DMA 청크 크기와 DSP의 FFT Hop Size가 수학적으로 어긋날 경우 링 버퍼에서 데이터가 찢어져 재정렬을 위해 `memcpy`를 강제 수행해야 함.
* **개선 방안:**
  * `T210_Def_250.hpp` 내에서 `FFT_SIZE`와 `OVERLAP_RATIO`를 기반으로 컴파일 타임에 `I2S_DMA_CHUNK_SIZE`를 도출하여, I2S 드라이버 초기화 파라미터에 바인딩.
* **구현 난이도:** 보통

### [12] [치명타] ESP-DSP FFT 복소수 버퍼 크기 불일치
* **이슈 여부:** **이슈 (치명적/예외 패닉)**
  * 1024-point 복소수 FFT(`dsps_fft2r_fc32_ae32`) 연산을 수행하면서 크기 1024짜리 실수 버퍼를 전달하여 인덱스 오버플로우 및 메모리 침범(Memory Corruption) 발생.
* **개선 방안:**
  * FFT 처리 버퍼 크기를 복소수 구조에 맞춰 `2 * N` (1024 FFT의 경우 2048개의 float 크기, 8KB)으로 확장 선언.
  * 실수 데이터를 복소수 버퍼로 이관할 때 짝수 인덱스에 실수값, 홀수 인덱스에 `0.0f`를 채워 넣는 Interleave 전처리 로직 강제화.
* **구현 난이도:** 보통

### [13] [치명타] FreeRTOS ISR 컨텍스트 위반
* **이슈 여부:** **이슈 (치명적/시스템 패닉)**
  * 외부 인터럽트 서비스 루틴(`T200_handleTriggerISR`, IRAM_ATTR) 내에서 FSM의 일반 동기식 `dispatchCommand()`를 호출하여 ISR 락 및 커널 크래시 리스크 존재.
* **개선 방안:**
  * FSM 매니저에 `dispatchCommandFromISR()` API를 별도로 개설하여 `xQueueSendFromISR()` 및 `portYIELD_FROM_ISR()` 매크로를 이용해 ISR 안전하게 커맨드를 전송하도록 수정.
* **구현 난이도:** 보통

### [14] TinyML AI 텐서 정렬(Alignment) 누락 (SIMD 로드 페널티)
* **이슈 여부:** **이슈 (보통/최적화)**
  * `_dataFlat` 버퍼를 `heap_caps_malloc`으로 할당하여 32비트 정렬만 보장되므로, S3의 SIMD 벡터 연산 구동 시 비정렬 로드 패널티 발생.
* **개선 방안:**
  * ESP32-S3 SIMD 아키텍처에 맞게 `heap_caps_aligned_alloc(16, size, MALLOC_CAP_SPIRAM)`을 활용해 16바이트 경계 정렬 강제 보장.
* **구현 난이도:** 보통

### [15] 락 프리 링버퍼 오버라이트 시 메모리 오더링(Memory Ordering) 역전
* **이슈 여부:** **이슈 (높음/동시성 버그)**
  * 버퍼 가득 참 발생 시 데이터를 먼저 복사하기 전에 `_tail` 포인터를 앞당겨, 다른 코어의 소비자가 불완전 복사된 원시 데이터를 참조할 여지가 있음.
* **개선 방안:**
  * `_buffer[head] = item` 복사를 완료한 후 메모리 배리어(`std::atomic_thread_fence(std::memory_order_release)`)를 치고 포인터를 전진시키도록 갱신 코드 재조정.
* **구현 난이도:** 보통

### [16] [치명타] 스토리지 I/O 뮤텍스 블로킹에 의한 실시간 파이프라인 붕괴
* **이슈 여부:** **이슈 (치명적/데이터 탈락)**
  * SD_MMC 디스크 물리 쓰기(`flush()`)가 뮤텍스를 소유한 채 진행되어 최대 수백 ms의 지연이 발생할 때, 동일 뮤텍스를 대기하는 실시간 수집 태스크까지 일시 대기하게 만드는 모순.
* **개선 방안:**
  * 뮤텍스는 링 버퍼 인덱스 제어 및 포인터 이동 등 메모리 경합 처리에만 극도로 한정하여 획득하고 해제.
  * 실제 파일 I/O 및 쓰기, 플러시는 뮤텍스 락 범위를 벗어난 백그라운드 태스크의 비동기 영역에서 비차단 방식으로 독립 처리(`Lock Decoupling`).
* **구현 난이도:** 높음 (스토리지 엔진 리팩토링 필요)

### [17] 메모리 풀링 아키텍처 변화에 따른 힙 단편화 방지 로직 미반영
* **이슈 여부:** **이슈 (보통/안정성)**
  * `T220` 및 `T270` 내부에서 통신 및 설정 직렬화 시 함수 내 지역 변수로 `JsonDocument`를 임시 생성하고 파괴하는 형태가 반복되어 파편화 및 OOM 리스크 존재.
* **개선 방안:**
  * `CL_T2_ConfigManager` 내에 공용 `JsonDocument`를 멤버 변수(`_docPool`) 또는 정적 풀로 두고 뮤텍스 보호 하에 재사용.
  * 매 연산 완료 후 `_docPool.clear()` 및 `_docPool.shrinkToFit()`을 명시 호출하여 메모리를 평탄화 및 유지관리.
* **구현 난이도:** 보통

### [18] [논리 붕괴] Non-Monotonic 시간의 동기화 오염 (SNTP Time Jump)
* **이슈 여부:** **이슈 (높음/정합성)**
  * 센서 수집 및 타임스탬프 계산에 NTP 영향을 받는 Real-Time Clock(RTC) 시간 도메인을 사용할 경우, Wi-Fi 재동기화 시 타임스탬프가 역전되어 정렬 모듈 오작동 유발.
* **개선 방안:**
  * 실시간 센서 스트림 및 시퀀스 빌딩에는 전적으로 하드웨어 타이머 기반의 단조 증가 시간인 `esp_timer_get_time()` (Monotonic Time)만 사용.
  * RTC 시간축은 저장 로그 파일의 네이밍이나 최종 경보 표기 등의 UI 필드에만 엄격 격리 적용.
* **구현 난이도:** 보통

### [19] [동시성 버그] 비원자적 변수(Non-Atomic)에 대한 메모리 배리어 무효화
* **이슈 여부:** **이슈 (보통)**

### [38] [FsmMgr ↔ DspEng] 코어 마이그레이션과 Task WDT 기아 현상
* **이슈 여부:** **이슈 (높음/시스템 리셋)**
  * 고하중 DSP 연산 태스크들이 특정 코어에 고정되지 않고 유동 스케줄되어 Core 0의 네트워크 및 센서 ISR과 경합 시 CPU 독점으로 인해 WDT 강제 리셋을 일으킴.
* **개선 방안:**
  * 실시간 센서 및 네트워크 수집부는 `xTaskCreatePinnedToCore`를 통해 Core 0에, 무거운 DSP 연산 및 AI 분석 태스크는 Core 1에 완벽 고정(`Core Binding`).
  * 복잡한 FFT 및 특징량 추출 연산 반복 루프 사이에 `esp_task_wdt_reset()`을 삽입하여 감시 데몬 방어.
* **구현 난이도:** 보통

### [39] [Storage ↔ SeqBuild] 플래시 가비지 컬렉션에 의한 텐서 조립 타임아웃
* **이슈 여부:** **이슈 (높음/시계열 파열)**
  * 파일 쓰기 시 발생하는 불규칙한 SD 카드 가비지 컬렉션 지연이 동적 메모리 조립부를 블로킹하여 시계열 데이터 결합 타임아웃을 유발하는 연쇄 실패.
* **개선 방안:**
  * 파일 세션 오픈 시 파일 크기 증가에 따른 물리 할당 병목을 막기 위해, 사전에 고정 영역 크기(예: 10MB)를 선할당(`f_lseek` 또는 `fallocate` 유사 방식 활용)하여 디스크 공간을 선점 확보함으로써 쓰기 속도 안정화.
* **구현 난이도:** 높음 (FATFS 물리 제어 적용)

### [41] [FsmMgr ↔ Trigger] STA/LTA의 '콜드 스타트(Cold Start)' 초기화 모순에 의한 오경보 폭주
* **이슈 여부:** **이슈 (보통)**
  * 장비 가동 중에 시스템이 재부팅되는 경우, 초기 LTA 히스토리가 0.0f로 시작하여 실제 현장의 배경 진동에 직면하는 순간 단기 평균(STA) 대비 폭발적인 상승으로 오인해 수많은 허위 결함 판정 발생.
* **개선 방안:**
  * 시스템 부팅 직후 FSM에 N초(예: 30초) 동안의 `WARM_UP` (안정화) 상태 단계를 신설.
  * 해당 시간 동안 LTA 버퍼에 배경 신호를 완전히 충전한 후에만 진단 판정 플래그를 정상 개시하도록 방어 처리.
* **구현 난이도:** 보통

### [43] [Trigger ↔ Storage] MLOps 데이터 파이프라인의 '레이블 모호성' 발생
* **이슈 여부:** **이슈 (보통/데이터 가치 유실)**
  * 결함 진단 트리거로 스토리지에 데이터를 덤프할 때 파일 내부에 어떤 결함 인자(임계치 초과 지표, 특정 주파수 대역 등)로 이상 판정이 났는지 상세 정보(그라운드 트루스)가 기록되지 않아 후속 학습 분석에 활용하기 어려움.
* **개선 방안:**
  * `EM_DetectionResult_t` 판정 인자 형식을 이상 데이터 속성 구조체(`ST_TriggerReason_t`: 축 번호, 지표 명칭, 초과 비율, 실 측정치 포함)로 확장.
  * 본 구조체 바이트 스트림 데이터를 스토리지 세션 바이너리 파일 헤더에 직접 임베디드하여 직렬화 기록.
* **구현 난이도:** 보통
