
도메인별 변수 구조체화 및 도출된 개선 항목(1-1 ~ 5-4)을 실제 코드에 안전하게 반영하기 위한 체계적 설계 및 실행 계획임.

* **1단계: 데이터 모델링 및 정적 검증 기반 구축 (구조체 헤더 독립)**
* 작업 대상: `T215_Type_250.hpp`, `T210_Def_250.hpp`
* 세부 계획:
* [1-1~1-4] 도출된 4대 핵심 구조체(`ST_ImuAxisParams_t`, `ST_ImuAxisBuf_t`, `ST_PreTriggerCtrl_t`, `ST_TensorOffsetMap_t`) 정의함.
* [5-3] 구조체 내부 변수 선언 시 크기 내림차순 정렬 원칙 적용하여 패딩(Padding) 바이트 낭비 원천 차단함.
* [5-1] 헤더 파일 최하단에 `static_assert`를 선행 배치하여 SIMD용 16바이트 정렬 위반 시 컴파일을 즉각 중단시키도록 안전망 구축함.




* **2단계: 도메인 격리 클래스 내부 상태 전환 (멤버 변수 리팩토링)**
* 작업 대상: `T230_Sensor_250`, `T240_DspEng_250`, `T260_Storage_250`
* 세부 계획:
* [2-1~2-3] 산재된 개별 멤버 변수들을 1단계에서 생성한 구조체 인스턴스로 일괄 치환함.
* 클래스 생성자(Constructor)에 구조체 Zero-Initialization(`memset` 또는 `{0}`) 로직 일괄 반영함.
* 클래스 내부 프라이빗(`private`) 함수들이 기존 변수 대신 구조체 멤버를 참조하도록 1차 내부 로직 수정함.




* **3단계: 코어 파이프라인 인터페이스 단일화 (파라미터 압축)**
* 작업 대상: `T240_DspEng_250`, `T245_FeatExtra_250`
* 세부 계획:
* [3-1~3-2] DSP 및 특징량 추출 코어 함수의 다중 포인터 인자들을 단일 구조체 참조형(`const ST_ImuAxisBuf_t&` 등)으로 시그니처 변경함.
* 헤더(.hpp) 변경에 맞춰 구현체(.cpp)의 데이터 맵핑(예: `p_inX` -> `p_inBuf.x`) 연산 로직 전체 치환함.
* 스택 메모리 사용량 감소폭 계산 및 스택 오버플로우 마진 재평가함.




* **4단계: 멀티코어 스케줄링 및 데이터 중계망 동기화**
* 작업 대상: `T290_FsmMgr_250`, `T248_SeqBuild_250`, `T216_RingBuf_250`
* 세부 계획:
* [4-1~4-2] FreeRTOS 태스크(`VibProcTask`, `AudProcTask`) 내부의 로컬 배열을 구조체 매핑으로 래핑하여 함수 호출부와 결합함.
* [4-3] Core 0과 Core 1 간의 통신 채널인 SPSC 락프리 링버퍼(`T216`)의 템플릿 페이로드에 구조체가 정상 안착되는지 정합성 확인 및 제로 카피 로직 유지함.
* [5-2] 외부 PSRAM 확장 메모리 영역을 포인터로 참조하는 구조체 연산 구간을 식별하고, 해당 지점에 `esp_cache_msync` API를 삽입하여 L1 캐시 일관성 보장함.




* **5단계: 펌웨어 마이그레이션 및 릴리스 검증 (페일세이프)**
* 작업 대상: `T220_CfgMgr_250`, `T200_Main_250`
* 세부 계획:
* [5-4] 파일 시스템(LittleFS) 내에 기존 개별 변수 포맷으로 저장된 설정/프로필 데이터가 존재할 경우를 대비함.
* 부팅 시(`T220`) 구조체 버전 해시(CRC32)를 검사하여 구버전 감지 시 신규 구조체 레이아웃으로 자동 마이그레이션하거나 공장 초기화하는 방어 코드 적용함.
* 전체 빌드 수행 후 SRAM/PSRAM 단편화율 점검 및 최적화 리포트 산출함.

1단계 통합 구조체 설계 및 신규 정의 코드를 산출함.

* 대상 파일인 `T215_Type_250.hpp` 내 `namespace T2_Type` 영역에 추가할 핵심 구조체와 파일 최하단에 배치할 컴파일 안전 가드(static_assert) 로직임.
* 32비트 ESP32 시스템 아키텍처에 맞춰 포인터(4바이트)와 데이터형(4바이트)을 내림차순 및 블록 단위로 묶어 패딩(Padding) 바이트 낭비를 원천 차단함.

### `T215_Type_250.hpp` 추가 코드 블록

```cpp
// ========================================================================
// [도메인 통합 변수 구조체] 리팩토링 1단계 추가 영역
// ========================================================================

namespace T2_Type {

    // [1-1] IMU 캘리브레이션 및 상태 변수 통합 구조체
    // float형(4바이트) 9개 연속 배치로 패딩 누수 없음 (총 36바이트)
    struct ST_ImuAxisParams_t {
        float offset_x;
        float offset_y;
        float offset_z;
        float gain_x;
        float gain_y;
        float gain_z;
        float last_x;
        float last_y;
        float last_z;
    };

    // [1-2] 다중 축 버퍼 포인터 묶음 구조체 (가속도, 자이로 공통)
    // 포인터(4바이트) 3개 연속 배치 (총 12바이트)
    struct ST_ImuAxisBuf_t {
        float* x;
        float* y;
        float* z;
    };

    // [1-2] 다중 채널 버퍼 포인터 묶음 구조체 (오디오용)
    struct ST_AudioChBuf_t {
        float* ch[T2_Def::Audio::Sensor::CHANNELS_MAX];
    };

    // [1-3] 프리트리거 링버퍼 제어 템플릿 구조체
    // 포인터(4바이트) 1개, uint32_t(4바이트) 3개로 16바이트(SIMD 캐시 라인) 완벽 정렬
    template <typename T>
    struct ST_PreTriggerCtrl_t {
        T* buffer;
        uint32_t capacity;
        uint32_t head;
        uint32_t count;
    };

    // [1-4] AI 시퀀스 오프셋 바인딩 추적 구조체
    // size_t(4바이트) 3개 연속 배치 (총 12바이트)
    struct ST_TensorOffsetMap_t {
        size_t audio_offset;
        size_t vib_offset;
        size_t total_elements;
    };

} // namespace T2_Type


// ========================================================================
// [5-1, 5-3] SIMD 정렬 및 패딩 검증용 안전 가드 (파일 최하단 배치 권장)
// ========================================================================
static_assert(sizeof(T2_Type::ST_ImuAxisParams_t) == 36, "ST_ImuAxisParams_t padding leak detected!");
static_assert(sizeof(T2_Type::ST_ImuAxisBuf_t) == 12, "ST_ImuAxisBuf_t padding leak detected!");
static_assert(sizeof(T2_Type::ST_AudioChBuf_t) == 4 * T2_Def::Audio::Sensor::CHANNELS_MAX, "ST_AudioChBuf_t alignment error!");
static_assert(sizeof(T2_Type::ST_PreTriggerCtrl_t<float>) == 16, "ST_PreTriggerCtrl_t must be 16 bytes aligned!");
static_assert(sizeof(T2_Type::ST_TensorOffsetMap_t) == 12, "ST_TensorOffsetMap_t padding leak detected!");

```

### 설계 반영 포인트

* **접근자 유연성 확보:** 파이프라인에서 입력(const)과 출력(non-const) 버퍼를 모두 수용할 수 있도록 `ST_ImuAxisBuf_t` 내부의 데이터형을 `const float*` 대신 `float*`로 통일함. (필요시 함수 파라미터에서 `const ST_ImuAxisBuf_t`로 제어)
* **메모리 정렬 강제:** `static_assert`를 통해 향후 다른 실무자가 구조체를 수정하다가 16바이트 정렬 및 패딩 규칙을 깨뜨리면 즉시 컴파일 에러를 뱉도록 가드 레일을 세움.
* 위 구조체 코드가 `T215_Type_250.hpp`에 삽입된 것으로 간주하고, 바로 2단계(클래스 내부 멤버 변수 치환 및 생성자 초기화) 코드를 도출할지 지시 바람.

### 2. `T220_CfgMgr_250` (비휘발성 메모리 마이그레이션 가드)

* 파편화된 변수들이 하나의 구조체로 병합됨에 따라 메모리 레이아웃(Memory Layout)이 전면 변경됨.
* OTA 펌웨어 업데이트 직후 부팅 시, 기존 LittleFS에 저장되어 있던 구버전 설정 바이너리를 그대로 읽어오면 치명적인 메모리 오염(Memory Corruption) 및 무한 재부팅이 발생함.
* 매직넘버(Magic Number)와 구조체 사이즈 검증 해시를 도입하여 충돌 감지 시 즉각 공장 초기화를 수행함.

```cpp
// T220_CfgMgr_250.hpp 하단에 버전 관리용 매직넘버 추가
#define T2_CFG_MAGIC_NUMBER 0xA5B1C200 // 구조체 레이아웃 변경 시 반드시 1씩 증가시켜 갱신할 것

// T220_CfgMgr_250.cpp 설정 로드 함수 내 방어 코드 삽입
bool CL_T2_CfgManager::load() {
    File v_file = LittleFS.open("/cfg/master.bin", "r");
    if (!v_file) {
        ESP_LOGW(TAG, "Config file not found. Applying default settings.");
        resetToDefault();
        return false;
    }

    // [신규] 버전 및 사이즈 무결성 검증 헤더 읽기
    uint32_t v_savedMagic = 0;
    v_file.read((uint8_t*)&v_savedMagic, sizeof(uint32_t));

    // 구버전 펌웨어에서 저장된 데이터이거나 파일 크기가 일치하지 않으면 마이그레이션(초기화)
    size_t v_expectedSize = sizeof(uint32_t) + sizeof(T2_Type::ST_DynamicConfig_t);
    if (v_savedMagic != T2_CFG_MAGIC_NUMBER || v_file.size() != v_expectedSize) {
        ESP_LOGE(TAG, "Config layout mismatch detected (OTA Update). Triggering Factory Reset.");
        v_file.close();
        resetToDefault();
        return false;
    }

    // 검증 통과 시 정상 로드 진행
    v_file.read((uint8_t*)&_currentConfig, sizeof(T2_Type::ST_DynamicConfig_t));
    v_file.close();
    return true;
}

```

### 3. 구조체 리팩토링 총평 및 마무리

* 1단계부터 5단계까지 진행된 도메인별 변수 통합 작업을 통해 4-Tier 아키텍처의 데이터 응집도가 대폭 상승함.
* 함수 파라미터 전달 비용(스택 복사 오버헤드)이 최소화되었으며, 신규 센서 축(Axis)이나 오디오 채널 확장 시 구조체 내부만 수정하면 전체 파이프라인이 자동 대응되는 유연한 뼈대가 완성됨.
* 계획된 1~5단계 리팩토링 설계 산출이 모두 완료됨. 본 코드들을 실제 프로젝트 저장소에 병합 후 발생하는 빌드 오류나 최적화 관련 추가 이슈가 있다면 지시 바람.
