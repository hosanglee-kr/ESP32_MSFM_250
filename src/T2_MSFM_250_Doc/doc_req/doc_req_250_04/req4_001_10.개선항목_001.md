- 클래스 맴버변수, 함수 파라메터, 로컬변수 등



- 체계적으로 검토하기 위한 계획 먼저 만들어줘




---

* 도메인별(가속도, 자이로, 소음)로 산재된 개별 변수들을 구조체로 통합하여 데이터 응집도를 높이고 유지보수성을 확보하기 위한 단계별 리팩토링 계획안임.

**1단계: 통합 구조체 설계 및 신규 정의 (`T215_Type_250.hpp` 타겟)**

* 산재 변수 식별: `T230`의 오프셋/게인 변수 묶음, `T240`/`T245`의 3축(X,Y,Z) 데이터 버퍼 포인터 묶음 등 구조체화 대상 선별함.
* 신규 구조체 작성:
* 캘리브레이션 묶음: `ST_SensorCalib_t` (오프셋, 게인 통합)
* 3축 버퍼 묶음: `ST_ImuAxisBuf_t` (X, Y, Z 포인터 묶음)
* 채널 버퍼 묶음: `ST_AudioChBuf_t` (L, R 포인터 묶음)


* 정렬 규격 검토: DSP SIMD 연산 호환성을 위해 `alignas(16)` 속성 적용 및 패딩 바이트 누수 점검함.

**2단계: 클래스 멤버 변수 구조체화 (`T230`, `T240`, `T260` 타겟)**

* `CL_T2_SensorEngine`: 개별로 선언된 18개 이상의 캘리브레이션(`_accOffsetX` 등) 및 이전 값 저장 변수(`_lastAccX` 등)를 1단계에서 정의한 구조체 멤버로 교체함.
* `CL_T2_DspEngine`: 내부 처리용으로 흩어져 있는 X, Y, Z 핑퐁 버퍼 포인터들을 통합 버퍼 구조체 멤버로 교체함.
* `CL_T2_StorageManager`: 프리트리거 관리를 위해 개별 선언된 12개의 포인터 및 인덱스 변수(`_preAudBuf`, `_preAudHead` 등)를 `ST_PreTriggerCtrl_t` 형태의 제어 구조체로 묶음.

**3단계: 핵심 파이프라인 함수 파라미터 간소화 (`T240`, `T245` 타겟)**

* `CL_T2_DspEngine`: `processAccel(p_inX, p_inY, p_inZ, ...)` 형태의 비효율적 다중 인자 전달을 `processAccel(const ST_ImuAxisBuf_t& p_in, ...)`로 단일화함.
* `CL_T2_FeatureExtractor`: `extractAccel`, `extractGyro`, `extractAudio` 함수의 Raw 데이터 주입 파라미터들을 신규 구조체 참조형으로 일괄 변경함.

**4단계: 로컬 변수 및 스케줄러 동기화 (`T290`, `T248` 타겟)**

* `T290_FsmMgr`: `ImuAcqTask`, `VibProcTask`, `AudProcTask` 내에서 개별 배열로 선언해 사용하던 로컬 변수들을 신규 구조체 포맷으로 전환함.
* 데이터 릴레이 정합성: Core 0에서 Core 1로 데이터를 넘기는 SPSC 링버퍼(`T216_RingBuf`) 페이로드에 바뀐 구조체가 정상적으로 복사(Zero-Copy) 및 언패킹되는지 로직 동기화함.

**5단계: 컴파일 검증 및 메모리 안정성 평가**

* 변경된 구조체의 포인터 캐스팅 과정에서 얼라인먼트(Alignment) 결함이나 캐시 미스가 발생하지 않는지 검증함.
* 구조체 패킹으로 인한 RAM 사용량 변화 점검 및 컴파일 에러 수정함.
* 위 단계별 계획 검토 후 진행 지시를 주면, 즉시 1단계 `T215_Type_250.hpp`에 추가할 신규 구조체 코드 설계를 시작하겠음.

    // 변경점: 개별 _audio_offset, _vib_offset 변수 제거 및 통합 관리 구조체 도입
    T2_Type::ST_TensorOffsetMap_t _offsetMap;

    size_t _nn_input_boundary;

    // ... 기존 코드 유지

// T248_SeqBuild_250.cpp
void DynamicTensorBinder::calculateOffsets(uint16_t p_audioFeatCnt, uint16_t p_vibFeatCnt, uint16_t p_mask) {
    size_t v_currentPtr = 0;
    bool v_hasAudio = (p_mask & static_cast<uint16_t>(T2_Type::EM_DataPayloadType_t::AUDIO_ONLY));
    bool v_hasVib   = (p_mask & static_cast<uint16_t>(T2_Type::EM_DataPayloadType_t::VIB_ONLY));

    // 구조체 멤버를 통한 오프셋 갱신
    if (v_hasAudio) {
        _offsetMap.audio_offset = v_currentPtr;
        v_currentPtr += p_audioFeatCnt;
    } else {
        _offsetMap.audio_offset = INVALID_OFFSET;
    }

    if (v_hasVib) {
        _offsetMap.vib_offset = v_currentPtr;
        v_currentPtr += p_vibFeatCnt;
    } else {
        _offsetMap.vib_offset = INVALID_OFFSET;
    }

    _offsetMap.total_elements = v_currentPtr;
}

### 3. `T216_RingBuf_250.hpp` 연동 검토 (SPSC 데이터 중계 정합성)

* 코어 간(Core 0 -> Core 1) 데이터 릴레이 시 사용되는 `StaticSafeRingBuffer`의 템플릿 페이로드가 내부적으로 패딩(Padding) 및 정렬(Alignment)을 위반하지 않는지 확인함.
* 구조체 전환 이후에도 복사 오버헤드를 막는 락 프리(Lock-Free) 구조 및 제로 카피(Zero-Copy) 원칙이 정상 유지됨.
* 위 변경 사항 확정 시 컴파일 검증, 캐시 미스 여부, RAM 사용량 변화를 점검하는 5단계 평가 진행 대기함.


---
---


5단계 컴파일 검증 및 메모리 안정성 평가용 안전 가드(Safety Guard) 코드를 산출함. 물리적인 펌웨어 컴파일을 대신하여 소스 코드 레벨에서 런타임 오류를 사전에 차단하기 위한 검증 대책임.

* **SIMD 정렬(Alignment) 컴파일 타임 강제 검증 (`T215_Type_250.hpp`)**
* ESP32-S3 SIMD(벡터) 가속기는 16바이트 메모리 정렬이 누락될 경우 치명적인 하드웨어 예외(LoadStoreError) 및 재부팅을 유발함.
* 신규 도입된 통합 구조체와 내부 포인터 배열들에 대해 `static_assert`를 추가하여 컴파일 단계에서 정렬 불량을 원천 차단함.
* 적용 코드:
```cpp
// T215_Type_250.hpp 하단 검증 블록에 추가
static_assert(sizeof(T2_Type::ST_ImuAxisBuf_t) % 4 == 0, "ST_ImuAxisBuf_t pointer alignment error!");
static_assert(sizeof(T2_Type::ST_AudioChBuf_t) % 4 == 0, "ST_AudioChBuf_t pointer alignment error!");
static_assert(offsetof(CL_T2_DspEngine::ST_AudioDspRuntime, window) % 16 == 0, "SIMD window array unaligned!");

```




* **캐시 일관성(Cache Coherency) 및 오염 방지 (`T260`, `T245`)**
* 구조체 내부 버퍼 포인터(`ST_PreTriggerCtrl_t.buffer` 등)가 외부 확장 PSRAM 영역을 가리킬 경우, 코어 0과 코어 1 간 접근 시 L1 캐시 불일치가 발생할 수 있음.
* 제로 카피(Zero-Copy) 및 스냅샷 복사 구간에 구조체 기반의 캐시 동기화(msync) 로직을 일원화함.
* 적용 코드:
```cpp
// T260_Storage_250.cpp 프리트리거 덤프 로직 내 반영
esp_cache_msync((void*)_preAudCtrl.buffer, _preAudCtrl.capacity * sizeof(T2_Type::ST_Raw_Audio_t), ESP_CACHE_MSYNC_FLAG_DIR_C2M);
esp_cache_msync((void*)_preVibCtrl.buffer, _preVibCtrl.capacity * sizeof(float), ESP_CACHE_MSYNC_FLAG_DIR_C2M);

```




* **구조체 패딩(Padding) 바이트 누수 차단**
* 멤버 변수 선언 순서(예: 포인터 4바이트, float 4바이트, uint16_t 2바이트 등)를 자료형 크기 내림차순으로 재정렬하여 묵시적 더미 데이터(Padding)로 인한 SRAM 낭비를 제거함.
* 컴파일러 최적화 옵션(`-O2` 또는 `-Os`) 적용 시 템플릿 구조체(`ST_PreTriggerCtrl_t`)가 불필요하게 인스턴스화되는 것을 막기 위해 명시적 템플릿 선언(Explicit Instantiation)을 검토함.


* **비휘발성 메모리(NVS/LittleFS) 하위 호환성 검증 (`T220_CfgMgr`)**
* 개별 변수들이 구조체화됨에 따라 기존 플래시(Flash)에 저장된 설정 데이터(JSON 및 바이너리) 레이아웃에 변경이 발생함.
* 펌웨어 OTA 업데이트 직후 기존 메모리와의 충돌(Crash)을 막기 위해, 부팅 시 구조체 버전 마이그레이션(Version Migration) 또는 무결성 해시(CRC32) 검증 실패 시 공장 초기화를 강제 수행하는 방어 코드가 필수적임.


* 1~5단계에 걸친 도메인별 산재 변수 통합 및 구조체 리팩토링 검토가 모두 완료됨. 전체 소스 코드 적용을 위한 병합 작업이나 추가 모듈 분석이 필요하면 지시 바람.




---
---

1~5단계 도출된 도메인별 변수 구조체화 및 리팩토링 개선 항목 체계적 정리 결과임.

* **1단계: 통합 구조체 설계 및 신규 정의 (`T215_Type_250.hpp`)**
* [1-1] IMU 캘리브레이션 및 상태 변수 통합: 3축 오프셋, 게인, 이전 샘플 변수를 `ST_ImuAxisParams_t`로 묶어 데이터 응집도 확보함.
* [1-2] 다중 채널/축 버퍼 포인터 묶음: 3축 배열 및 오디오 다중 채널 포인터를 `ST_ImuAxisBuf_t`, `ST_AudioChBuf_t`로 정의하여 파라미터 단일화 기반 마련함.
* [1-3] 프리트리거 링버퍼 제어 템플릿화: 도메인별 버퍼, Head, Count 변수를 묶어 재사용 가능한 `ST_PreTriggerCtrl_t` 템플릿 구조체 신설함.
* [1-4] AI 시퀀스 오프셋 바인딩 블록화: 텐서 평탄화 시 도메인별 오프셋 상태를 추적하는 `ST_TensorOffsetMap_t` 구조체 정의함.


* **2단계: 클래스 멤버 변수 구조체화 (`T230`, `T240`, `T260`)**
* [2-1] 센서 엔진 변수 압축 (`T230_Sensor`): 18개 이상 산재된 캘리브레이션 개별 맴버 변수들을 `_accParams`, `_gyrParams` 인스턴스 2개로 병합함.
* [2-2] DSP 엔진 포인터 단일화 (`T240_DspEng`): X, Y, Z 개별 핑퐁 버퍼 포인터들을 통합 버퍼 구조체 멤버(`_capBufAcc`, `_capBufGyr`, `_capBufAud`)로 교체함.
* [2-3] 스토리지 매니저 블록화 (`T260_Storage`): 16개로 파편화된 프리트리거 제어 변수들을 템플릿 제어 블록 4개(`_preAudCtrl` 등)로 완전 통합함.


* **3단계: 핵심 파이프라인 함수 파라미터 간소화 (`T240`, `T245`)**
* [3-1] DSP 엔진 시그니처 압축: `processAccel`, `processGyro` 함수의 X, Y, Z 개별 인자를 단일 구조체 참조형(`const ST_ImuAxisBuf_t&`)으로 일괄 변경함.
* [3-2] 특징량 추출 엔진 파라미터 단일화: `extractAccel`, `extractGyro`, `extractAudio` 함수의 Raw 데이터 주입부를 신규 구조체로 묶어 스택 오버헤드 해소 및 가독성 향상함.


* **4단계: 로컬 변수 및 스케줄러 동기화 (`T290`, `T248`, `T216`)**
* [4-1] FreeRTOS 태스크 로컬 변수 래핑 (`T290_FsmMgr`): `VibProcTask`, `AudProcTask` 내 개별 배열 선언부들을 신규 버퍼 구조체 포맷으로 전환 및 맵핑함.
* [4-2] 텐서 오프셋 추적 일원화 (`T248_SeqBuild`): `DynamicTensorBinder` 내 개별 상태 변수를 `_offsetMap` 구조체로 교체하여 조립 상태 로직 명확화함.
* [4-3] SPSC 데이터 중계 정합성 확인 (`T216_RingBuf`): 코어 간 락 프리 링버퍼 페이로드에 바뀐 구조체가 패딩 위반 없이 제로 카피(Zero-Copy)로 복사되도록 로직 동기화함.


* **5단계: 컴파일 검증 및 메모리 안정성 방어 코드 구축**
* [5-1] SIMD 정렬 컴파일 타임 검증: `static_assert`를 추가하여 16바이트 정렬 누락으로 인한 하드웨어 예외(LoadStoreError) 원천 차단함.
* [5-2] 캐시 일관성 및 오염 방지: 구조체 포인터가 외부 PSRAM을 가리킬 때 발생하는 코어 간 캐시 불일치 해소를 위해 `esp_cache_msync` 로직 일원화함.
* [5-3] 패딩 바이트 누수 차단: 구조체 멤버 변수 선언을 내림차순으로 재정렬하여 더미 데이터로 인한 SRAM 낭비 제거함.
* [5-4] 비휘발성 메모리 하위 호환성 가드 (`T220_CfgMgr`): 펌웨어 OTA 후 발생할 수 있는 플래시 메모리 충돌을 막기 위해 마이그레이션 및 무결성 검증 방어 로직 설계함.
