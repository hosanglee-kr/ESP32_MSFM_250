# 임베디드 엣지 진단 프레임워크 종합 설계서 (v248_004)

SMEA-100 엣지 제어기 및 진단 엔진에서 발견된 126건의 보안, 구조 무결성, 동시성, 물리 예외 결함들을 근본적으로 차단하기 위한 4단계 아키텍처 가이드라인 명세서입니다.

---

## 📌 설계 전제 가설 (Core Assumptions)
1. **단일 I2S 포트 스테레오 수집:** 하드웨어 보드 설계 상 두 마이크가 단일 I2S 포트의 L/R(Stereo) 채널로 연결되어 있으므로, 하드웨어 수준에서 위상이 완벽히 동기화됩니다. 소프트웨어 레벨의 비동기 지연 보정 루프는 생략하고 단일 DMA 스테레오 수집 구조를 채택합니다.
2. **TFLM 정적 입력 텐서 (Fixed Shape):** TensorFlow Lite for Microcontrollers(TFLM) 입력 텐서의 크기는 고정된 크기(Fixed Shape)로만 가져갑니다. 채널 마스크 등의 설정이 변경될 경우 FSM이 해당 설정에 부합하는 새로운 정적 모델로 교체(Model Switching)하는 구조를 전제합니다.
3. **지연 추론 기반 시계열 선형 보간 (해석 A 채택):** 실시간 처리 시 오디오 프레임(24.38ms)은 진동 데이터(640ms)가 수집될 때까지 임시 SPSC 링버퍼에 버퍼링됩니다. 새로운 진동 스냅샷이 수입되는 즉시, 버퍼링된 오디오 타임스탬프를 매핑하여 `_prev_vib`와 `_curr_vib` 사이에서 정밀한 선형 보간을 계산해 지연 추론을 수행합니다. 이로 인해 결과 도출에 최대 640ms의 물리적 지연(Latency)이 허용됩니다.

---

## 🛠️ 126개 이슈 체계적 해결을 위한 3대 전략

### 1. 영향도 기반 레이어 격리 (Layered Sandboxing)
* 개별 연산 함수마다 방어 코드를 분산 배치하지 않고, 드라이버 직후와 텐서 조립 직후에 **'데이터 무결성 검증(Sanitization)'만 전담하는 마이크로 인터락 레이어**를 배치하여 예외를 한 번에 흡수합니다.

### 2. '공통 상태 주입(SSOT)' 중심의 허브-앤-스포크 설계
* 설정 변동 시 FSM이 파이프라인 연산을 잠시 동결(Clock Gating)한 뒤, 주소 오프셋 재배치 및 모델 전환을 안전하게 핫스왑하는 동기화 시퀀스를 수행합니다.

### 3. 기능 영향 범위에 따른 단계적 롤아웃 (Tiers)
* 시스템 실시간성에 미치는 영향도가 낮고 독립적인 하위 영역부터 가장 파급력이 큰 전역 FSM 영역까지 **4단계 안전 기동 설계**를 적용합니다.

## 📋 4단계 아키텍처 패치 시퀀스 명세

### 1단계: 글로벌 데이터 타이핑 및 세이프티 매크로 설계 (Tier 1: Foundations)

* **목적:** 부동소수점 오염(`NaN`, `Inf`), 분모 제로, 하드웨어 정렬 예외를 전역 레벨에서 원천 차단.
* **설계 범위:**
  * `-ffast-math` 최적화 환경 대응 및 FPU 가속 친화형 수치 제어 매크로 설계.
  * 메모리 정렬(Alignment) 이원화 설계: 통신 버퍼는 1바이트 패딩을 강제하되, 내부 DSP 및 텐서용 구조체는 4/8/16바이트 정렬을 유지하여 하드웨어 예외 방지.

#### 1. FPU 가속 친화형 수치 수렴성 보호 매크로
```cpp
#include <cmath>
#include <algorithm>

// -ffast-math 옵션에서도 NaN을 정확하게 검출하는 컴파일러 내장 가속 함수
#define SMEA_IS_NAN(v) (__builtin_isnan(v))
#define SMEA_IS_INF(v) (__builtin_isinf(v))

// FPU NaN/Inf 예외 발생 시 안전 하한치(또는 0.0f)로 강제 수렴
#define SMEA_SAN_FLOAT(v) ((SMEA_IS_NAN(v) || SMEA_IS_INF(v)) ? 0.0f : v)

// 하드웨어 입력 스케일 폭발 및 뉴런 데드(Dead ReLU) 방지를 위한 경계 제한 가드
#define SMEA_CLAMP_FLOAT(v, min_v, max_v) (std::clamp(SMEA_SAN_FLOAT(v), (min_v), (max_v)))

// 분모 제로 나눗셈(Zero Division) 원천 차단 (FPU 성능을 고려하여 fabsf 적용)
#define SMEA_SAFE_DIV(num, denom, eps) ((fabsf(denom) < (eps)) ? ((num) / (eps)) : ((num) / (denom)))
```

### 2단계: 버퍼 가드 및 Lock-Free SPSC 링버퍼 설계 (Tier 2: Buffers & Memory)

* **목적:** 오프-바이-원(Off-by-One) 경계 침범, 링버퍼 롤오버 인덱스 뒤집힘, 멀티코어 동시성 오염 차단, 하드웨어 통신 예외 방어.
* **설계 범위:**
  * 인터럽트 마비(Interrupt Latency)를 원천 해결하기 위한 단일 생산자-단일 소비자(SPSC) 구조의 Lock-Free 링버퍼 설계.
  * SPI/I2C 버스트 리드 바이트 뒤집힘 방지 및 DRY 핀 인터럽트 디바운싱 필터링 설계.

#### 1. SPSC Lock-Free 링버퍼 아키텍처 명세
```cpp
#include <atomic>
#include <algorithm>

template <typename T, size_t MaxSize>
class StaticSafeRingBuffer {
private:
    T _buffer[MaxSize];
    std::atomic<size_t> _head;
    std::atomic<size_t> _tail;

public:
    StaticSafeRingBuffer() : _head(0), _tail(0) {
        std::fill_n(_buffer, MaxSize, T());
    }

    // 단일 생산자(Producer: ISR 또는 전용 수집 태스크) 호출 전용 (락 프리)
    bool enqueue(const T& item) {
        size_t head = _head.load(std::memory_order_relaxed);
        size_t tail = _tail.load(std::memory_order_acquire);

        size_t next_head = (head + 1) % MaxSize;
        if (next_head == tail) {
            // 버퍼가 가득 찬 경우 (가장 오래된 데이터 유실 허용 시 tail 1보 전진)
            _tail.store((tail + 1) % MaxSize, std::memory_order_release);
        }

        _buffer[head] = item;

        // 메모리 쓰기 순서가 섞이지 않도록 하드웨어 배리어 강제 (데이터 복사 완료 보장)
        std::atomic_thread_fence(std::memory_order_release);
        asm volatile("memw");

        _head.store(next_head, std::memory_order_release);
        return true;
    }

    // 단일 소비자(Consumer: 처리 태스크) 호출 전용 (락 프리)
    bool dequeue(T& outItem) {
        size_t tail = _tail.load(std::memory_order_relaxed);
        size_t head = _head.load(std::memory_order_acquire);

        if (tail == head) return false; // 읽을 데이터 없음

        outItem = _buffer[tail];
        _tail.store((tail + 1) % MaxSize, std::memory_order_release);
        return true;
    }

    void clear() {
        // Consumer 태스크 컨텍스트에서 안전하게 클리어 수행
        _head.store(0, std::memory_order_relaxed);
        _tail.store(0, std::memory_order_release);
    }

    size_t getCount() const {
        size_t head = _head.load(std::memory_order_relaxed);
        size_t tail = _tail.load(std::memory_order_relaxed);
        if (head >= tail) return head - tail;
        return MaxSize - (tail - head);
    }
};
```

#### 2. SPI/I2C 하드웨어 예외 가드 및 DRY 인터럽트 디바운싱
* **물리 드라이버 바이트 정합성:** SPI 버스트 리드 직후, MSB/LSB 바이트 역전 오염을 막기 위해 가속도 센서 원시 출력이 비정상적인 거대 진폭(G-Range 임계치의 1.5배 이상)을 가질 시 패킷을 즉시 폐기하고 직전 유효 패킷으로 Fallback합니다.
* **DRY 디바운싱:** DRY 인터럽트 핸들러 내에 물리적 채터링 노이즈를 방어하기 위한 최소 인터럽트 억제 마진(예: 최소 0.5ms 이하의 재호출 필터링)을 탑재하여 중첩 ISR 호출로 인한 메모리 오염을 원천 방지합니다.

### 3단계: 다중 주율(Multi-rate) 정적 시간축 동기화 및 텐서 바인딩 설계 (Tier 3: Pipelines)

* **목적:** 소음(24.38ms)과 진동(640ms)의 주기 비대칭 매칭 붕괴 해결, 마스크 가변 시 차원 붕괴 차단, 신호처리 라이브러리 규격 매칭.
* **설계 범위:**
  * 소음과 진동의 주기 불일치를 정밀하게 매핑하기 위해 시계열 선형 보간(Linear Interpolation)을 적용한 `MultiRateTimeAligner`.
  * `nullptr` 형변환 버그를 해결한 `INVALID_OFFSET` 기반 `DynamicTensorBinder`.
  * 단일 포트 스테레오 동기화 수집 구조 명문화 및 온도별 음속 보정 행렬 반영.
  * ESP-DSP(`dsps_fft_f32`, `dsps_bit_rev_f32`) 실수/허수 교대 정렬 가이드 준수.

#### 1. MultiRateTimeAligner (선형 보간 기반 정밀 시계열 동기화 설계)
```cpp
typedef struct {
    float features[T2_Def::Vib::FEAT_MAX];
    uint64_t timestamp_us;
    bool is_valid;
} ST_Vib_Snapshot_t;

class MultiRateTimeAligner {
private:
    ST_Vib_Snapshot_t _prev_vib;
    ST_Vib_Snapshot_t _curr_vib;
    uint64_t _max_allowed_skew_us;

public:
    MultiRateTimeAligner(uint64_t max_skew_us) : _max_allowed_skew_us(max_skew_us) {
        _prev_vib.is_valid = false;
        _curr_vib.is_valid = false;
    }

    void injectNewVibSample(const float* raw_feats, uint64_t ts) {
        _prev_vib = _curr_vib; // 이전 유효 스냅샷 백업

        // 원시 주입 시 세이프티 매크로를 거쳐 NaN이 내부에 누적되는 현상 원천 차단
        for (size_t i = 0; i < T2_Def::Vib::FEAT_MAX; i++) {
            _curr_vib.features[i] = SMEA_SAN_FLOAT(raw_feats[i]);
        }
        _curr_vib.timestamp_us = ts;
        _curr_vib.is_valid = true;

        if (!_prev_vib.is_valid) {
            _prev_vib = _curr_vib; // 최초 기동 시 초기화 가드
        }
    }

    bool getAlignedVibration(uint64_t audio_ts, float* out_feats) {
        if (!_curr_vib.is_valid) return false;

        // 양방향 타임스탬프 스큐 절댓값 검증 가드 (언더런 및 오버런 동시 차단)
        int64_t skew = static_cast<int64_t>(audio_ts) - static_cast<int64_t>(_curr_vib.timestamp_us);
        if (std::abs(skew) > static_cast<int64_t>(_max_allowed_skew_us)) {
            return false; // 정합성 붕괴로 판정하여 안전하게 프레임 드롭
        }

        // 지연 추론(해석 A) 전제: 오디오 프레임이 버퍼링된 상태로 진동 스냅샷 시간축 사이를 순회
        if (audio_ts >= _prev_vib.timestamp_us && audio_ts <= _curr_vib.timestamp_us) {
            uint64_t total_delta = _curr_vib.timestamp_us - _prev_vib.timestamp_us;
            if (total_delta == 0) {
                std::copy(_curr_vib.features, _curr_vib.features + T2_Def::Vib::FEAT_MAX, out_feats);
                return true;
            }
            float alpha = static_cast<float>(audio_ts - _prev_vib.timestamp_us) / static_cast<float>(total_delta);

            for (size_t i = 0; i < T2_Def::Vib::FEAT_MAX; i++) {
                // NaN 오염 방지 가드가 선행 완료된 데이터를 보간
                out_feats[i] = _prev_vib.features[i] + alpha * (_curr_vib.features[i] - _prev_vib.features[i]);
            }
        } else {
            // 경계를 벗어난 과도기/예외 구간은 가장 안전하게 최신 스냅샷 값 유지 (ZOH 폴백)
            std::copy(_curr_vib.features, _curr_vib.features + T2_Def::Vib::FEAT_MAX, out_feats);
        }
        return true;
    }
};
```

#### 2. DynamicTensorBinder (무효화 마커 논리 모순 차단)
```cpp
class DynamicTensorBinder {
private:
    static constexpr size_t INVALID_OFFSET = static_cast<size_t>(-1); // 확실한 무효 오프셋 지정
    size_t _audio_offset;
    size_t _vib_offset;
    size_t _total_active_elements;
    size_t _nn_input_boundary;

public:
    DynamicTensorBinder(size_t nn_input_size)
        : _audio_offset(INVALID_OFFSET), _vib_offset(INVALID_OFFSET),
          _total_active_elements(0), _nn_input_boundary(nn_input_size) {}

    void updateTensorOffsets(uint16_t active_mask_flags, size_t audio_feat_cnt, size_t vib_feat_cnt) {
        size_t current_ptr = 0;

        if (active_mask_flags & EM_StatusBit_t::MASK_AUDIO_ACTIVE) {
            _audio_offset = current_ptr; // 정상적으로 0 오프셋 매핑
            current_ptr += audio_feat_cnt;
        } else {
            _audio_offset = INVALID_OFFSET;
        }

        if (active_mask_flags & EM_StatusBit_t::MASK_VIB_ACTIVE) {
            _vib_offset = current_ptr;
            current_ptr += vib_feat_cnt;
        } else {
            _vib_offset = INVALID_OFFSET;
        }

        _total_active_elements = current_ptr;
    }

    bool buildFlattenTensor(float* p_target_tensor, const float* audio_src, const float* vib_src, uint16_t mask) {
        if (_total_active_elements > _nn_input_boundary) {
            return false;
        }

        // 전체 영역 안전 소거 (Fixed Shape 가정을 위해 0.0f 패딩 강제 적용)
        std::fill_n(p_target_tensor, _nn_input_boundary, 0.0f);

        // 오디오 복사 (INVALID_OFFSET이 0이 아니므로 정상 동작 보장)
        if ((mask & EM_StatusBit_t::MASK_AUDIO_ACTIVE) && _audio_offset != INVALID_OFFSET) {
            std::copy(audio_src, audio_src + T2_Def::Audio::FEAT_MAX, p_target_tensor + _audio_offset);
        }

        // 진동 복사
        if ((mask & EM_StatusBit_t::MASK_VIB_ACTIVE) && _vib_offset != INVALID_OFFSET) {
            std::copy(vib_src, vib_src + T2_Def::Vib::FEAT_MAX, p_target_tensor + _vib_offset);
        }

        return true;
    }
};
```

#### 3. 듀얼 마이크 스테레오 수집 및 환경 온도 음속 매칭
* **하드웨어 위상 동기화:** 단일 I2S 포트의 L/R(Stereo) 채널로 마이크가 연결되어 있으므로 물리적 샘플링 어긋남이 없습니다. 단일 DMA 수집 블록을 순차 파싱하여 동기화를 단순 유지합니다.
* **온도별 음속 보정:** 빔포밍 AoA 지연 상수에 현재 센서 측정 온도($T_{celsius}$)를 연계하여 실시간 음속($v = 331.5 + 0.6 \times T_{celsius}$)을 보정 계산하고 이를 빔포밍 공간 지연 행렬에 실시간 핫스왑 매핑합니다.

#### 4. ESP-DSP FFT 연산 규격 가이드라인
* `dsps_fft_f32` 호출 이전에 40차원 MFCC 배열 등을 2의 거듭제곱(예: 1024) 실수/허수 교대(Real/Imaginary interleaved) 형태로 변환하기 위한 임시 가용 아레나 버퍼를 둡니다.
* 버스트 연산 완료 후 실수부 복원을 보장하기 위해 반드시 `dsps_bit_rev_f32` 연산 쌍을 누락 없이 순차 호출하는 파이프라인 안전 규격을 강제합니다.

### 4단계: 비상 차단 프리엠프티브 인터락 및 FSM 폴백 제어 시퀀스 설계 (Tier 4: State & Interlock)

* **목적:** 교착 상태(데드락)로 인한 비상 차단 지연 해소, 좀비 락 루프 차단, AI 모델 교체 예외 처리 및 JSON 파싱 자원 고갈 방어.
* **설계 범위:**
  * `std::atomic` 기반의 무교착 최상위 비상 차단 하드웨어 액션 설계.

#### 1. 프리엠프티브 인터락 및 라이프사이클 복구
```cpp
class PreemptiveSafetyInterlock {
private:
    std::atomic<bool> _is_emergency_fault;
    std::atomic<uint16_t> _critical_fault_map;
    const uint8_t _relay_pin;

public:
    PreemptiveSafetyInterlock(uint8_t pin)
        : _is_emergency_fault(false), _critical_fault_map(0), _relay_pin(pin) {}

    void triggerEmergencyFault(uint16_t fault_bit) {
        _critical_fault_map.fetch_or(fault_bit);
        _is_emergency_fault.store(true, std::memory_order_release);
        digitalWrite(_relay_pin, LOW); // 즉각적인 물리 릴레이 차단
    }

    inline bool checkEmergencyStatus() const {
        return _is_emergency_fault.load(std::memory_order_acquire);
    }

    void clearEmergencyLatch() {
        _critical_fault_map.store(0);
        _is_emergency_fault.store(false, std::memory_order_release);
    }
};
```

#### 2. TFLM 추론 결과 안전 가중치 해석 및 타이 브레이킹
* **Softmax 가드 및 모델 출력 확인:** AI 추론 엔진 실행 직후 출력 텐서의 정밀 타입(`TfLiteType`)을 먼저 확인하여, Int8/UInt8 모델인 경우 무조건 float 포인터 캐스팅을 차단하고 스케일/제로포인트를 반영한 정형 복원식(`(quant_val - zero_point) * scale`)을 경유하도록 통제합니다.
* **로짓 출력 대응:** 출력 레이어에 Softmax 활성화 함수가 유실된 로짓(Logit) 상태인 경우 FSM 레벨에서 임계치 확률 해석 전에 시그모이드 또는 소프트맥스 보정을 백그라운드에서 강제 경유시켜 룰베이스 판정에 전달합니다.
* **타이 브레이킹 판정:** 복수 클래스 결함 확률이 완전한 동수(예: 0.5 대 0.5)로 충돌 시, 우선순위가 높은 물리적 치명 결함(예: 기계 진동 파손) 인덱스를 우선적으로 안전 클래스로 선정하도록 타이 브레이킹 규칙을 강제 적용합니다.

#### 3. JSON 역직렬화 힙 누수 및 OOM 차단 설계
* **수신 크기 검증 가드:** 런타임에 설정 패킷 인입 시 파일 시스템이나 네트워크 소켓 수준에서 사전 검증 가드(`payload_size <= 2048` 바이트)를 거쳐 기형적인 크기의 JSON 문서가 수집 버퍼를 통과하는 것을 차단합니다.
* **메모리 단편화 방지:** 동적 메모리 할당(`DynamicJsonDocument`) 사용을 지양하고, 시스템이 허용하는 최대 규격에 맞게 컴파일 타임에 할당되는 정적 버퍼(`StaticJsonDocument<2048>`)와 전용 스코프 블록을 선언하여 스코프 이탈 시 임시 힙 단편화 없이 자원을 완벽 회수하도록 설계합니다.
