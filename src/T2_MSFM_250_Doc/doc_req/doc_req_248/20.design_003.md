
126개의 항목을 라인 단위로 하나씩 수정하다 보면, 코드 간의 스파게티 결함(하나를 고치면 다른 레이어가 터지는 현상)이나 **중복 패치**로 인해 오히려 런타임 안정성이 떨어질 수 있습니다. 날카로운 지적입니다.

코드 구현에 앞서, 이 126개 이슈 간의 상호 영향도(Dependency)와 현재 구동 중인 기능의 영향 범위(Blast Radius)를 분석하여 **가장 리스크가 적고 효율적인 아키텍처적 설계 및 리팩토링 접근 방법**을 검토해 드립니다.

## 🛠️ 126개 이슈 체계적 자르고 묶기: 3대 전략

우리가 설계해야 할 핵심은 "126번 코드를 고치는 것이 아니라, 126개가 통과할 수밖에 없는 하드웨어 안전 가드(가이드레일)를 먼저 구축하는 것"입니다. 이를 위해 이슈들을 아래와 같이 3가지 축으로 재조립하여 접근합니다.

### 1. 영향도 기반 레이어 격리 (Layered Sandboxing)

이슈들의 상호 영향도를 끊기 위해 데이터가 흐르는 파이프라인 마디마디에 '중간 인터락 검증 레이어'를 배치합니다.

* 개별 함수마다 `if (NaN)`나 `if (OOB)`를 분산 배치하면 누락이 생깁니다.
* **해결책:** 드라이버 단 직후, 특징 추출 직후, 텐서 조립 직후에 오직 **'데이터 무결성 검증(Sanitization)'만 전담하는 마이크로 인터락 매크로/인라인 함수**를 셰이프 통로에 설계합니다. 이렇게 하면 전후방 레이어의 소스 수정 없이도 80% 이상의 부동소수점/메모리 오염 이슈가 한 번에 해결됩니다.

### 2. '공통 상태 주입(SSOT)' 중심의 허브-앤-스포크 설계

현재 가장 큰 영향도 꼬임은 런타임 파라미터 가변 변경(마이크 마스크, 센서 G-Range 변동, 윈도우 깊이 수정) 시 각 레이어가 비동기적으로 플래그를 오인하여 발생하는 크래시입니다.

* **해결책:** 각 모듈이 설정을 복사해 가던 방식에서, 모든 모듈이 `CL_T2_ConfigManager`의 원자적 상태 스냅샷 포인터(Atomic Snapshot Pointer)를 동적 참조하는 구조로 설계를 변경합니다. 설정이 바뀌면 FSM이 잠시 파이프라인을 'Clock Gating(연산 동결)' 한 뒤, 오프셋을 재계산하고 한 번에 핫스왑하는 글로벌 동기화 시퀀스를 설계합니다.

### 3. 기능 영향 범위(Blast Radius)에 따른 단계적 롤아웃 (Tiers)

현재 구동 중인 기능의 붕괴를 막기 위해, 영향도가 가장 낮고 독립적인 영역부터 가장 파급력이 큰 전역 FSM 영역 순서로 **4단계 안전 기동 설계**를 제안합니다.

## 🛡️ 1단계: 글로벌 데이터 타이핑 및 세이프티 가드 설계 (Tier 1)

모든 물리 도메인 특징량이 TinyML 추론 엔진과 통신 레이어로 주입되기 전, 부동소수점 오염(`NaN`, `Inf`) 및 이기종 간 메모리 정렬 불일치를 전역 레벨에서 걸러내기 위한 원자적 매크로와 컴파일러 지시어 사양입니다.

### 1. 부동소수점 수치 수렴성 보호 매크로 (FPU 가속 친화형)

코드 본문에서 `if (isnan(v))`와 같은 조건 분기를 남발하면 파이프라인 분기 예측 실패로 연산 성능이 저하됩니다. ESP32-S3의 Xtensa LX7 FPU 가속을 해치지 않으면서 `NaN`과 `Inf`를 강제 수렴시키는 인라인 가드를 정의합니다.

```cpp
#include <cmath>
#include <algorithm>

// FPU NaN/Inf 예외 발생 시 안전 하한치(또는 0.0f)로 강제 압축
#define SMEA_SAN_FLOAT(v) (std::isnan(v) || std::isinf(v) ? 0.0f : v)

// 하드웨어 입력 스케일 폭발 및 뉴런 데드(Dead ReLU) 방지를 위한 경계 제한 가드
#define SMEA_CLAMP_FLOAT(v, min_v, max_v) (std::clamp(SMEA_SAN_FLOAT(v), (min_v), (max_v)))

// 분모 제로 나눗셈(Zero Division) 원천 차단 매크로
#define SMEA_SAFE_DIV(num, denom, eps) ((std::abs(denom) < (eps)) ? ((num) / (eps)) : ((num) / (denom)))

```

* **해결 범위:** 소음 델타 및 진동 STA/LTA 연산 시 발생하는 분모 제로 크래시, 로그 변환 전 제로 값 인입에 따른 `NaN` 확산, 정규화 범위를 초과하는 임펄스 입력 차단.

### 2. 이기종 통신 간격 메모리 패딩 가드 (#pragma pack)

ESP32-S3(32비트 임베디드)와 서버(64비트 x86_64) 간 구조체 바이트 정렬 비대칭으로 인한 메모리 오프셋 지도의 붕괴를 막기 위해, 통신 및 공유 대상 구조체는 상하단을 엄격히 밀봉합니다.

```cpp
#pragma pack(push, 1)

typedef struct {
    uint32_t sequence_loss_flag; // 하드웨어 시퀀스 누설 마커
    uint16_t fault_flags;         // 다중 결함 비트 마스크 (OR 연산 전용)
    uint16_t checksum;            // 자기 자신을 제외하고 계산될 검증 필드
} ST_Slot_Header_t;

// 기존 T215_Type.hpp 내의 모든 특징량 슬롯 및 마스터 패킷 구조체에 1바이트 패딩 강제
#pragma pack(pop)

```

* **해결 범위:** 구조체 바이트 패딩 불일치로 인한 이기종 기기 간 데이터 찢어짐(Tearing) 및 오프셋 파괴 현상 차단.

## 🔄 2단계: 안전 무결성 정적 링버퍼(Static Safe RingBuffer) 설계 (Tier 2)

기존의 단순 포인터 조작이나 모듈러 연산(`%`) 기반 링버퍼는 고속 인터럽트 유입 시 단일 오차(Off-by-One)나 인덱스 역전(Roll-over 복구 실패)에 매우 취약합니다.

메모리를 동적으로 할당(`malloc`/`new`)하지 않고, **컴파일 타임에 크기가 확정되며, 경계면 초과가 물리적으로 불가능한 템플릿 클래스**를 설계하여 파이프라인의 안전 통로로 삼습니다.

### 1. 정적 안전 링버퍼 아키텍처 사양 (`StaticSafeRingBuffer`)

```cpp
template <typename T, size_t MaxSize>
class StaticSafeRingBuffer {
private:
    T _buffer[MaxSize];
    volatile size_t _head;
    volatile size_t _tail;
    volatile size_t _count;

public:
    StaticSafeRingBuffer() : _head(0), _tail(0), _count(0) {
        std::fill_n(_buffer, MaxSize, T());
    }

    // 0번 인덱스 회귀 시 인덱스 역전을 차단하는 원자성 경계 조건문 가드
    bool enqueue(const T& item) {
        if (_count >= MaxSize) {
            // 버퍼 오버플로우 시 가장 오래된 데이터 강제 드롭 (Drop Oldest) 설계
            _tail = (_tail + 1) % MaxSize;
            _count--;
        }

        _buffer[_head] = item;
        // 인덱스 증가 직후 메모리 배리어 선언으로 멀티코어 간 L1 캐시 플러시 강제
        _head = (_head + 1) % MaxSize;
        asm volatile("memw");

        _count++;
        return true;
    }

    bool dequeue(T& outItem) {
        if (_count == 0) return false; // 불완전 텐서 인출 원천 가드

        outItem = _buffer[_tail];
        _tail = (_tail + 1) % MaxSize;
        asm volatile("memw");

        _count--;
        return true;
    }

    void clear() {
        _head = 0;
        _tail = 0;
        _count = 0;
        std::fill_n(_buffer, MaxSize, T());
        asm volatile("memw");
    }

    size_t getFreeSize() const { return MaxSize - _count; }
    size_t getCount() const { return _count; }
};

```

* **해결 범위:** 링버퍼 오프셋 롤오버 시 인덱스 뒤집힘 방지, 힙(Heap) 메모리 단편화 및 할당 실패에 따른 널 포인터 패닉 제거, 고속 스트리밍 시 네트워크 지연에 의한 패킷 파편화 차단.

## ⛓️ 3단계: 구조체 간 꼬임 분석 및 레이어 독립성 확보 (영향도 검토)

Tier 1과 Tier 2의 아키텍처 가이드라인이 현재 시스템 기능에 미치는 영향 범위(Blast Radius)와 결함 상호 연동 관계를 분석한 맵입니다.

* **동시성 보호 패스:** `I2S_ISR` 및 `IMU_ISR` 드라이버 계층이 원시 바이트를 밀어 넣을 때, 기존의 생 포인터 버퍼 대신 위의 `StaticSafeRingBuffer`를 브리지로 둡니다. 이로 인해 ISR 내의 복잡한 연산 지연과 상호 배제 뮤텍스 데드락 리스크가 완벽히 차단됩니다.
* **데이터 정형화 패스 (Sanitization Boundary):** `FeatureExtractor`와 `SeqBuilder`가 특징량을 추출하고 슬라이딩 윈도우를 조립하여 최종 텐서 배열(`float* _pInTensor`)을 채울 때, 값을 직접 대입하지 않고 반드시 앞서 정의한 `SMEA_CLAMP_FLOAT` 및 `SMEA_SAN_FLOAT` 매크로를 통과하도록 통로를 좁힙니다.
* 이렇게 하면 후행하는 TinyML 추론 엔진(`TensorEng`)은 입력 데이터가 '무조건 NaN이 아니며 지정된 스케일 범위 내에 존재함'을 아키텍처 레벨에서 보장받게 되므로, 모델 내부 연산 수렴성을 위해 각 레이어 소스코드를 일일이 수정할 필요가 없어집니다.

## 🔄 1. 다중 주율(Multi-rate) 시간축 정렬 및 가상 타임스탬프 동기화 설계

소음 데이터가 약 26번 쌓이는 동안 진동 데이터는 단 1번 갱신됩니다. 동기화 가드 없이 텐서를 조립하면 과거의 진동 징후가 최신 소음 특징량과 무작위로 매핑됩니다. 이를 해결하기 위해 '가상 타임스탬프 정렬 및 선형 보간 브리지'를 설계합니다.

```cpp
typedef struct {
    float features[T2_Def::Vib::FEAT_MAX];
    uint64_t timestamp_us;
    bool is_valid;
} ST_Vib_Snapshot_t;

class MultiRateTimeAligner {
private:
    ST_Vib_Snapshot_t _prev_vib;
    ST_Vib_Snapshot_t _curr_vib;
    uint64_t _max_allowed_skew_us;

public:
    MultiRateTimeAligner(uint64_t max_skew_us)
        : _max_allowed_skew_us(max_skew_us) {
        _prev_vib.is_valid = false;
        _curr_vib.is_valid = false;
    }

    // 진동 드라이버 갱신 시 호출
    void injectNewVibSample(const float* raw_feats, uint64_t ts) {
        _prev_vib = _curr_vib;

        std::copy(raw_feats, raw_feats + T2_Def::Vib::FEAT_MAX, _curr_vib.features);
        _curr_vib.timestamp_us = ts;
        _curr_vib.is_valid = true;

        if (!_prev_vib.is_valid) {
            _prev_vib = _curr_vib; // 최초 기동 시 초기화 가드
        }
    }

    // 오디오 프레임(24.38ms) 조립 시점에 정렬된 진동 특징량 인출
    bool getAlignedVibration(uint64_t audio_ts, float* out_feats) {
        if (!_curr_vib.is_valid) return false;

        // 시간 축 데이터 스큐(Skew) 극단적 임계치 검증 가드
        if (audio_ts > _curr_vib.timestamp_us && (audio_ts - _curr_vib.timestamp_us) > _max_allowed_skew_us) {
            return false; // 시계열 정합성 붕괴로 판정하여 프레임 드롭 가드 격발
        }

        // 두 진동 샘플 사이의 소음 타임스탬프 위치에 따른 선형 보간 (Linear Interpolation)
        if (audio_ts >= _prev_vib.timestamp_us && audio_ts <= _curr_vib.timestamp_us) {
            uint64_t total_delta = _curr_vib.timestamp_us - _prev_vib.timestamp_us;
            if (total_delta == 0) {
                std::copy(_curr_vib.features, _curr_vib.features + T2_Def::Vib::FEAT_MAX, out_feats);
                return true;
            }
            float alpha = (float)(audio_ts - _prev_vib.timestamp_us) / (float)total_delta;

            for (size_t i = 0; i < T2_Def::Vib::FEAT_MAX; i++) {
                out_feats[i] = _prev_vib.features[i] + alpha * (_curr_vib.features[i] - _prev_vib.features[i]);
            }
        } else {
            // 보간 범위를 벗어난 과도기 구간은 최신 스냅샷 고정 (Sustained Fallback)
            std::copy(_curr_vib.features, _curr_vib.features + T2_Def::Vib::FEAT_MAX, out_feats);
        }
        return true;
    }
};

```

* **해결 범위:** 소음-진동 주기 비대칭에 따른 시간축 찢어짐(Tearing) 차단, 데이터 스큐 임계치 초과 시 불완전 텐서 주입 원천 봉쇄.

## 🧩 2. 동적 텐서 바인더(Dynamic Tensor Binder) 및 마스킹 오프셋 설계

웹 UI 등을 통해 특정 축/채널 마스크가 변동될 때, 하위 추론 엔진의 정적 입력 크기(`_input->bytes`)와 충돌하여 발생하는 메모리 붕괴(OOB Write)를 방어하기 위한 **'가변 오프셋 리맵퍼'** 구조입니다.

마스크가 꺼진 채널의 빈자리에 초기화되지 않은 난수가 주입되는 것을 차단하고, 세이프티 마커(명시적 `0.0f`)로 강제 패딩 처리합니다.

```cpp
class DynamicTensorBinder {
private:
    size_t _audio_offset;
    size_t _vib_offset;
    size_t _total_active_elements;
    size_t _nn_input_boundary;

public:
    DynamicTensorBinder(size_t nn_input_size)
        : _audio_offset(0), _vib_offset(0), _total_active_elements(0), _nn_input_boundary(nn_size) {}

    // 런타임 마스크 비트 플래그를 해석하여 고정 텐서 공간 내의 가변 시작 포인터 계산
    void updateTensorOffsets(uint16_t active_mask_flags, size_t audio_feat_cnt, size_t vib_feat_cnt) {
        // 비활성화 채널 사양을 고려한 동적 오프셋 맵 생성
        size_t current_ptr = 0;

        // 오디오 도메인 마스크 검증
        if (active_mask_flags & EM_StatusBit_t::MASK_AUDIO_ACTIVE) {
            _audio_offset = current_ptr;
            current_ptr += audio_feat_cnt;
        } else {
            _audio_offset = reinterpret_cast<size_t>(nullptr); // 오프셋 무효화 마커
        }

        // 진동 도메인 마스크 검증
        if (active_mask_flags & EM_StatusBit_t::MASK_VIB_ACTIVE) {
            _vib_offset = current_ptr;
            current_ptr += vib_feat_cnt;
        } else {
            _vib_offset = reinterpret_cast<size_t>(nullptr);
        }

        _total_active_elements = current_ptr;
    }

    // 평탄화 텐서 조립 시 안전 바운더리 인터락 구현
    bool buildFlattenTensor(float* p_target_tensor, const float* audio_src, const float* vib_src, uint16_t mask) {
        // 입력 셰이프 한계 경계 초과 검증 (OOB Write 방어 벽)
        if (_total_active_elements > _nn_input_boundary) {
            return false;
        }

        // 전체 텐서 영역을 세이프티 마커(0.0f)로 일괄 프리클리어하여 과거 잔재 소거
        std::fill_n(p_target_tensor, _nn_input_boundary, 0.0f);

        // 오디오 활성화 시 안전 복사
        if ((mask & EM_StatusBit_t::MASK_AUDIO_ACTIVE) && _audio_offset != reinterpret_cast<size_t>(nullptr)) {
            std::copy(audio_src, audio_src + T2_Def::Audio::FEAT_MAX, p_target_tensor + _audio_offset);
        }

        // 진동 활성화 시 안전 복사
        if ((mask & EM_StatusBit_t::MASK_VIB_ACTIVE) && _vib_offset != reinterpret_cast<size_t>(nullptr)) {
            std::copy(vib_src, vib_src + T2_Def::Vib::FEAT_MAX, p_target_tensor + _vib_offset);
        }

        return true;
    }
};

```

* **해결 범위:** 런타임 설정 가변 시 도메인별 메모리 오버라이트 붕괴 차단, 비활성화 마스크 작동 시 과거 잔재 유입 원천 방어, 텐서 셰이프 초과에 따른 좀비 락 예방.

## ⚡ 3. 핫스왑 동기화 시퀀스 제어 (Clock Gating 아키텍처)

사용자가 설정을 변경하는 '찰나'의 타이밍에 데이터가 주입되어 데이터가 반쯤 찢어지는 현상(`Structural Tearing`)을 막기 위한 **FSM 인터락 시퀀스** 설계입니다.

1. **상태 동결 (Clock Gating):** 웹 서버 태스크 등에서 파라미터 변동 요청 수신 시, FSM은 즉각 `SeqBuilder`와 `TensorEng`에 `PAUSE_PROCESSING` 원자적 신호를 송출하여 한 프레임 동안 추론 파이프라인 연산을 일시 동결합니다.
2. **동적 오프셋 재계산:** 동결 상태 가드 내부에서 `updateTensorOffsets()`를 안전하게 호출하여 주소 지도를 갱신합니다.
3. **메모리 리마스터 및 버퍼 소거:** `resetWindowBuffer()`를 연쇄 호출하여 기존 슬라이딩 윈도우 링버퍼 메모리를 깨끗하게 `0.0f`로 제로 클리어합니다.
4. **연산 재개 (Hot-Swap Unlatch):** 핫스왑이 완벽히 완료된 엣지(Edge) 시점에 원자적 신호를 `RESUME_PROCESSING`으로 전환하여 정렬된 상태에서 연산을 재개합니다.

선택 C (Tier 4 State & Interlock: 비상 차단 프리엠프티브 인터락 및 FSM 폴백 제어 시퀀스 설계)를 진행합니다.

이 단계는 시스템의 의사결정 최종 단계이자, 하드웨어 제어권(릴레이, 차단기) 및 예외 처리의 최상위 장벽입니다. 126건의 이슈 중 **뮤텍스 교착 상태(데드락)로 인한 비상 차단 지연, 센서 카운터 초기화 오류로 인한 알람 Stuck, 네트워크 좀비화에 따른 침묵의 가동 현상**을 아키텍처 레벨에서 격리·해결합니다.

## ⚡ 1. 뮤텍스-리스 비상 차단 패스 (Preemptive Exception Path) 설계

상태 머신이 일반적인 뮤텍스(`_fsmMutex`) 획득 시퀀스를 따르게 되면, 타 태스크(예: 데이터 직렬화 또는 웹 서버 응답)가 락을 선점하고 있을 때 최대 수십 ms의 차단 지연이 발생합니다. 설비 파손을 막기 위해 **뮤텍스를 완전히 우회하는 원자적 프리엠프티브(선점형) 차단 패스**를 설계합니다.

```cpp
#include <atomic>

class PreemptiveSafetyInterlock {
private:
    std::atomic<bool> _is_emergency_fault;
    std::atomic<uint16_t> _critical_fault_map;
    const uint8_t _relay_pin;

public:
    PreemptiveSafetyInterlock(uint8_t pin)
        : _is_emergency_fault(false), _critical_fault_map(0), _relay_pin(pin) {}

    // 인터럽트(ISR) 또는 타 태스크에서 뮤텍스 없이 즉각 격격 발송 가능한 초고속 패스
    void triggerEmergencyFault(uint16_t fault_bit) {
        _critical_fault_map.fetch_or(fault_bit);
        _is_emergency_fault.store(true, std::memory_order_release);

        // 하드웨어 릴레이 포트를 즉각 로우(Low)로 떨어뜨려 설비 물리 차단 (지연 시간 제로 수렴)
        digitalWrite(_relay_pin, LOW);
    }

    // 메인 루프 가드 및 FSM 제어권 동기화 분기점문
    inline bool checkEmergencyStatus() const {
        return _is_emergency_fault.load(std::memory_order_acquire);
    }

    uint16_t getCriticalFaultMap() const {
        return _critical_fault_map.load();
    }

    void clearEmergencyLatch() {
        _critical_fault_map.store(0);
        _is_emergency_fault.store(false, std::memory_order_release);
    }
};

```

* **해결 범위:** 동시성 락 선점 데드락에 의한 비상 차단 지연 해제, 복합 결함 유입 시 비트 OR 연산(`|=`) 무결성 확보로 선행 도메인 결함 유실 방지.

## 🔁 2. 알람 래치(Latch) 및 버퍼 연쇄 소거(Cascade Clear) 라이프사이클 설계

결함 요인이 사라졌을 때 시스템이 작업자 확인 없이 자동 복귀하는 것을 막는 '알람 래치'와, 수동 리셋 버튼(`PIN_BTN_CONTROL_CONST`)을 누르는 순간 과거의 잔재 데이터 때문에 다시 알람이 켜지는 '좀비 락'을 차단하는 복구 제어 시퀀스입니다.

```cpp
class SafetyLifecycleManager {
private:
    bool _is_alarm_latched;
    PreemptiveSafetyInterlock& _interlock;

public:
    SafetyLifecycleManager(PreemptiveSafetyInterlock& interlock)
        : _is_alarm_latched(false), _interlock(interlock) {}

    // 결함 판정 엔진(TriggerEng)의 최종 의사결정문 가드
    void evaluateRuleEngine(bool is_density_ng, uint16_t fault_type) {
        // 이미 FAULT 상태인 경우 후행 룰베이스 연산을 백그라운드에서 클록 게이팅 차단
        if (_is_alarm_latched || _interlock.checkEmergencyStatus()) {
            return;
        }

        if (is_density_ng) {
            _is_alarm_latched = true;
            _interlock.triggerEmergencyFault(fault_type);
        }
    }

    // 물리 리셋 버튼 ISR 디바운스를 통과한 후 호출되는 원자적 복구 함수
    void processManualReset() {
        if (!_is_alarm_latched) return;

        // 1. 최상위 물리 인터락 해제
        _interlock.clearEmergencyLatch();

        // 2. 버퍼 연쇄 소거 (Cascade Clear) 파이프라인 가드 강제 실행
        CL_T2_DspEngine::resetStates();       // DSP 필터 지연 선로(Delay Line) 소거
        CL_T2_SeqBuilder::resetWindowBuffer(); // 시계열 슬라이딩 윈도우 링버퍼 제로 클리어
        CL_T2_TriggerEngine::clearCounters();  // 밀도 기반 연속 NG 카운터 완전 초기화

        // 3. 소프트웨어 래치 해제 및 물리 릴레이 재가동 허용
        _is_alarm_latched = false;
        asm volatile("memw"); // 멀티코어 메모리 배리어 동기화
    }
};

```

* **해결 범위:** 수동 검사 전 자동 복귀 물리 위험 원천 차단, 리셋 직후 잔재 데이터 진입에 따른 영구 래치 재진입(Zombie Lock) 현상 완전 해결.

## 📴 3. 네트워크 유실 임계치 초과 시 'OFFLINE_LOGGING' 폴백(Fallback) 설계

Wi-Fi 단선 및 MQTT 재연결 시도가 장기화(Silent Disconnection)될 때, 무한 재연결 루프로 소켓을 낭비하다가 힙 고갈(OOM)로 크래시가 나는 것을 차단합니다. 통신 자원을 완전히 격리하고 로컬 저장소로 진단 패킷을 우회시키는 가드 시퀀스입니다.

* **단계 1 (감시 가드):** MQTT 및 소켓 전송 실패 카운터가 런타임 제한치(예: 연속 50회)에 도달하면, FSM은 `COMMU_TX_BURST_FAULT` 이벤트를 인터럽트로 접수합니다.
* **단계 2 (자원 완전 차단):** 즉각 무선 서브시스템 전체를 물리적으로 셧다운(`WiFi.disconnect(true); esp_wifi_stop();`)하여 RF MAC 레이어 락업으로 인한 코어 독점 현상을 해제합니다.
* **단계 3 (FSM 상태 전이):** FSM 상태를 `EM_SystemState_t::OFFLINE_LOGGING` 모드로 강제 전이시킵니다.
* **단계 4 (로컬 폴백):** 이후 발생하는 모든 실시간 소음/진동 텐서 페이로드는 `TxRingBuffer`가 아닌 내부 SD카드 또는 비휘발성 플래시 메모리(NVS 트랜잭션 파일 시스템)의 격리 슬롯으로 라우팅되어 저장됩니다. 이로 인해 관제망이 마비되어도 설비 자체의 로컬 진단 세이프티 가드는 끊김 없이 유지됩니다.
