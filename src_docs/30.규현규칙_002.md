T2_MSFM 시스템 코딩 규칙 및 원칙 (유형별 정리)

1. 기본 철학 및 아키텍처 원칙

1.1 SSOT (Single Source of Truth)

- 모든 설정, 상수, 파라미터는 단 하나의 진실 공급원에서 파생됨
- 하드코딩 금지: 모든 숫자 값은 의미 있는 이름의 상수로 정의
- 매직 넘버 제로: 코드 내에 직접 숫자(예: 1024, 1600)가 나타나지 않도록 함
- 계산식 정의: 종속된 값은 반드시 컴파일 타임 계산식(constexpr)으로 정의

1.2 도메인 완벽 격리 (Domain Isolation)

4개의 독립적인 도메인 유지, 도메인 간 의존성 최소화

- Global: 시스템 인프라, 통신, 저장소, 공통 수학 상수 (T2_Def::Global)
- Accel: 가속도계 전용 파이프라인 (T2_Def::Accel)
- Gyro: 자이로스코프 전용 파이프라인 (T2_Def::Gyro)
- Audio: 소음(마이크) 전용 파이프라인 (T2_Def::Audio)
- AI: 텐서 조합 및 추론 (T2_Def::AI)

규칙:

- 각 도메인은 Sensor, FeatureLimit, Dsp, Trigger, Calib 하위 네임스페이스를 가짐
- 도메인 간 상수 참조 금지 (필요시 Global로 이동)
- 모든 설정 구조체(ST_*_Config)는 자신의 도메인에 속함

1.3 리소스 이중화 (Resource Duality)

정적 메모리 할당 안전성과 런타임 유연성을 동시에 확보

- _MAX: 정적 할당 상한선 (OOM 방지) - 배열 크기, 버퍼 크기
- _DEF: 런타임 기본값 (실제 연산 루프 제어)

```cpp
inline constexpr uint16_t SEQUENCE_FRAMES_MAX   = 32;   // 정적 상한
inline constexpr uint16_t SEQUENCE_FRAMES_DEF   = 16;   // 런타임 기본
```

1.4 컴파일 타임 계산 (Compile-time Derived Values)

종속 파라미터는 하드코딩하지 않고 계산식으로 정의

```cpp
// MFCC 차원 = 계수 * 컴포넌트 * 총 채널 수 (8)
inline constexpr uint32_t MFCC_DIM_MAX = MFCC_COEFFS_MAX * MFCC_COMPONENTS_MAX * CHANNELS_MAX;
```

2. 네이밍 규칙

2.1 파일 및 네임스페이스

- 헤더 파일: T2xx_Name_yyy.hpp (xx=모듈 번호, yyy=버전) 예: T210_Def_245.hpp
- 구현 파일: T2xx_Name_yyy.cpp 예: T230_Sensor_245.cpp
- 네임스페이스: T2_Def::도메인::하위 예: T2_Def::Accel::Sensor

2.2 상수 (Constants)

- inline constexpr 사용
- 접미사: _CONST (고정 하드웨어), _MAX (정적 상한), _DEF (기본값)
- 단위는 이름에 포함 (예: MS_PER_SEC_CONST)

```cpp
inline constexpr uint32_t SPI_FREQ_HZ_CONST  = 10000000;
inline constexpr uint8_t  BAND_MAX           = 16;
inline constexpr float    RMS_THRESH_DEF     = 0.5f;
```

2.3 타입 (Types)

- 구조체: ST_ 접두사, _t 접미사 (예: ST_Global_System_t)
- 열거형 클래스: EM_ 접두사, _t 접미사, enum class 사용 (예: enum class EM_SystemState_t : uint8_t)

2.4 변수 (Variables)

- 지역 변수: v_ (예: v_sum, v_idx)
- 함수 매개변수: p_ (예: p_len, p_outBuf)
- 클래스 멤버 (private): _ (언더스코어) (예: _lock, _isInitialized)
- 전역 변수: g_ (최소화) (예: g_systemState)

2.5 함수 (Functions)

- 카멜케이스 사용
- 동사 + 명사 형태 (예: init(), setState(), readVibFifoBatch())

3. 메모리 관리 규칙

3.1 정적 할당 (Static Allocation)

- 모든 배열과 버퍼는 _MAX 상수로 크기 결정
- VLA(Variable Length Array) 금지

```cpp
float band_energy[AXIS_MAX][BAND_MAX];  // OK
float buffer[size];                     // size가 constexpr이 아니면 금지
```

3.2 동적 할당 (Dynamic Allocation)

- PSRAM 사용 시: heap_caps_aligned_alloc(16, size, MALLOC_CAP_SPIRAM)
- SRAM 필요 시: MALLOC_CAP_INTERNAL | MALLOC_CAP_8BIT
- 반드시 할당 실패 검사 후 처리

```cpp
float* buffer = (float*)heap_caps_aligned_alloc(16, size, MALLOC_CAP_SPIRAM);
if (!buffer) { ESP_LOGE(...); return false; }
```

3.3 정렬 (Alignment)

- 모든 연산 버퍼 및 SIMD 대상 배열: alignas(16)
- 구조체 전체 정렬: struct alignas(16) ST_Slot_Header { ... };

3.4 정적 메모리 우선 원칙 (추가 규칙)

- 가능한 모든 할당은 정적 할당을 우선 사용
- 동적 할당은 PSRAM 대용량 버퍼가 절대적으로 필요한 경우로 제한
- new/delete 사용 금지 → heap_caps_* 함수 사용

4. 동시성 및 태스크 관리

4.1 RTOS 태스크

- 태스크 스택 크기는 _MAX와 _DEF로 정의
- 각 태스크에 고정 CPU 코어 할당 가능 (CORE_PROCESS_DEF)

```cpp
xTaskCreatePinnedToCore(_captureTask, "CapTask", 8192, this, 10, &_hCaptureTask, 0);
```

4.2 동기화 (Synchronization)

- 공유 자원 접근 시 SemaphoreHandle_t 뮤텍스 사용
- 인터럽트 서비스 루틴(ISR)은 최소한의 작업만 수행 (플래그 설정)

4.3 큐 (Queues)

- 태스크 간 데이터 전달은 FreeRTOS 큐 사용
- 큐 크기는 QUEUE_LEN_MAX로 상한 설정
- 큐 송수신 시 시간 초과(timeout) 값을 명시적으로 지정

4.4 태스크 모니터링 (추가 규칙)

- uxTaskGetStackHighWaterMark()로 각 태스크의 스택 잔여량 주기적 확인
- 워치독(Watchdog): 메인 루프에서 esp_task_wdt_reset() 주기적 호출

5. 오류 처리 및 디버깅

5.1 반환 값

- 성공/실패는 bool 반환
- 초기화 함수: true(성공) / false(실패)

5.2 로깅

- ESP-IDF 로깅 매크로 사용: ESP_LOGI, ESP_LOGE, ESP_LOGW
- 각 파일에 static const char* TAG 정의
- 릴리스 빌드에서 디버그 로그는 조건부 컴파일로 제거 고려

5.3 상태 텍스트

- 센서 엔진 등은 _statusText[32] 멤버로 사람이 읽을 수 있는 상태 유지

5.4 오류 복구 (추가 규칙)

- 초기화 실패 시 자동 재시도 로직 구현 (최대 재시도 횟수 상수 정의)
- 치명적 오류 발생 시 시스템 안전 상태(Safe State)로 전환

6. DSP 및 SIMD 규칙

6.1 윈도우 함수

- FFT 윈도우(Hann, Hamming, Blackman)는 dsps_wind_*_f32 사용
- 진폭/에너지 보상 계수는 상수로 정의 (WINDOW_AMPLITUDE_CORR_HANN)

6.2 필터

- FIR 필터 계수는 _MAX 기반 배열
- IIR/Notch 필터는 dsps_biquad_gen_*_f32로 계수 생성
- 각 축/채널별 독립 필터 인스턴스 허용

6.3 수학적 안전

- 0 나눗셈 방지: fmaxf(x, MATH_EPSILON_CONST)
- 로그/제곱근 0 방지: MATH_EPSILON_12_CONST

6.4 SIMD 최적화 (추가 규칙)

- ESP32-S3의 SIMD 명령어 활용 시 데이터 정렬(16바이트) 필수 확인
- DSP 라이브러리 함수 호출 전 입력/출력 버퍼 크기 검증

7. 패킷 및 직렬화

7.1 네트워크 패킷

- 구조체에 #pragma pack(push, 1) 적용
- WsHeader는 8바이트 정렬로 시작
- 이후 float 배열들은 4바이트 정렬이 보장되어 JavaScript Float32Array와 호환

7.2 파일 저장

- 바이너리 파일 헤더(FileHeader)에 설정 JSON(config_dump[8192]) 포함 (MLOps)
- 원자적 쓰기: .tmp 파일에 저장 후 rename

7.3 엔디안 (Endianness)

- 리틀 엔디안 가정 (ESP32)
- 네트워크 전송 시 변환하지 않음 (일관성 유지)

7.4 직렬화 안전성 (추가 규칙)

- 역직렬화 시 버퍼 오버런 검사 필수
- 패킷 길이 필드가 실제 데이터 길이를 초과하지 않는지 검증

8. 설정 관리

8.1 동적 설정 구조체

- 모든 설정은 DynamicConfig 하나로 통합
- 중첩 구조체로 도메인별 설정 포함

8.2 JSON 직렬화

- ArduinoJson 사용
- _applyJson() 함수로 JSON → 구조체 변환
- cfgSet(), cfgStr(), T2_20_Cfg_SetArray() 헬퍼 사용

8.3 지연 쓰기 (Lazy Write)

- 설정 변경 시 _isDirty = true
- checkLazyWrite()에서 3초 후 저장 (플래시 수명 보호)

8.4 프리뷰/튜닝 모드

- updatePreview(): RAM만 변경 (플래시 미기록)
- commitSave(): 현재 RAM 설정을 플래시에 저장
- revertCancel(): 마지막 저장 상태로 복원

8.5 설정 기본값 검증 (추가 규칙)

- 설정 로드 시 값의 유효 범위 검증 (예: 샘플레이트, 임계값 등)
- 범위를 벗어난 값은 기본값(_DEF)으로 대체

9. 특수 장치 규칙

9.1 BMI270 센서

- SPI 모드 0, 10MHz, MSB 우선
- 읽기 명령 시 MSB=1, 더미 바이트 1회 필요
- FIFO 헤더(0x84: Accel, 0x88: Gyro) 기반 프레임 파싱

9.2 I2S 마이크 (ICS43434)

- 32비트 데이터, 오른쪽 정렬
- 스테레오 모드: L/R 인터리브
- PCM_32BIT_SCALE_CONST로 정규화

9.3 장치 초기화 순서 (추가 규칙)

1. 전원 안정화 대기 (지연 상수 정의)
2. SPI/I2C 버스 초기화
3. 장치 소프트 리셋
4. 레지스터 설정
5. FIFO/버퍼 클리어
6. 정상 동작 확인 (체크섬 또는 ID 레지스터 읽기)

11. 보안 및 안전

11.1 워치독 (Watchdog)

- 메인 루프에서 esp_task_wdt_reset() 주기적 호출
- 장시간 블로킹 작업 전 워치독 리셋 또는 일시 비활성화 고려

11.2 스택 오버플로우 방지

- 태스크 스택을 _MAX로 제한
- uxTaskGetStackHighWaterMark()로 주기적 모니터링
- 스택 잔여량이 임계값 이하 시 로그 출력

11.3 민감 정보

- WiFi 비밀번호, MQTT 패스워드는 NVS에 암호화 없이 저장됨 (외부 보안 고려)
- 프로덕션 환경에서는 네트워크 레벨 보안(VLAN, 방화벽)으로 보완

11.4 입력 검증 (추가 규칙)

- 모든 외부 입력(네트워크 패킷, 직렬 명령, 파일 데이터)은 길이 및 형식 검증
- 버퍼 오버플로우 방지를 위한 경계 검사 필수
